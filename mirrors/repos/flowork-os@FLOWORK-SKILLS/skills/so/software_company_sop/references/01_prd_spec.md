# Product Requirement Document (PRD) Specification SOP

## 1. Role Mandate & Core Standard
The Product Lead (Leader) owns the PRD. In accordance with MetaGPT and ChatDev doctrines, requirements must be fully crystallized into structured documentation before engineering commences. Speculative implementation without acceptance criteria is prohibited.

## 2. Core Specification Sections
1. **Target User & Problem Statement:** Clear definition of user persona, pain points, and business context.
2. **User Stories & Priority Matrix:** MoSCoW prioritization (Must-Have, Should-Have, Could-Have, Won't-Have).
3. **Acceptance Criteria (Gherkin):** Given-When-Then behavioral specifications for all happy and boundary paths.
4. **Non-Functional Invariants:** Multi-OS portability, memory limits, and performance budgets.
