# REA Doctrine: Epistemology & Evidence Provenance Discipline

## 1. Trigger Objective & Operational Mandate
Enforce rigorous scientific epistemological standards in reverse engineering: strict provenance tracking and zero-hallucination discipline.

## 2. Parameter & Input Specification
- `claim`: Technical statement or finding to evaluate (required)
- `supporting_evidence`: Array of evidence citations (hashes, offsets, logs) (required)

## 3. Systematic Execution Workflow
1. Classify Statement: Segregate claim into Observation (verbatim output), Derivation (computed result), Inference (hypothesis), or Unknown.
2. Verify Immutable Provenance: Trace claim back to specific binary SHA-256, hex offset, tool log, or pcap packet number.
3. Assess Falsifiability: Define what empirical evidence would disprove the claim; test against opposing hypotheses.
4. Audit Negative Space: Ensure lack of evidence is never reported as evidence of absence.
5. Seal Evidence Record: Store verified finding in immutable vault (.fl_brain) with reproducible verification commands.

## 4. Reverse Engineering Epistemic Discipline
- Never assert what cannot be demonstrated with terminal or disassembler output.
- Confidence levels must accompany every Inference (Low, Medium, High) with explicit justification.
- All findings are provisional upon discovery of counter-evidence.

## 5. Attestation & Verification (Exit Code 0)
- Execution is ONLY valid when verified with tangible evidence (disassembly output, hash, memory dump, test log).
- All scratch artifacts must reside exclusively in `{effective_ws}/.FL_BIN/scratch/` and be purged upon completion.
- Claiming completion without physical proof is strictly prohibited by Sovereign Law.
