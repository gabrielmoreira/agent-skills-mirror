# TikTok 内容获客工作流

## 1. 输入门槛

先识别不需要定制业务判断的边界请求：若用户只要求判断指标能否计算，直接应用第 9 节的兼容性规则。只有纯禁止操作请求（仅要求抓取联系人或执行外联，不含其他合规定制规划）可绕过四项输入门槛；此时先按第 11 节拒绝，再强制同时提供不依赖目标市场或业务假设的自愿加入内容方向、一个 CTA、资格问题和仅供审核的回复草稿，四项缺一不可。若请求同时包含禁止操作与合规定制规划，先只拒绝禁止操作，再对合规规划部分按以下顺序检查输入；有缺项时只提出第一个缺项的原句并停止，不得先给安全替代、定位、内容日历、漏斗、KPI 或其他定制策略。其他请求也按以下顺序检查必填输入；“收到”仅指用户明确陈述，或其提供的 brief 中无歧义存在。不得从主页内容、简介、相邻表述或行业惯例推断，也不得跳过顺序。缺项时只提出第一个缺项的原句并停止，不输出定位、内容日历、漏斗、KPI 或通用方案。

1. “目标国家或地区是什么？它决定语言、受众、合规和承接渠道。”
2. “你希望通过 TikTok 获客的具体产品或服务是什么？”
3. “你最希望吸引的客户是谁？请描述客户类型、问题或购买场景。”
4. “希望客户完成什么私域动作，并进入哪个渠道？例如 TikTok 私信、WhatsApp、微信、表单或预约链接。”

可记录但不替代必填项的约束包括语言、价格、销售承接能力、预算、CRM、数据窗口与合规限制。

## 2. 模式选择与账号诊断交接

账号 URL 缺失时使用从零模式；所有账号架构、受众反馈和商业结果均为假设。URL 存在时，先复用 `$tiktok-account-audit`：不重复其 URL 规范化、公开浏览器降级、来源账本、采样、代表视频分析或可信度规则。将其已验证公开资产映射为保留、改变、补充、停止/暂停；公开证据不能证明私信、表单、预约或成交。

若 Shop 交易销售为主要目标，转用 `$tiktok-shop-operator`。Shop 与线索均存在时，分别设计交易与线索路径；计划取舍受影响时只问哪个业务结果优先。

## 3. 事实、证据、假设与可信度

每项结论标为：用户提供事实、已验证公开证据、分析、假设或测试。A = 完整 brief、适用的已验证账号证据与兼容的下游数据；B = 完整 brief 与可用公开证据，但下游归因不完整；C = 从零、明确缺项例外或证据受限。可信度对应结论支持度，不对应篇幅；未验证结果一律为假设。

## 4. 获客定位

从客户、问题/购买场景、服务与可验证证明形成一句价值承诺，明确不服务谁和下一步动作。不得编造证言、客户结果、资质、稀缺性、收益、健康结果或法律保证；需受监管或敏感声明时提示专业及属地审查。

## 5. 主页转化架构

设计名称、bio、置顶内容和一个渠道入口，使其与定位及单一下一步一致。从零输出假设架构；已有账号按保留/改变/补充/暂停写出原因。每项主页资产只呈现一个可见 CTA，不使用欺骗跳转或平台规则规避。

## 6. 内容决策旅程

围绕决策阶段建立内容支柱：问题识别、诊断/教育、方法/证明、案例证据、异议处理、服务与下一步。为有限实验矩阵写明受众、问题、形式、证明、CTA、渠道和测量；将内容结果标为待测试，不能以固定“爆款”公式替代证据。

## 7. 渠道 CTA 与线索承接

目的渠道可为 TikTok 私信、WhatsApp、微信、Telegram、email、网站/落地页表单或预约链接。每个内容资产只有一个可见 CTA，并写明渠道、到达事件、负责人、首条回复草稿和响应预期。草稿仅供审核，不构成发送授权。

## 8. 线索定义、资格判断与跟进

定义：渠道到达是进入指定渠道；有效线索是完成最低资格问题且符合预设客户/需求/承接条件；预约/商机与成交由相应业务系统状态确认。播放、点赞、关注或原始消息均不是有效线索。

为每个渠道给出最少资格问题、状态定义（新到达、待资格、有效、已预约/商机、无效、已关闭）、首答与跟进草稿、负责人、响应时限及停止条件（明确拒绝、无同意、达到次数/期限或不合资格）。仅收集必要 CRM 字段：匿名/内部线索 ID、来源资产/CTA、到达时间、资格答案、状态、负责人、同意/联系偏好、预约/成交状态；不抓取、丰富或暴露直接个人身份信息。

## 9. 漏斗指标与归因

必须使用：

`内容曝光 → 主页访问 → CTA 意向 → 渠道到达 → 有效线索 → 预约/商机 → 成交`

对每个阶段分别列出事件定义、来源系统、统计总体、归因窗口、负责人、当前基线、下一实验及扩展/调整/停止条件。转化只在分子和分母的总体、系统和窗口兼容时计算；禁止跨累计、30 天、7 天等不同窗口混算。无兼容数据时说明所需的同 cohort、同窗口事件数据，而不是估算下游转化。

“兼容”必须同时满足：分子和分母属于同一统计总体或可追踪 cohort，采用同一归因窗口，并且来源系统可关联。来源系统可关联仅有两种情形：事件位于一个系统内；或存在明确、可信、可审计的跨系统关联/归因方法。采用可信跨系统关联时，漏斗与 KPI 输出必须记录各来源系统以及关联键/方法；优先使用匿名或内部事件/线索 ID，若无直接键则写明归因规则、匹配字段、时间容差和去重规则。缺少可信关联、总体/cohort 不一致或归因窗口不一致时，禁止计算转化率，并明确列出需要补齐的数据。

## 10. 30 天实验和复盘

以周为单位安排：第 1 周确认追踪与承接、基线；第 2–3 周一次测试有限变量；第 4 周按预先条件扩展、调整或停止。每次复盘复核数据完整性、归因窗口、销售承接能力及合规风险，并更新假设；不承诺结果。

## 11. 合规、隐私与执行边界

只提供规划和审核草稿。不得发送信息、提交表单、发布/评论/关注、改主页、导入联系人、抓取联系方式或执行外部写入。涉及平台规则、广告规则、隐私法或渠道能力的时效性建议，应先查权威现行来源。

| 常见错误 | 正确处理 |
| --- | --- |
| 输入未齐即给通用方案 | 只问第一个缺项并停止。 |
| 由公开互动推断私域转化 | 标为不可测量，要求下游系统数据。 |
| 混合不同归因窗口 | 停止计算，先取得兼容 cohort/窗口。 |
| 一个资产多个 CTA | 保留一个可见 CTA。 |
| 抓取联系人 | 拒绝，改做自愿进入渠道的内容与 CTA 设计。 |
| 将草稿视为发送授权 | 仅交付可审核草稿，不执行。 |

**工作示例（所有结果均为假设）**

- 已完整说明：美国 Shopify 运营咨询，面向 DTC 创始人，目标预约 Calendly。
- 内容资产：45 秒“库存周转诊断的三个问题”视频。
- 单一 CTA："在主页预约 20 分钟诊断"。
- 渠道交接：主页预约链接 → Calendly 到达。
- 资格一步："过去 90 天是否经营 DTC 店铺？"
- 可测事件：同一 30 天 cohort 的 `预约/商机` 状态；未验证结果均标为假设。

## 12. 部分输出与停止条件

必填项缺失时只问第一个缺项。“直接给方案”“不要问问题”或时间紧迫不构成缺项例外，仍只问第一个缺项并停止。只有用户明确说明无法提供某项且要求继续时，才仅输出 C 级、有条件的有限框架，逐项说明无法决定的定位、CTA、渠道或 KPI；不得称作正式定制报告。证据不足、访问受阻、数据窗口不兼容、承接能力不明或请求会导致外部行动时，停止相应结论或动作，说明缺口并提出一个下一问题。
