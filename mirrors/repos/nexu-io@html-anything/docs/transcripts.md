# Transcripts, recordings and platform versions

The **Transcript** panel handles speech recognition, subtitle import, reading and correction. Segment and paragraph views link speech to playback; Edit text reveals correction controls. **Captions** is a separate panel for choosing a native caption track, style, position, size and visibility. Both remain available as left-side tabs. The timeline toolbar provides icon-only microphone, Transcript and **CC** controls with hover/focus descriptions and accessible names. Recording and caption visibility remain visible button states. Each timeline row identifies its kind and number: V for video/visuals, A for audio, T for text and C for captions. Human controls and external Agents compose the same `openmotion_assets_use` transcript operations.

## User stories and observable completion

| Story | Product flow | Completion evidence |
| --- | --- | --- |
| Turn an interview into captions | Import video → Add to timeline → Transcript → Transcribe → Edit text → Save transcript → Caption styles → Add captions to video | A persistent transcript retains the source hash and original text. Native text clips appear at the chosen timing and are included in project history and export. |
| Turn a voice memo into subtitles | Timeline Record → Start recording → grant microphone permission → Stop recording → Listen to recording → Add and transcribe → review in Transcript → Caption styles | Microphone tracks stop; a real recording file enters the project. The same transcription pipeline handles it. Download recording preserves a local copy if import fails. |
| Work without an ASR provider | Import media → Import subtitles → Choose subtitle file → review and correct → apply captions | No model request is needed. Supplied cues must have valid times within the source duration. |
| Extract an editable script | Open Transcript → search and correct → Export captions or script → Copy text or download TXT/JSON | Output contains actual recognized or corrected text. This is speech text, not automatic visual scene interpretation. |
| Make several platform/language versions | Translate or create versions popover → choose a goal, platforms and subtitle languages → copy the complete brief to a connected Agent | The brief identifies the workspace, project and selected transcript. The Agent uses existing import/read, transcript, duplicate, native editing, preview and export operations. Each output has its own editable project and checked export. |
| Recover safely | Inspect failed/cancelled job, reload a conflicting transcript, or repair missing credentials | No automatic paid resubmission or provider fallback. The current source/project is preserved; a conflict does not overwrite another edit. |

## Configure transcription

In **Settings → Model providers**, configure an OpenAI-compatible provider with its documented public HTTPS base URL and key. Sync models or add the exact model ID manually. Under **More settings**, choose **Transcription**, then select a response supported by the provider. Set a default in **Default Agent & models**, or open Recognition settings in Transcript.

- **Timed segments and words** uses `verbose_json` and requests both segment and word timestamps. Groq's documented `whisper-large-v3` and `whisper-large-v3-turbo` support this contract.
- **Plain transcript** uses `json`. For example, the currently documented OpenAI `gpt-transcribe` response provides text; OpenMotion does not manufacture subtitle timing from it. Review/copy/TXT remain available, and users can enter timings explicitly.
- **Speakers and timed segments** uses `diarized_json` and automatic provider chunking. Select it only for a model that documents this response. Speaker identity is supplied by the provider; identity across independently processed chunks is not reconciled automatically.
- Advanced JSON defaults accept `response_format`, `timestamp_granularities`, `temperature`, `chunking_strategy`, `keywords` and `languages`. Endpoint support is model-specific. Per-request parameters override saved defaults through MCP. Context/vocabulary `prompt` is a per-request MCP parameter; it cannot be stored in model defaults.

Credentials remain in the existing settings service. Compatibility is a request contract, not proof of account entitlement, accuracy, quota or successful billing. See the maintained [compatible provider reference](../skills/openmotion-media/references/providers/compatible.md).

## Review and caption placement

Transcript and Captions share the current left-column width. Switching tabs, including the first activation, preserves the preview and other column positions. Manual divider resizing is retained; window resizing still fits the columns to the available workspace without hiding the preview. Narrow panels use compact toolbar actions.

Transcript keeps a fixed toolbar for pause markers, segment/paragraph view, text editing, SRT/VTT import and caption styles. A compact source selector and media-actions menu sit below it; recognition model and language choices open in an anchored Recognition settings popover. Empty, loading and recognition-progress states occupy the reading area, and text scrolls independently of the controls. Pause markers show source-time gaps of at least half a second between adjacent timed segments; clicking a marker locates the gap without deleting footage. Transcript opens in reading mode. Use segment view for timestamped lines or paragraph view for continuous speech; clicking text seeks the source and mapped timeline. Edit text enables corrections and timing/speaker details. Save before opening Caption styles. The Captions panel offers six native artwork styles, three positions and size choices. Sentence captions retain one cue per segment; word highlighting is selected when creating a track and requires real ordered word timestamps matching the text. Edited text without word alignment must be transcribed again or use sentence captions. Styles are original authored-video presets, while the editor controls use the shared design system.

The Captions panel keeps its track selector and visibility controls above a separate scrolling appearance area. Selecting a managed native text or caption clip selects its track in the panel. Legacy text tracks retain their T identity and original content. Existing style, position and size changes apply immediately through native transactions; there is no separate Apply step. Changing an existing track's style or CC visibility patches native source in place, preserving manual timing/text edits. Visibility applies to preview and export, and the CC menu can toggle individual tracks, open the selected track’s styles, or open Auto captions and Add captions directly. Locked tracks refuse changes. New captions retain a pinned Add captions to video action. To change sentence/word pacing, choose the new pacing or Create from transcript; Recreate captions explicitly replaces that transcript’s existing cues, including native edits, using the reviewed placement. Imported tracks without their workspace transcript remain styleable without linking to an unrelated document. Removing a managed track removes its marked native block and is reversible through project history. Imported project ZIPs retain these track controls even without workspace transcript history.

The panel retains the initial transcript, corrected revisions, source path/hash, language and chosen model. Searching filters the text and speaker labels. Clicking a timestamp seeks the source audio; the source play/pause controls are separate from the composition transport. Corrections invalidate obsolete word alignment for that segment. Removing a caption segment does not remove source footage. Restore original text stages the original text for review and saving.

A selected matching root media clip automatically supplies caption placement. For other placements, open **Caption timing**, save the transcript and match **Source in/out**, **Timeline start** and **Playback rate** to the media clip. The mapping is `timelineStart + (sourceTime - sourceStart) / playbackRate`; cues are clipped to the source range. **Use selected media clip** reads the matching clip’s source offset, duration, speed and timeline position. Nested or automated clips require explicit mapping. **Use playhead** supplies a placement start, and **Locate in timeline** maps the current source playback time to the composition. This explicit mapping does not guess which of several copies of a media file is intended.

Applying captions creates native timed text elements above existing media tracks and extends the composition when needed. Creating a new overlay shifts existing track indices without changing clip timing; locked tracks must be unlocked first. Text and captions are excluded from magnetic main-video track detection, including older projects with overlays below the video. Reapplying that same transcript replaces its marked caption layer. It uses the existing project version transaction, requires both current project identities plus the transcript revision, and refuses a changed source file. Existing native timing, typography, history, preview and render controls continue to apply. For a montage with several source ranges, the Agent maps each cue to its actual destination clip using native editing; one offset must not be used for disjoint cuts.

TXT contains the corrected speech text, SRT/VTT contain timed cues, optionally mapped to the composition clock with **Use caption placement for SRT/VTT**, and JSON retains the document and original text. Untimed results cannot be exported as subtitles or applied as captions until timing is supplied. Project ZIPs include adopted native captions; workspace transcript/job history is separate. Export the transcript files when handing over that history.

## Complete example: several source videos to multilingual outputs

1. Open a source project. Import local video/audio files in Transcript. Alternatively, open **Create platform & language versions**, choose highlights or full-video adaptation, click the target platforms and subtitle languages, then copy the brief to a connected Agent. The default is highlights, Douyin for the Simplified Chinese UI or YouTube Shorts for other locales, and the source language. Platform choices reuse the shared creative canvas presets. **More options** contains custom platforms/languages, source links (including YouTube links), source searches and editorial requirements. Choices persist while the popover is closed in the current panel; reloading Studio resets them. Translation presets preserve the original voice.
2. The Agent retrieves usable source files through its available host tools, records source provenance and imports them through the public asset/project operations. The product does not implement a YouTube downloader, login bypass or platform publishing client. A page URL is never passed as a local file path. If retrieval is unavailable, the Agent identifies the missing file instead of claiming success.
3. Discover existing transcripts and verify their source hashes. Transcribe only missing sources with the chosen configured model; follow the original job. Inspect actual speech and timestamped video frames together before proposing cuts. Host analysis, not ASR text alone, establishes visual observations.
4. Review the selected ranges and wording. The Agent duplicates the source project for each output, edits native clips, and recomposes the layout for the requested platform. Suggested portrait/landscape canvases are editorial choices, not a claim about current platform upload limits.
5. The Agent translates reviewed cue text for each requested language, preserves source timing and speaker identity, removes obsolete word alignment, and imports each language into its destination project. Original voice remains; translated subtitles do not imply translated dubbing.
6. Apply editable captions, inspect the preview, and read the latest project identity again. Continue through the existing platform-export workflow or public export operations. Follow each original export job to technical verification, play the actual results when the host supports it, and deliver the platform/language → project/video/subtitle mapping. Uploading the resulting files is a separate action.

This is a product-guided Agent workflow built from the existing editor and public operations. Copying its brief does not execute an Agent, download a source, translate content or finish an export. Those steps have separate observable outcomes.

## Public operations and storage

Use `openmotion_assets_use` with `action: "transcript"` and nested `transcript` arguments. The tool inventory remains sixteen registered names.

| Command | Inputs and result |
| --- | --- |
| `models` | Enabled configured transcription models and default ID; no keys |
| `sources`, `list` | Explicit `projectId`; source file hashes or document summaries/jobs |
| `get` | `projectId`, `transcriptId`; document including original segments |
| `submit` | `projectId`, `sourcePath`, stable `requestId`, optional model/language/parameters; original queued job |
| `status`, `cancel` | `projectId`, `jobId`; persistent task state |
| `import` | `projectId`, `sourcePath`, stable `requestId`; either segments or SRT/VTT text; optional language |
| `update` | `projectId`, `transcriptId`, `expectedTranscriptRevision`, stable `requestId`, segments |
| `export` | `projectId`, `transcriptId`, format `txt/srt/vtt/json`; optional complete source/timeline placement for SRT/VTT; file contents, MIME type and extension |
| `captions` | Explicit project/transcript/composition, source and timeline mapping, expected transcript/project/version identities and stable request ID; optional captionSettings; native history result |
| `caption_tracks` | projectId and compositionPath; managed native text/caption identities, kind (text or caption), settings, cue counts and lock states |
| `caption_update` | Track identity in transcriptId, project/composition, expectedRevision, expectedVersionId, requestId; captionSettings (preset, position, scale, visible) or remove=true. Preserves cue edits; changing pacing requires explicit regeneration through captions. |

Workspace-owned `transcripts/` stores private task metadata, source snapshots, chunk results and versioned documents outside the checkout and project ZIP. ASR tasks retain their input fingerprint and bound provider identity. A worker processes one job at a time per workspace; each ten-minute audio chunk is decoded to mono 16 kHz WAV and sent once. The first audio track is used. Provider failures or uncertain timeouts stop the task; completed chunks are not automatically replayed. Cancel aborts local work but cannot promise provider cancellation or a refund. Interrupted workers fail rather than resubmitting paid work. Explicitly starting a new job may incur charges again.

Source imports retain the shared 500 MB file limit; transcription accepts up to six hours and up to 20,000 segments/two million text characters. Each provider upload is bounded to 25 MB. Browser recording stops at ten minutes or approximately 100 MB and is held locally until imported; unimported recordings and unsaved corrections survive project switching within the current browser session; import/save before closing or reloading Studio. Switching projects stops capture and retains the finished recording for the original project. Completed recordings are decoded locally into mono 16 kHz WAV before native import; decoding failures retain the original downloadable recording. ASR is a post-recording operation, not streaming live captions. Local Whisper, automatic filler removal, speaker identity reconciliation, autonomous visual script extraction, translated dubbing and automatic social publishing are not implemented by this feature.

The interface provides English and Simplified Chinese, with English fallback for the other supported locales. Export → Platform export includes subtitle languages and a direct link back to Transcript. Its Agent brief uses these same transcript commands.

## Verification

`tests/transcription.test.ts` covers normalization, real FFmpeg extraction for audio/video, chunk offsets, wire multipart requests, deduplication, privacy-safe errors, cancellation, source/provider changes, transcript conflicts, native caption version transactions and restoration. `studio/src/motion/Transcript.test.tsx` covers correction, stale composition guards, microphone permission cleanup and clipboard recovery. `tests/transcript-browser.mjs` exercises the isolated Studio import/record/review/caption flow and public version/export chain using synthetic ASR responses and real media/runtime operations. Live paid-provider accuracy, real YouTube retrieval, generated translations and human content acceptance require separate evidence.

## Research references

The capability study reviewed [OpenChatCut](https://github.com/0xsline/OpenChatCut/tree/f96502a18e65a09c19324b10feb671bb505056bd) and [OpenReel](https://github.com/Augani/openreel-video/tree/367d7e90b61b5181f9861b852bb8b9d7a7d2954a). This feature is an original implementation using OpenMotion's service, model configuration and native project boundaries; no upstream source was copied. Their licenses remain independent.

The research distinguishes speech text from a visual script/storyboard:

| Project reviewed | Speech and captions | Transcript/script surface |
| --- | --- | --- |
| OpenChatCut at the revision linked above | Local Whisper and cloud ASR paths; microphone capture feeds post-recording transcription | A dedicated transcript panel with word/speaker timing, seek and text-based editing; transcript text is not automatic visual scene interpretation |
| OpenReel at the revision linked above | Browser Whisper worker and automatic caption creation | Searchable subtitle/transcription editing; useful interaction references for correction and caption adoption |
| [OpenCut](https://github.com/opencut-app/opencut) / [OpenCut Classic](https://github.com/opencut-app/opencut-classic) | The current main repository is a rewrite; the maintained README directs users to Classic. These are source-code findings, not live paid-model acceptance tests. OpenMotion implements its own bounded provider pipeline and document model instead of importing another editor's persistence or editing engine.

## Direct captions and basic editing

Captions opens **Auto captions**, **Add captions**, and **Style**. Auto captions selects a project video/audio source and spoken language; Generate captions runs configured ASR and adds its timed result directly to the native timeline. Model settings stay in a disclosure. Audio with vocals can be transcribed through the same provider; instrumental music does not supply speech, and lyric accuracy depends on the model. Transcript remains the reading/correction surface. Failed adoption leaves the transcript available for review and a separate retry, without repeating paid recognition.

Add captions accepts pasted lines with an explicit duration per cue at the playhead, then selects the created track and opens Style. The timeline T icon opens this same manual entry; there is no separate Text tab. Existing managed text tracks remain available in Style and the CC menu. Manual captions produce editable native clips without a model or source media; select them to change text/font/position, drag their edges to trim, or use Split at the playhead. Import SRT/VTT works directly in Captions without a source-media prerequisite, offset at the current playhead. The timeline toolbar has icon-only Manual captions (T), Music, Record, Transcript and CC entries with accessible labels/tooltips. Music imports local audio and adds it at the playhead through the existing native media path.

`openmotion_assets_use` with `action=transcript`, `command=caption_add` exposes the same manual/import operation to Agents. Supply `projectId`, `compositionPath`, `expectedRevision`, `expectedVersionId`, a stable `requestId`, and either timed `segments` or `subtitles` (SRT/VTT). `textKind=text` creates titles; `textKind=caption` (default) creates a managed caption layer; `timelineStart` offsets cue times. The response returns the new `trackId`, which can be passed as `transcriptId` to `caption_update`; `caption_tracks` discovers both kinds without converting their timeline roles. Text is escaped, invalid timing is refused, repeated requests replay, and stale versions do not overwrite edits. Existing public asset import and native edit operations cover music, trimming, splitting and positioning.

Default caption previews reuse the Inter stylesheet and bounded font-file downloads across text edits. Authored text subsets and large custom/CJK font families retain their existing subset behavior; failed downloads are retried on a later preview rather than retained as successful cache entries. This removes repeated default-font downloads without changing authored timing or fonts.

Timeline clip movement uses a 5-pixel snap acquisition radius and releases within 7 pixels; ruler subdivisions no longer capture drags/trims. Main-track magnet defaults off while saved user choices remain respected. Cmd/Ctrl temporarily bypasses edge snapping and magnetic collision placement. Ordinary overlaps retain pointer time and open/use a compatible layer instead of moving the clip back to a distant gap.

## Export the edited timeline

**Export → Captions** downloads SRT or VTT directly. It waits for pending Studio saves and reads visible managed caption cues from the selected composition, including manual captions, corrected text, splits and trims. Multiple visible caption tracks are combined by default; the track selector can isolate a language or a legacy text track. Hidden cues are excluded. Contiguous word-highlight fragments with identical text are coalesced when adjacent. No media, model or transcription request is needed.

The shared public operation is `openmotion_assets_use({action: "transcript", transcript: {command: "caption_export", projectId, compositionPath: "index.html", format: "srt"}})`. Optional `transcriptId` selects a managed track. It returns `content`, `mimeType`, `extension`, `cueCount` and the requested project/composition identity. `caption_tracks` discovers available identities. Missing tracks, empty visible captions and invalid timing report recoverable errors. Independent nested scenes must be exported from their own composition; this operation does not guess placement across scene references. SRT/VTT contain text and timing; authored appearance remains in video output and the editable project.

Transcript **export** still downloads the reviewed source document; **caption_export** is the saved timeline result. The UI and public MCP call the same implementation. Editing remains version guarded; exporting subtitles is read only.
