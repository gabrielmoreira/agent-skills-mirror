# Workspace assets

Assets stores reusable images, video and audio outside film projects. Upload local media or open AI Create for direct model generation. The Agent tab and Agent task-type filter are temporarily hidden; existing Agent conversations remain accessible through Tasks. The library uses horizontal All/Image/Video/Audio categories, source and newest/oldest/name menus, a compact search field and a Trash entry above one flat asset grid. There is no date filter or date grouping. Video cards preview silently in place on hover or keyboard focus, keeping their poster while loading or if playback fails. Only one gallery video previews at a time; leaving the card, scrolling, resizing, backgrounding or leaving Assets releases it. Touch and reduced-motion preferences keep the poster. Source choices distinguish local uploads from AI-generated assets; trash remains reversible. Opening a file switches to an inline workspace: a left asset filmstrip, central preview and right provenance/version inspector. Video and audio detail previews request autoplay with native controls; browser autoplay restrictions leave manual playback available. Switching assets or versions, or leaving the detail surface, pauses the previous player. Select a version to preview or download its exact bytes, make an older version current without deleting later history, or continue editing beside the preview. Editing pins the selected parent and reference version and saves a new version without overwriting the original. The gallery and filmstrip share the loaded collection, including media type, source, search, sort and page, so entering or leaving preview does not refetch the list or flash loading cards. Returning to the same collection restores its gallery scroll position. Both side panes support bounded resizing; CSS keeps the navigation on the left, shrinking it to a 112px minimum without feeding measured widths back into layout. On very narrow screens, the inspector sits below the preview to the right of the navigation. Only explicit resizing changes saved width preferences. Audio detail previews add a monochrome, audio-reactive waveform to the existing native player; pausing freezes the display, and leaving or replacing the preview releases its analysis. Analysis failure leaves native playback available. My assets in the editor can import an exact library version into the current project; adding it to the composition remains a separate step.

The editor’s upload menu offers local upload and library import. A library import waits for pending saves, pins the selected asset/version and verifies the returned project-relative file in the native project listing before closing the picker and showing a floating success notice. My assets clears hiding search/type filters and reveals the imported file first in its media category. A failed list refresh keeps the picker retryable and reuses the completed import; an uncertain transport outcome retains its request ID. Late completions cannot refresh or notify a different project. Opening or dismissing the picker preserves the project sidebar.

## Agent generation route

Discover configured providers with `openmotion_media_use` inspect/reference/models, then use `openmotion_assets_use` to generate with a full model ID, poll the original job, inspect an exact asset/version, and import only the selected version into an explicit project before composing. Standalone assets require no carrier project. When only the compatible `openmotion_assets` name is discovered, use its actions and inspect adopted local files with available media tools; it has no read action. Existing project-direct media_use jobs retain their original Tool/projectId/jobId and must not be re-generated or imported a second time. Follow the single [generation boundary](../skills/openmotion-production/references/materials.md#generation-boundary).

## Storage and jobs

The installation data directory owns `asset-library/records`, immutable media in `files/<assetId>/<versionId>/`, import request receipts, staging and conversations. Files are private user data and never belong in the checkout or package. Uploads accept at most 500 MB of decodable media. Local imports snapshot regular files without following the final symlink, validate the snapshot and hash the saved bytes before committing metadata under the workspace lock. Stable upload request IDs match content and options, rather than temporary browser-upload paths. A reserved asset identity makes an interrupted metadata commit recoverable without duplicating an asset.

Each version records its original name, MIME type, byte count, SHA-256, dimensions/duration when available, origin, prompt, model, request parameters, references, parent version and job/conversation identities. A reference is always `{assetId, versionId}`. Selecting an older current version preserves all versions. Trash hides an asset from normal browsing and new reference/import operations; it does not destroy bytes or alter project copies. An already-submitted generation can finish into a trashed asset without restoring it or discarding the paid result. After trash or restore succeeds, Studio exits that asset’s preview and refreshes the current list and counts without switching the filmstrip to another collection. Late reads or writes cannot replace a later selection. A floating Removed notice provides Undo for the exact asset through the same `update` operation; undo does not change another selected asset, and a failed undo remains retryable. Permanent deletion, shared cloud storage and cross-device sync are not implemented.

Model Gateway keeps the existing credentials, providers, OpenDesign account connector, queues, cancellation and failure handling. A library destination needs no project. New project generation, including openmotion_media_use, also saves every output into this same local workspace library and keeps the original project paths as independent copies. Completed historical jobs are not backfilled. This storage belongs to the local workspace; it is not a signed-in account cloud library. Before invoking a model for any generation job, the worker checks native media readiness and starts both configured FFmpeg and FFprobe binaries. Missing or unusable tools fail the task before model usage; repairing prerequisites does not replay the failed job. Source checkouts can use `HYPERFRAMES_FFMPEG_PATH` and `HYPERFRAMES_FFPROBE_PATH` when the tools are outside PATH. A new multi-output generation creates separate assets; edits append versions to their explicit target. Source files, task IDs and original versions remain available. Compact task rows show queued, creating, saving, completed, cancelled or failed states, with cancellation and exact-result navigation. The unified Tasks popover combines direct model jobs and Agent conversations, with search, type filters and status; pending approvals and active work appear before finished history, then sort by recent activity. A compact Tasks entry remains in both the gallery and asset-preview headers after the creator closes, showing active or awaiting-approval counts. Selecting a task reopens its progress or conversation beside the current preview without changing the selected asset/version. Polling failure preserves known tasks and exposes retry; delayed reads cannot erase a new submission or replace newer progress. Only new saved outputs refresh the library during task polling. Agent-owned generation jobs remain nested under their conversation. History floats over the workspace without moving the gallery. The creator uses one compact toolbar for generation mode, task selection and a new task. Selecting a direct task restores its prompt, model, parameters and pinned references; selecting an Agent task resumes that conversation. Selection and new-task actions never submit generation. A missing model or reference prevents silent substitution. The view uses existing job and conversation records, not a second execution store. Failure details expand in place and never imply a successful output. A cancelled conversation does not automatically cancel submitted media jobs; each job can be cancelled from its task detail. Failed/interrupted generation is never resubmitted automatically. Multi-output completion can leave successfully saved versions if a later output fails. Complete downloaded outputs are retained with content hashes before library/project saving; interrupted saving becomes a recoverable failed task. Use Retry saving in the original task or retry_save through MCP after repairing storage. Stable per-output identities and receipts recover an already-committed version without duplicating it. An existing project file is reused only if its bytes match; changed project files are never overwritten. Missing, malformed or changed retained outputs fail recovery without contacting a model and persist savePending=false with phase=save_unavailable, removing the retry action. Recovery validates files before queueing, outside the metadata lock, and the worker checks them again. Remaining local bytes are preserved; temporary storage/runtime errors remain retryable. Cancellation after staging retains the paid outputs for explicit save recovery; cancellation before complete download cannot promise a recoverable result. A full disk or failure before complete output staging may prevent retaining all bytes.

## APIs

`openmotion_assets_use` is the preferred public protocol-1 tool; `openmotion_assets` retains its original operations, adds save-only recovery and shares the same records, operation implementations and request receipts. The preferred name adds `read`. Both names are shared by stdio MCP, WebMCP and Studio's `/motion-api/phase1/call` authority:

| Action | Boundary |
| --- | --- |
| `list`, `get` | Filter/page metadata; inspect versions and provenance |
| `read` | Read bounded media content for an explicit assetId/versionId; no generation or asset-version mutation |
| `import` | Copy a real local file using a stable requestId; optional assetId/parentVersionId appends a version |
| `update` | Rename, trash/restore, or select an existing currentVersionId |
| `generate` | Explicit model, modality, prompt, stable requestId and optional parameters/references; returns a job |
| `jobs`, `status`, `cancel` | Observe or cancel original library and new project generation jobs; no implicit retries |
| `retry_save` | Original jobId and stable requestId; save retained local outputs only when savePending is true, without invoking a provider |
| `resume` | Original jobId and stable requestId; recheck an eligible failed Cloud task without uploading or submitting generation again |
| `import_to_project` | Explicit projectId, assetId, versionId and requestId; ordinary project import/history protection, no timeline placement |

Discover available providers and models through `openmotion_media_use` before generating. User credentials stay in model settings. Reference capability is model-specific. Image models that report `supportsImageReference` edit with up to `maxInputImages` references (one when unpublished): local Codex image editing and OpenDesign account models take one; OpenDesign Cloud image models whose catalogue publishes `edits` take up to their `max_input_images`. Cloud video models that publish `max_input_images` take one reference as the first frame. Cloud discovery also returns the provider's native options (`nativeOptions`: durations, resolutions, ratios, quality, sizes). The Codex adapter reads bounded completion/error events and imports only one fresh, regular raster file from the isolated job directory. It does not import the reference, stale files, symlinks or arbitrary paths from model replies. CLI login and an enabled image feature do not prove image-service authorization: an authorization error remains a failed job with actionable guidance, rather than a missing-filename error. Missing proxy credentials are distinguished from account authorization errors; the active Codex provider must select the configuration matching its endpoint and authentication. OpenMotion inherits that configuration without rewriting it or copying credentials. No automatic paid retry or provider switch occurs. Other configured media models support standalone generation using their existing provider parameters; reference input is not implied where a model does not report it.

The browser upload endpoint is `POST /motion-api/assets/upload?requestId=...` with binary body and URI-encoded `X-File-Name`. Media `GET`/`HEAD` at `/motion-api/assets/<assetId>/versions/<versionId>/file` supports single byte ranges and attachment downloads. These are local installation routes behind the existing loopback and same-origin boundary, not public remote endpoints. Browser imports use selected Files; external MCP imports require paths readable on the host.

## Reading a fixed version

Call `openmotion_assets_use` with `action: "read"`, `assetId` and `versionId`. `get` stays metadata-only. The shared reader snapshots a regular no-follow file, verifies its saved byte count/SHA-256 and decodes that snapshot; it never follows a changing current-version pointer. Retained trash is readable, consistently with get/download, while new references and project imports still require an active asset.

- Images return a PNG preview with aspect ratio and transparency retained, at most 1024 pixels per side and without upscaling.
- Video returns the first frame by default. Optional `timestamps` selects one to four seek positions in seconds, in request order. Positions must be before the known media duration; codec/frame-rate seeking can quantize the selected frame. These are requested seek positions, not frame-accurate motion measurements.
- Audio returns mono 16 kHz PCM WAV. Optional `start` defaults to zero; `duration` defaults to 10 seconds, accepts 0.1–15 seconds, and clips to the available audio. The result records the measured clip duration. Timestamps are video-only; start/duration are audio-only.
- Each preview is at most 4 MiB, and one read is at most 8 MiB of decoded output files before base64 encoding. A decode or limit failure returns an error, not an empty successful preview. Temporary snapshots/previews are removed on success or failure; no project, generation task or asset version is created.

HTTP returns version metadata, measured preview metadata and typed `content`. Stdio MCP and WebMCP return the same media in native image/audio content blocks and keep base64 out of `structuredContent` and its text summary. The embedded Codex runner forwards image/audio data URLs using its app-server content types and persists only metadata, never media base64, in tool messages. Host support determines whether media can actually be interpreted or played; a successful read is not evidence of human listening or visual acceptance.

Both names are registered, so the public profile has sixteen names for fifteen domain capabilities. The tool-wide annotation remains `readOnlyHint:false` because other actions modify state or generate media. New calls do not silently fall back to an older authority that advertises only the old contract; refresh/upgrade discovery and the owning backend together when needed, preserving workspace data and active jobs.

## Conversations

Studio's Agent conversation runs the installed Codex CLI's [app-server protocol](https://learn.chatgpt.com/docs/app-server). It initializes the experimental dynamic-tool interface, starts/resumes a persistent thread, streams assistant messages and calls the same asset service through dynamic tools. A private workspace directory scopes the session. The adapter requests read-only sandboxing with on-request approvals; command/file approvals are surfaced to the user, unsupported protocol requests fail explicitly, and generation proposals show their concrete model/prompt/options before submission. No CLI login secrets are copied into OpenMotion conversations.

Messages, tool results and thread identity are persisted. Stop terminates the local app-server session; a new user message can resume the thread. Repeated turn request IDs do not start a second paid turn, and stale running state after a service restart is reported as interrupted. Four conversations may run concurrently, with a 30-minute turn timeout. The currently selected Codex model or its configured default drives the conversation. Other local Agents consume the public MCP tool externally; merely detecting a CLI does not establish an in-app execution adapter.

The Assets interface maintains English and Chinese copy; new asset-specific labels in other configured locales currently use English fallback. Provider model names, authored prompts and Agent replies retain their original language.

## Verification boundary

Deterministic tests cover storage, receipts, version references, generation job ownership, byte-range reads, project imports, protocol streaming, approvals, cancellation and thread resume using a fixture Agent. They do not prove a real paid model request, account quota, every installed CLI version or human visual acceptance. Browser checks cover the opened asset workspace, filters, inline version previews, reference dialogs, uploads, narrow layouts and both themes. Runtime packaging includes these modules and guidance through the maintained distribution list.

## Original Cloud task recovery

Use resume with the original jobId and a stable requestId to check a failed/interrupted Cloud task with a known remoteId, without uploading inputs or submitting another paid generation. Cancelled jobs and confirmed remote failures cannot resume. Use retry_save only for retained local outputs (savePending); regeneration is a separate paid request requiring authorization. Studio offers Check original task on eligible failed jobs. Reference counts follow the selected model before any reference file is read; there is no fixed library count ceiling. Local Codex/account editing remains one image, video remains one first frame, and project referenceAsset remains image-only.

Cloud tasks keep bounded read retries (five attempts) and local timeouts (30 minutes for video, 15 for other media). Interrupted tasks remain failed until explicitly resumed; reconnection never retries upload or generation POSTs. Status and generated asset versions preserve bounded, redacted structured result metadata. Confirmed remote failures retain short error codes and retryable flags and cannot resume, even if the provider labels them retryable. Every returned output is saved with existing media validation. Non-empty parameters.images selects image edits; combining it with pinned local references is rejected before submission.
