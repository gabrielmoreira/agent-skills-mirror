# Native template catalog capabilities

Shared catalog capability reference; read when the selected route needs templates. This page does not restart intake or require original productions to choose a template. Reuse an already selected ID and scope. Editable builtin/registry sources belong to openmotion-template-to-video; video-only references belong to openmotion-recreate. Both routes are implemented. Creating a reusable template from a video is a separate openmotion-video-to-template task, chosen only for that requested deliverable.

## Browsing and recommendations

A request to browse, compare or recommend OpenMotion catalog templates is a discovery task, not permission to create. Use existing preferences without a new creative questionnaire.

1. Call `openmotion_open_preview({target: "templates"})` and complete its `previewHandoff` in this turn. Reuse a currently visible matching library tab; do not merely return a text table. Do not pass project/session/version fields or submit project `record_display` for this page. An explicit text-only/no-opening request, including a still-applicable earlier refusal, takes precedence. An exact selected template plus explicit creation intent goes directly to the existing creation flow instead.
2. Present the exact returned URL in the host browser/panel, preserving parameters and the current chat. Verify native panel visibility and actual library content before saying it opened. Only host-confirmed inactivity permits queued deferral; recheck on return. Retry a failed presentation once, then report the failure. If the host lacks a browser/panel, provide the real library URL and explain the limitation. A service failure without a usable URL is a failure, not a link handoff. Prepared, queued and hidden states are not successful display.
3. Read the current connection's catalog with `openmotion_list_templates`, search its local JSONL index and use `openmotion_get_template` as needed to verify candidates. Catalog lookup and page preparation may run concurrently. Usually suggest two or three relevant choices with accurate names and brief reasons; offer one if only one fits, and never invent or pad candidates. State verified duration/capability only: guidance-only references are not directly editable projects. If the catalog is unavailable, still hand over a working library if possible and explain that reliable recommendations are unavailable.
4. Browsing and playback must preserve project contents, selection and history. Do not create a project, download template project source, acquire production assets or export until the user asks to use a selected template. Catalog/preview loading is allowed. If the user already created a project through Studio, continue it instead of making a duplicate.

The detailed policy lives here. Discovery descriptions carry its short trigger/creation boundary. New Tool descriptions and installed Skills must actually be loaded by the host; a compatible backend connection does not refresh an existing chat's context. Use supported host refresh when needed, preserving projects and running work; report unavailable refresh rather than claiming a stale chat is fixed.

## Selected template creation

Select an exact editable builtin or Prism template through the Studio gallery or a supplied guide, then call `openmotion_create_project` with projectType=template, templateId, requestId, title and requirements. For discovery, call `openmotion_list_templates` with no arguments: it returns a local JSONL index path, total and catalogVersion, not search results. Search the index using local shell/file tools, then call `openmotion_get_template` with the chosen templateId to read the file manifest and TEMPLATE.md. A known ID can skip listing. These paths are accessible only on the machine running OpenMotion. Other sources require host inspection and native authoring; reference footage is not a copyable template.

A copied gallery prompt deliberately contains only a guide link and template ID. Read that URL for the current workspace, connection config and full instructions. Preserve the chosen ID and defaults; no repeated template selection or optional media intake. For external references, inspect the actual video or registry source, import real assets and author native compositions with openmotion_edit_project. Do not substitute an unrelated built-in example or claim that placing the unchanged reference video on a track is a recreation.

Only when a template choice remains unresolved, offer two or three relevant options, preferably with the user's actual material. Do not present all options when only one fits. Show ID/name, the concrete opening, shot sequence, duration, asset needs, visual difference and tradeoff. The recommendation is advisory until the user selects it or explicitly delegates the choice.

## Accepted template selection

All hosts share the same three distinct reference IDs sampled once from the four-entry curated pool in `shared/onboarding-templates.ts`. Use the exact prepared selection and order from the installation result; do not independently draw another set. When the user asks the Agent to choose a first experience, recommend the first prepared card by name before creating. Installation catalog metadata uses that same selection, including hosts without video cards. Its `recommendedTemplateId` is advisory, not user acceptance. If preparation fails, report the unavailable recommendations with the usable library link and preserve any prior selection; do not replace the list with local builtin samples.

A user-sent “yes / 好 / 就这个” after one named recommendation accepts that recommendation's exact ID. Continue with it without repeating template selection. A number, name or submitted card brief selects that exact card; only a generic agreement to several equal choices without a single recommendation needs clarification. Browsing, playing or copying a card does not authorize creation. Export follows the user's requested scope.

Carry the accepted ID, source and requirements until the user explicitly changes the selection. A directly editable source can use `projectType=template`; a reference-only source requires recreation, not a different template. Sample experiences retain the accepted content, motion and native duration; unrelated workspace branding is not a request to adapt them.

A native recommendation card identifies the exact ID in this chat's corresponding result. Its Recreate template button only prepares a composer draft; it does not submit a task or authorize creation/export. Draft preparation is not project creation evidence. Presentation itself remains read-only.

## First-run delivery

Applies to the first successful delivery of an accepted onboarding recommendation, whether it continued as a template or a recreation.

For a successful first-run delivery, keep the editable OpenMotion page open on the right. The final reply contains, in order, one concise completion sentence and the contextual next-step invitation below. Use plain Markdown. Keep screenshots and verification evidence in local records; omit editor screenshots, ZIPs, duplicate project links and checklists unless requested. The selected final-video preview follows [shared delivery](production.md#choose-one-final-video-preview), including host-native embedding; additional downloads still depend on the requested scope. HTML wrappers such as `<details>` and `<summary>` are not part of the reply format.

After the completion sentence, generate one brief, natural sentence in the user's language asking what video they want to make next and introducing three ways to start: choose an existing template, send a video link to recreate, or describe their requirements for an original video. Adapt the wording to the conversation; this is a behavior instruction, not a fixed script. If the user already supplied their next request, acknowledge or continue that request instead of asking again. Otherwise wait for their choice before starting another video. This invitation belongs only to the first successful experience delivery, not follow-up edits or exports.

If a host lacks browser/panel capability, provide the project URL and briefly state that the page could not be opened automatically. Report any material delivery limitation before inviting new work. If the project cannot be created or does not load and play, or a requested export fails, preserve the editable project and report the concrete failure without a success statement or next-step invitation. If tools are unavailable, carry this selected template/defaults/project scope into a continuation without asking the user to choose again.
