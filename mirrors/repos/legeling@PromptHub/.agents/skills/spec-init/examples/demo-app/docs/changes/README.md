# Changes: demo-app

> 更新时间：2026-05-26

这个目录记录单次变更工作区的生命周期，以及“为什么变、影响了什么、同步了哪些文档和测试”。

## 何时新增记录

- 新需求进入当前计划
- bug 修复影响用户行为、接口、数据或回归策略
- 重构改变模块边界、接口约定或实现流程
- 任何需要向后来人解释“为什么这次要改”的工作

## 目录结构

- `active/<change-key>/`: 当前进行中的 change 工作区
- `completed/`: 已完成但仍保留历史价值的变更
- `legacy/`: 旧结构遗留、仅保留参考价值的历史记录

状态和目录必须一致：

- 还在实现、验证、同步或阻塞中的变更，留在 `active/<change-key>/`
- 已完成并通过收敛检查的变更，必须移动到 `completed/`（启用年月归档时为 `completed/YYYY/MM/<change-key>/`）
- 不能把 `active/<change-key>/overview.md` 的状态写成“已完成”却不移动目录

## 与其他文档的关系

- `workflow / knowledge / verification / tasks` 记录当前真相与长期真相
- `changes/` 记录本次变化过程和生命周期位置
- `adr/` 记录关键架构决策
- `releases/` 记录版本对外交付摘要

不要只改当前文档不留痕，也不要只写变更记录却不更新当前状态。
