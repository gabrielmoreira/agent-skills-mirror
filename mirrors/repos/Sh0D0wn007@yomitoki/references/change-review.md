# 変更内容の点検

`review_session.py begin`・`finish` を使うと、以下の退避・Python構造差分・全対象のテキスト差分が保存される。手順は [一括検査と比較](review-session.md) を参照する。保存済みの差分は再生成せず、下の「LLM が差分と契約を照合する」の観点で読む。手動で退避・比較するときは以下を使う。

## 変更前のソースの保存

変更前のソースは、現在の作業ツリーから保存する。複数ファイルは相対パスを保って一意な保存先にコピーし、対応を記録する。保存先は検査対象の外に置き、変更前のスナップショットを上書きしない。対象が既に編集済みなら、Git の HEAD を代用してユーザー変更まで今回の差分に含めない。

単一ファイルの例（同じシェルで実行）：

```bash
review_dir=$(mktemp -d)
cp /path/to/project/module.py "$review_dir/before.py"
# この後に対象を編集する
python3 /path/to/yomitoki/scripts/diff_code.py \
  "$review_dir/before.py" /path/to/project/module.py
```

Windows では Git Bash で実行し、`python3` を `python` に読み替える。

`compare_reports.py` は検査結果の JSON 同士、`diff_code.py` は Python ソース同士を比較する。用途を混同しない。

## 機械的に抽出する内容

`diff_code.py [--json] before.py after.py` は Python 標準ライブラリだけで動く。入力の文字コード宣言を読み、AST を解析・コンパイルして構文を確認する。対象を import・実行・変更しない。

| 分類 | 確認候補 |
| --- | --- |
| definitions | 関数・クラスの定義全体。名前、引数、既定値、注釈、デコレーター、継承、本文を含む |
| imports | import の変更 |
| control | 条件、反復、例外処理、with、match、内包表記の構造 |
| effects | 呼び出し、return、raise、yield、await、break、continue、assert、delete |
| data | 代入、global、nonlocal |

各分類で AST が一致する要素を相殺し、残った要素の種類と変更前・変更後それぞれの位置を示す。変更は削除と追加の組として出るため、改名や関数移動を意味的に対応付けない。親の構文には子の内容も入るため候補は重複する。件数は重大度を表さない。

同じ構文要素の集合で出現順だけが違うときは `orderChanged` を示す。これは AST の巡回順であり、実行順の解析ではない。追加・削除と並べ替えが混在するとき、このフラグだけで順序変更の有無を判断しない。全体の AST も比較するので、分類外の変化も `astChanged` に反映される。

行・列などの位置情報を AST 比較から除く。`type: ignore` の行位置も正規化する。型コメントや docstring は比較に含む。コメント・引用符・空白等は AST に現れない場合があるが、ファイルの SHA-256 の比較で `textChanged` を示す。

出力にはソース本文やリテラル値を載せず、パス・種類・位置とハッシュを載せる。関数・クラスの定義名、呼び出し先の名前（`a.b.c`のような名前と属性の連なりのときだけ）、import のモジュール名は `name` として載せる。添字やリテラルを含む呼び出し先は `null`。列位置は UTF-8 バイト単位の1始まり。位置のない構文は行 `null`・列 `0`。JSON には Python バージョン、双方のパス・ハッシュ、変化、エラー、終了コードを含む。

| 終了コード | 意味 |
| --- | --- |
| 0 | AST に差分なし。テキストやコメントの差分はあり得る |
| 1 | AST に差分あり。意図したリファクタリングでも返る |
| 2 | 読み込み・構文などのエラー。点検未完了 |

## LLM が差分と契約を照合する

1. 全ソース差分を読み、各変更が依頼した読みづらさの解消に必要かを確認する。
2. 追加・削除された条件、値、キー、呼び出し、例外処理を、編集前に控えた契約と照合する。
3. 早期 return が後処理を飛ばさないか、短絡評価や呼び出し回数が変わらないかを確認する。
4. 指摘のない差分も確認する。コメント、`noqa`、`fmt: off`、行番号依存などは AST 一致でも影響し得る。
5. テスト・型チェックなどの実行結果を照合し、必要なら修正して影響する検査と最終差分を確認する。

このスクリプトは意味解析や挙動の同一性の証明を行わない。動的参照、外部設定、複数ファイル間の契約は別途確認する。追加・削除ファイルも一覧で確認し、無関係なファイル同士を機械的に対応付けない。Python 以外、またはスクリプト実行不能の場合は同じ観点で手動確認し、機械検査済みとは報告しない。

解析 API の根拠：[Python ast](https://docs.python.org/3/library/ast.html)。
