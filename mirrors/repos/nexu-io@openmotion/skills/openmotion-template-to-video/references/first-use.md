# First-run template experience

Read for an accepted first-run template recommendation (including a curated reference that continues through recreation) or a submitted recommendation-card brief. Initial installation reply rules and few-shots remain in `docs/install-onboarding.md`, section “Installation-success reply”; this procedure resumes creation after consent.

## First-run experience defaults

Installation opens the library without creating a project. Resolve agreement, source capability and sample scope through [accepted template selection](../../openmotion-production/references/templates.md#accepted-template-selection). Do not restart the template/assets questionnaire or substitute a fixed default. Reuse an existing experience project, including a Studio **Open and edit** project, instead of creating a duplicate.

For a reference-only selection, read its exact ID with `openmotion_get_template`, read its instructions and motionDocument, and continue through `openmotion-recreate` with the accepted sample content or submitted changes. For a directly editable source, call `openmotion_create_project` once with projectType=template, the accepted templateId, stable requestId, title and confirmed requirements. Record the source ID and returned projectId in working notes. Preserve that selection during retries and recovery; if retrieval or production is blocked, explain the blocker without switching samples. Shorter duration, faster export, builtin availability and technical smoke testing never justify switching to decision-tree or another sample. Call `openmotion_open_preview({projectId})` and open its exact previewUrl through the host's supported browser/panel; check the actual selected content and playback. Before delivery, compare the actual project with the accepted source and report any unmet scope. Export only when requested.

For a recommendation card, wait for the user to send the brief, then honor its template title/ID, requirements, attachments and requested HTML/MP4 delivery. Do not substitute legacy frozen sample `createArgs` for a customized submitted brief. A reference card has no `createArgs`: read its exact ID and continue through recreation. Only when the accepted unchanged card is a directly editable sample that actually supplies `createArgs`, pass its complete frozen `createArgs` to `openmotion_create_project` without adding a current `sessionId`, changing its `requestId` or rewriting its title/requirements on retry. User changes form a new intent under the existing workflow; do not reuse an old request ID with altered inputs. Reuse a confirmed project from this experience, including a GUI-created copy, rather than creating again after a card redisplay. Reconcile an unknown write before retrying.

For a directly editable source with requested unchanged HTML/project or MP4 files, continue through [unchanged file export](unchanged-export.md), including its bounded handoff and parallel version-pinned work. Modified content uses [verification](../../openmotion-production/references/verification.md); reuse an applicable existing job or call `openmotion_export_request` once with the current projectId/versionId/revision and stable requestId. Poll `openmotion_get_project` with exportJobId; technical verification is automatic, actual playback is separate.

For a successful first-run delivery, keep the editable OpenMotion page open on the right. The final reply contains, in order, one concise completion sentence and the contextual next-step invitation below. Use plain Markdown. Keep screenshots and verification evidence in local records; omit MP4s, editor screenshots, ZIPs, duplicate project links and checklists from this reply unless the user requested them. HTML wrappers such as `<details>` and `<summary>` are not part of the reply format.

After the completion sentence, generate one brief, natural sentence in the user's language asking what video they want to make next and introducing three ways to start: choose an existing template, send a video link to recreate, or describe their requirements for an original video. Adapt the wording to the conversation; this is a behavior instruction, not a fixed script. If the user already supplied their next request, acknowledge or continue that request instead of asking again. Otherwise wait for their choice before starting another video. This invitation belongs only to the first successful experience delivery, not follow-up edits or exports.

If a host lacks browser/panel capability, provide the project URL and briefly state that the page could not be opened automatically. Report any material delivery limitation before inviting new work. If the project cannot be created or does not load and play, or a requested export fails, preserve the editable project and report the concrete failure without a success statement or next-step invitation. If tools are unavailable, carry this selected template/defaults/project scope into a continuation without asking the user to choose again.
