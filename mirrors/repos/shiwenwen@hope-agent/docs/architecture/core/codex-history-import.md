# Codex 本机会话记录导入

> 范围：本机 Codex CLI / Codex 桌面端写入的会话 JSONL；不读取 ChatGPT 云端历史。

## 用户流程

在会话侧栏顶部提供「导入本机 Codex 记录」。点击后，Hope Agent 扫描当前运行机器的 Codex 会话目录；按钮显示加载状态，完成提示新增、更新及跳过数量。一次操作导入所有可识别记录，不要求用户逐个选择文件；再次点击可重试。后端结果还分别返回未变化、失败及不支持的内容块数量。

导入的会话在侧栏和全局搜索中可见，打开时显示只读提示；保留原时间和正文顺序，不设置 Codex 的原工作目录。它们是**只读记录**：不能在原记录上发送消息、运行工具、压缩上下文或分叉；导入不触发自动记忆提取。用户要继续工作，可新建 Hope Agent 会话并自行引用所需内容。删除导入记录只影响 Hope Agent 的副本，不删除 Codex 原文件。导入无需 Codex 登录。

桌面入口使用本机 Codex 目录；HTTP / Web 入口明确标示读取的是 Hope Agent **服务器机器**的 Codex 目录。两种入口使用同一个后端扫描与写入实现，不接收浏览器提供的任意服务端路径。

## 来源与转换

- 来源根目录按 `CODEX_HOME`（若配置）或用户主目录下的 `.codex` 解析，只扫描 `sessions/**/*.jsonl` 与 `archived_sessions/**/*.jsonl` 的普通文件。拒绝越界的符号链接；不触碰 `auth.json`、配置、日志、缓存或项目文件。
- `session_meta.payload.id` 是稳定来源 ID；缺少或重复 ID 的文件单独跳过并计入结果。保留时间戳；不导入 `cwd`、`base_instructions`、`world_state`、`turn_context`、`compacted`、`token_usage_record`。
- 仅导入 `response_item` 中 `type=message` 且 `role=user|assistant` 的可见 `input_text` / `output_text`。Codex 可能把自身注入的 `AGENTS.md`、环境信息和插件推荐也写成 `role=user`；解析时只剥离这些位于消息开头且完整闭合的运行时信封，保留残缺的相似文本和其后的真实提问。按 JSONL 顺序保存。`developer` / `system`、推理、工具调用与结果、图片原始数据、事件和传输元数据不导入；不支持的内容类型计数并在结果中说明。标题取首条非空用户正文的短摘要，保留用户之后手动改的标题。
- 每条导入消息以外部资料对待；Markdown 渲染遵循现有转义规则。导入不创建可供模型恢复的 `context_json`、工具状态、审批状态或执行队列。用户界面可查看和搜索副本；模型侧 `sessions_list` / `session_status` / `sessions_history` / `sessions_search`、`recall_memory(include_history=true)`、`session_to_note`、行为感知和回顾提取均排除导入记录，避免未经不可信资料封装的正文进入活跃对话。`@` 会话提及与 IM `/sessions` 候选也排除导入记录；IM `/session` 解析和最终绑定入口拒绝导入记录，避免向远端聊天回放只读历史。ACP 会话列表、加载和恢复入口同样排除导入记录。

## 持久化与幂等

导入记录仍使用普通会话的读取与搜索投影，`SessionMeta.origin` 只用于展示。只读状态由独立来源台账判定：Desktop / HTTP 在用户提示 Hook 预检前拒绝导入会话，直接提交保留持久化前的拒绝；所有来源的排队消息入口也在持久化前拒绝，`messages` 插入触发器阻止其他持久化入口追加消息。侧栏打开时隐藏输入框和工作台执行操作；模型侧跨会话发送、Goal / Loop 创建与定时目标校验也拒绝导入会话。团队创建和成员启动前拒绝导入 lead session，子代理台账也阻止从导入会话派生运行；已有团队不能在导入会话上恢复。工作流创建、启动认领、恢复、批准和脚本执行前都复查台账，已有 run 也不能在导入会话上执行；Desktop / HTTP 的手动运行入口直接返回只读错误。智能验证的规划与运行在创建台账前拒绝导入会话，即使它绑定了工作目录。仪表盘的会话、消息活动和代码改进统计排除导入记录，避免把 Codex 历史算作 Hope 使用量。

新增 kernel 所有的 `session_import_sources` 台账：`provider`、`source_id`、`session_id`、`content_hash`、`imported_at` 及非敏感统计。`(provider, source_id)` 唯一；`session_id` 唯一。对每个文件先解析完整且稳定的快照，再在一个 SQLite 事务里写入会话、消息与来源台账，或替换同一来源的旧导入消息。重跑时哈希未变化直接跳过；源文件追加或改动时原 Hope 会话 ID 保持不变，只更新其只读副本。前端导入完成后清除已知导入会话的消息缓存与分页游标，包括已经离开当前会话列表页的记录；当前打开的导入会话从数据库重新加载，侧栏有搜索词时重新查询命中，避免继续使用失效的消息 ID。导入过程不调用会话消息的实时 Hook 镜像、未读提醒或模型用量记账。分叉和手动压缩在内核入口拒绝导入会话，避免生成显示历史与模型上下文不一致的可写副本。

同一 Hope Agent 运行实例内的导入请求串行执行，避免较早扫描晚提交时回退较新的副本。扫描期间若文件变化，只跳过该文件并在结果中提示下次重试；单个坏文件不阻断其余文件。导入前后都不改写 Codex 文件。删除 Hope 副本时一并删除来源台账；下一次点击导入可以重新带回该记录。

代码审查任务在内核创建入口拒绝导入会话，即使它后来绑定了工作目录，避免读取仓库或调用模型。项目分配与工作目录写入入口拒绝导入会话，代码改进报告也拒绝以导入会话为起点，并从项目范围排除历史上已关联项目的导入会话。计划模式的状态转换、文件保存与 Git checkpoint 回滚在共享内核入口拒绝导入会话。托管工作树创建及 Git 控制入口也在执行前核对来源台账；即使旧数据带有工作目录，也不能借导入会话修改仓库。

## 边界与限制

- 后端限制文件数、目录深度、单文件大小、单行大小与整次读取量；文件数超限时优先处理最近修改的文件，其余计入跳过，不整批失败；其它超限显式跳过，不静默截断内容。每次只解析一个有大小上限的文件。错误与日志不打印正文、工具参数、凭据或绝对工作目录。
- HTTP 端点沿现有 owner 鉴权，且只使用服务端固定来源根目录。桌面命令和 HTTP 路由都调用同一 kernel API；导入为显式用户动作，不做启动时后台扫描或定时同步。
- 来源格式是 Codex 的本地实现细节。未知顶层/消息类型跳过；既有可识别记录继续导入。图片和附件在首版不导入，不尝试从原路径复制或网络抓取。
- 导入记录初始不绑定项目，不参与自动记忆、Cron 目标、子代理或 ACP 恢复。

## 验收

1. 含中文、多轮、工具调用、开发者消息和图片标记的合成 JSONL，只导入用户与助手可见文字，顺序和时间正确；工具与开发者内容不出现。
2. 对同一目录连续导入两次不产生重复会话；源文件追加后更新同一 Hope 会话；解析失败或扫描中改动不留下半个会话。
3. 导入记录可在侧栏打开、搜索、导出、删除；向其提交 turn 的桌面、HTTP 和内核入口都被拒绝；Codex 原文件保持逐字节不变。
4. `CODEX_HOME` 缺失、空目录、符号链接、超限文件和部分坏文件不会导致越界读取或整批回滚；结果计数准确，日志没有记录正文或凭据。
