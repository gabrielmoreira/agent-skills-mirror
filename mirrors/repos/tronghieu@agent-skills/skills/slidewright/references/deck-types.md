# Deck types — purpose sets structure and voice

Decide the deck type before writing any slide. Two questions settle it: **what will the
audience do afterwards**, and **who outranks whom**. Getting the second one wrong is the
worst failure: a board report written as a lesson lectures the people the presenter
answers to.

Infer the type from the request ("báo cáo HĐQT" → report upward, "workshop" → training)
and tell the user which type you chose in one line. Ask only when the request fits two
types equally.

| Type | Audience will | Audience stance | Arc | Voice |
| --- | --- | --- | --- | --- |
| **Report upward** — board, executives, quarterly review | Oversee, challenge | Above the presenter, knows the business | Conclusion → actual vs plan → risks → decisions needed | Neutral, numeric, never explanatory |
| **Decision request** — budget, plan, option approval | Approve or reject | Above the presenter | The ask → why → options → cost and risk → next step | Direct, weighs trade-offs, no decoration |
| **Pitch** — customers, investors | Buy, invest | Outsiders, not yet convinced | Problem → solution → proof → the ask | Confident, about their benefit |
| **Training** — class, workshop | Do something new | Learners | Goal → concept → example → practice → recap | Explains, guides, asks questions |
| **Talk** — conference, keynote, sharing session | Remember one idea | Peers who chose to come | One big idea told as a story | Personal, narrative, few words |
| **Internal update** — team meeting, project review | Know the status, coordinate | Colleagues | Done → blocked → next | Short, everyday |

## Rules per type

### Report upward

- State the overall result and what needs a decision on the first content slide.
- Write every slide title as a finding with its number: "Q3 revenue reached 92% of plan",
  not "Revenue".
- Show every number against a baseline: plan, previous period, or target.
- Tables and charts are the content, not illustration.
- State bad news plainly, with its cause and the action taken.
- Close with the decisions or support requested.
- Never define a concept the audience already knows, ask a rhetorical question, give the
  audience advice or "lessons", open with learning objectives, or add a motivational
  quote.

### Decision request

- Put the ask in the first two slides: what, how much, by when.
- Show the options with their trade-offs, including doing nothing. Recommend one and say
  why.
- State the cost, the risk, and what happens if the request is rejected.
- Never hold the ask back until the end, and never present only the favourable side.

### Pitch

- Describe the problem in the audience's own terms before showing the solution.
- Back every claim with proof: a number, a named customer, a demo.
- End with one specific ask.
- Never list features without the benefit, and never claim without evidence.

### Training

- Open with what learners will be able to do afterwards.
- Follow each concept with a worked example, then practice, then a recap.
- Explanations, questions to the room, and exercises belong here and only here.
- Exercises happen off the slide: the deck still has no input fields.

### Talk

- Build the deck around one idea the audience should remember.
- Use stories and large visuals. Keep the words for the presenter's voice.
- Never use dense tables or walls of bullets.

### Internal update

- Say what is done, what is blocked, and what comes next, with owners and dates.
- Never repeat background the team already knows.

## Mixed decks

Pick the type of the deck's main goal. A section may borrow another type's arc (a board
report that ends in a decision request), but the audience stance never changes within
one deck.
