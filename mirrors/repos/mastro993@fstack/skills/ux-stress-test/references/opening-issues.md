# Opening issues

Use the project's tracker: GitHub issues when `gh repo view` works, otherwise ask the user where issues go; with none, write `RUN/issues/UX-NN.md` per issue and say so. File one issue per `UX-NN`, written for a developer who never saw this run:

- **Title**: the issue in plain words ("Signup hides the password rule until it fails").
- **Body**: hit by (count and personas), severity, where, root cause; repro steps and expected behaviour from the clearest finding; one line per persona in their own words; for needs-owner issues, what the owner must supply.
- **Screenshots**: open each before attaching it, and attach only those showing nothing sensitive (secrets, real personal data, internal-only identifiers); name any you held back and why. If the tracker can't take attachments, list the file names.
