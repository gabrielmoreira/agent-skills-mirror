# 核心角色当前快照反推规则（长篇导入）

> 长篇导入时，将核心角色截至最后完整章的状态写入初始化事务 `character_snapshots`，由 `tracking_commit.py init` 生成 `追踪/角色状态/{角色名}.md`。

## 一、输入来源

从已落盘的拆文产物反推，不重读 `原文/`：

| 输入 | 用途 |
|---|---|
| `拆文库/{书名}/角色/{角色名}.md` | 身份、能力、目标、成长弧线、出场记录 |
| `拆文库/{书名}/角色/角色关系.md` | 截至最后完整章的关键关系 |
| `拆文库/{书名}/章节/第N章_摘要.md` | 从 `涉及` 锁定相关章，从 `状态变化`、`信息变化`、`局面结果` 和 `章尾钩子` 提取最后位置、最新状态、已知信息与未结事项；旧摘要缺字段时回退其关键事件与情节点 |
| `拆文库/{书名}/剧情/*.md` | 阵营/身份转折、阶段目标和长期冲突 |
| 初始化事务中的伏笔与时间线候选 | 核对角色未结事项及其可知范围 |

## 二、追踪对象

只为主角、反派、核心配角建立独立快照。临时路人和只承担一次功能的角色不建文件。边界不清时优先不建，后续角色真正进入复用状态时再由逐章事务创建。

## 三、反推方法

对每个核心角色，以最后完整导入章 N 为截面，分别确定：

1. `identity`：截至 N 章实际成立的身份/职业，不写未来晋升计划。
2. `location`：最后落点或下一章开始前可确定的位置。
3. `goal`：角色当前正在追求的具体目标。
4. `state`：身体、情绪、名望、立场中会影响续写的当前状态；只写必要信息。
5. `abilities_resources`：当前确实掌握的能力、物品、权限、作品或人脉。
6. `relationships`：与后续会复用角色的当前关系。
7. `knowledge`：角色本人已经知道、且会影响其行为的信息，不混入作者真相。
8. `open_threads`：有已写正文证据的未结事项；纯未来设计留在大纲。

同一字段多次变化时，只取截至 N 章的当前值。四个列表不设条数上限，容量按文末字节限制；导入旧章不补造逐章记录，续写后的变化由 `逐章记录/第NNN章.md` 承担。

## 四、初始化 JSON 形状

以下示例来自 demo《让你管账号，你高燃混剪炸全网》第 10 章：

```json
{
  "江晨": {
    "identity": "火箭军文工团宣传兵；军宣爆款创作者",
    "location": "火箭军文工团高层看片会",
    "goal": "完成五天百万粉任务，继续做出真正能打的军宣内容",
    "state": "专业团队重拍版反向坐实手机原版的价值，军内认可继续抬升",
    "abilities_resources": [
      "前世 MCN 爆款运营经验",
      "《中国军魂》伴奏",
      "大师级导演能力"
    ],
    "relationships": [
      "钟嘉嘉持续提供军报资源",
      "周薄森和张耀祖已明确认可其创作能力"
    ],
    "knowledge": [
      "《军报》采访稿已经过审",
      "高层决定继续采用《诸君，且听龙吟》手机原版"
    ],
    "open_threads": [
      "五天百万粉任务尚未结算",
      "钟嘉嘉所谓只猜对一半仍未解释"
    ]
  }
}
```

工具据此生成的文件固定包含：截至章节、身份、位置、当前目标、身心状态、能力与资源、关键关系、已知信息、未结事项。模型不得另写一套 Markdown 模板。

## 五、残稿与重复初始化

- 最后一章是残稿：所有快照截至残稿之前的最后完整章；残稿中的动作、获得物、关系变化不得提前生效。
- 已有 `_tracking-state.json` 时不能再次 `init`；快照只在初始化时写一次，不追加历史。

## 六、质量检查

- [ ] 每个文件对应一个核心角色，无功能角色堆积
- [ ] 所有字段都是截至最后完整章的当前值
- [ ] 角色已知信息没有混入作者真相
- [ ] 未结事项都有正文证据，未来设计仍在大纲
- [ ] 单角色快照目标不超过 4096 字节；确有必要可放宽，但不得超过 8192 字节硬上限
- [ ] `tracking_commit.py check` 通过
