# Stage 5：主报告、完整概要与选题回填

Stage 5 时刻读本文件与 [synthesis-inputs.md](synthesis-inputs.md)。`拆文报告.md` 的模板与写法在 [author-facing.md](author-facing.md)「拆文报告.md」。

## 备份与标记

生成新的 `拆文报告.md` 前先执行：

```text
"{PYTHON}" "{story-long-analyze skill 根}/scripts/manage_analysis_run.py" mark-stage --root "{拆文目录}" --stage stage5 --prepare
```

若有旧报告，命令会完整复制到 `_analysis_cache/legacy/拆文报告.md`；已存在的首份备份不覆盖。旧报告与首份备份内容不同时，另存一份带内容 hash 的历史备份。其他旧产物与已有摘要不得覆盖。新报告和完整概要落盘后再用不带 `--prepare` 的 `mark-stage` 标记完成。

## 完整概要

从已落盘的 `剧情/故事线.md`（含故事框架）与各剧情单元写 500–1000 字全书概要，涵盖主要剧情线的发展阶段、核心人物作用、关键转折与因果，写进 `概要.md`：把 Stage 0 的「首版概要」一节换成「全书概要」，基本信息和卷段表保留。

## 报告

按 author-facing「拆文报告.md」写。报告只综合已落盘的底层结果，不为写报告重读全文，也不复制逐章摘要；每条结论写一句人话，再指向对应文件和章节。`source_locator`、证据等级和 `EV/RV/AX/EM` 全量编号留在底层文件里，报告里的编号只在带名称时出现。

文风尚未生成时，「文风一句话」写明待补；报告落盘并标记 `stage5` 后，由 Stage 6 按 [style-profile-generator.md](style-profile-generator.md)「报告回填」补齐，续跑也照此交接。

## 选题回填

长篇扫榜的 `选题决策.md` 会把「能爆的原因」标成 `待拆文验证`，等拆文给出依据。报告落盘后找这份文件：先看 `拆文库/` 所在的工作区根目录，再看工作区里 `扫榜/*/选题决策.md` 中日期最新的一份；都没有就跳过，不影响拆文。

1. 文件里没有「推荐选题」一节（只扫了榜）就跳过，不算无效；有推荐选题但缺「能爆的原因」等当前必需字段时停下，按 author-facing「选题决策缺栏目」告诉作者。
2. 只看「题材组合」与本书题材匹配、且「能爆的原因」仍标 `待拆文验证` 的选题。
3. 拆文支持这个假设时，把标记改成 `已拆文验证`，在同一行补依据，写成「依据：《{书名}》拆文报告·核心发现第 N 条（第 x–y 章）」；拆文结果与假设不符时改成 `拆文未证实`，用同样格式写清哪里不符。只改这一行，其他栏目不动。
4. 向作者汇报时用一句话说明回填了哪个选题、结论是什么。
