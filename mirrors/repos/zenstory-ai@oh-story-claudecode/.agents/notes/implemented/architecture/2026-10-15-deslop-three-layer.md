# Agent Note: 去 AI 味按表达、用笔与故事三层诊断

Status: implemented
Date: 2026-10-15
Related: [旧定档决定](../../implemented/bug-fix/2026-09-27-deslop-one-grading.md)、[Gate 与检测说明](../../implemented/bug-fix/2026-10-14-deslop-doc-contract-gaps.md)

## Problem

独立去味按六项表层密度选 Gate，措辞干净的稿子可能跳过用笔与故事诊断。词表、完整指南、Gate 详规重复规定修法和验收，情绪直写与 Show/Tell 范例还互相冲突。写法抽查已有详略、人物立场和关键过程的判据，却只在爽点及脚本标记处抽查。部分改写范例改变人物策略，整段禁止删除与固定删减比例又限制无功能内容的压缩。

## Decision

独立去味默认分别检查表达、叙事用笔、故事因果与变化，不再按六项词句密度定档。`expression.md`、`narrative-focus.md`、`story-logic.md` 是三层方法的唯一源，位于 story-deslop，按共享 manifest 同步到长短篇、审稿和部署目录。四份旧 `anti-ai-writing.md` 删除，词表收为信号索引；`deslop-gates.md` 只保留活跃定点范围映射与执行接口。写手读取表、派写 prompt、审稿 solo、短篇适配和 OpenCode/Codex 生成产物同步。

作者要求保留长期积累的词汇与句式语料。逐项对照主干旧词表和完整指南发现，压缩后的索引漏掉23个核心词项及部分句式分支、复合原例；现将旧词表64个核心词项全部保留，补回隐性盖章、点破潜台词、论述腔、身体反应、场景／天气／打斗等样本，旧机械替换的材料保留为误改反例。语料统一收在已有 `banned-words.md`，由 story-long-write 的 canonical 同步五份，不另建重复索引。命中后仍回到上下文判断，不恢复出现即删、固定频次或见情绪换动作的旧规则。为保留语料，索引预算由1,800明确调至4,600去空白字符，相关三条加载路径同步计入完整文件，35K硬上限和豁免不变。

作者后续明确要求电报体、短碎句重点治理，并否定了自动评审给满分的节选。表达方法首节和写手入口将其置于表达层首要位置：围绕行动组织句子，把背景、条件和原因嵌入动作，分出信息主次并删除可推知的重复解释；补齐主体和合句只是必要修补，独立分句逐项播报仍不合格。首节采用货车段落示范，对话也不把每项条件改成一行问答。作者认可其句子主次的处理方式，随后指出单看逻辑仍乱；范例进一步明确两方位置，把电话问答概述为应对，避免“来接她”引出载人的歧义。原冻结评分保留为历史记录，作者拒绝的节选进入后续测评的失败反例，不能再以该满分声称表达自然。删并重复说明腾出篇幅，未调高任何预算。

普通去味直接修有原文或已定设计依据的表达、承接和详略；需要改变动机、事件、决定、结果或揭露时机时给出最小设计方案，作者已授权的部分直接执行。按叙事功能保护正文，允许删整段无功能内容，不设固定删减率。定点任务不执行全文件标点写入，报告明确区分未检查、未发现问题、资料不足与尚需设计。

长篇章末与短篇 Phase 4 继续按本次清单和检测问题定点修复，完整三层诊断由独立去味流程承接，不强制作者新开对话或新增确认点。三份方法在实际完整诊断路径中全额计入预算，保留35K硬上限，没有新增豁免。部署守卫由旧 Gate 具体措辞断言改为三方法的可读取路由、canonical/部署副本一致和旧指南退出检查；写作行为由独立改稿测评验收。

合入主干的作者记忆集中管理后，独立去味只接收调用方已有偏好，不查询或维护记忆，结构化派写 prompt 同步该边界。合并前复核补齐 story-review 的检测器入口与结构审查 prompt：表达 blocking 与 advisory 均先作为语义复核候选，确认具体阅读损失后按实际影响定级；不再把检测器命中一律升级为 S2 并照搬其修法。确定性退化项仍单独处理，full、lean、solo 均保持只报告、不改正文的边界。

0.8.6 发布前的独立复核发现公开去味指南仍介绍六指标定档、固定删减率和已删除的完整指南，现同步为三层诊断与授权范围，英文技能总览同步。表达范例把“有纠错功能可保留”补齐为原句保留须有作者选择及既有白名单；没有豁免时保留其纠错功能自然改写后复扫，不能用说明代替调用方的提交验收，无法兼顾时报告剩余阻塞。运行时门禁及白名单权限均不变，避免写手保留同一命中而父流程反复重派。

测评协议、合成样稿与旧版技能先冻结到 `~/.oh-story-bench/prereg/2026-10-15-deslop-three-layer/`，产物在同名 runs 目录。主场景与只检测用例的设计文件被发现含显式诊断提示，在读取任一臂输出与评分前，去掉提示并由两个新执行者重跑；首轮保留为试跑，主评分使用 `2026-10-15-deslop-three-layer-unprompted` 的两项产物。安静送行与授权重写沿用首轮，两臂同样处理。判据、通过线和硬失败保持原冻结协议。

## Alternatives considered

- 保留 Gate 和轻中重，只补几条深层规则：调用改动小，也沿用已有删除保护；但表层分级仍能跳过后两层，因此改成三层独立诊断。
- 把现有 reference 合成一个文件：减少导航成本；但词表、用笔和故事设计仍会混在同一加载单位，故按检查对象拆分，每条判据只解释一次。
- 全部改成剧情重写：能直接解决缺少阻力或因果的稿子；但普通去味不代表作者授权改变人物决定和揭露顺序，故诊断深度与执行权限分开。

## Consequences

收益是词句干净的稿子也能暴露详略失衡和故事缺口，方法与范例不再互相重复。代价是共享调用、文档预算与写手适配需要一起迁移；语义测评依赖模型判断，小样本只能验证本次场景，不能证明所有题材都提升。
