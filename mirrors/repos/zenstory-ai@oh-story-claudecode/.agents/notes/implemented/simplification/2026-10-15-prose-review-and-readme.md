# Agent Note: 精修合并前复核与 README 同步

Status: implemented

## Problem

13 个 skill 的精修已形成 #472–#484 依赖栈。合并前复核发现，长篇情绪资料仍把短篇固定比例和节距写成通用要求，贯穿道具资料也要求每个单元重复三次；长篇拆文 Stage 5 的文风占位尚未交接给 Stage 6 回填。README 的宿主数量、追踪读取范围、hook 阻断能力和升级步骤与现有实现有出入。

## Decision

中英文 README 按 prose-gap-polish 的语言、精简、消歧、真值回查、逻辑五步顺序整理：合并工作台重复介绍，区分 7 款宿主与通用环境，纠正状态卡读取范围、12 KiB 上限、hook 支持边界和检测与改写分工，统一规划/部署/升级顺序并校正扫描命中数。真实录屏、原文引用、全部非 Mermaid 代码块和去 AI 味反例保持原文。

长篇情绪资料保留机制与案例，移除短篇固定比例和小节间距；道具三次出现保留为可选示例，开场事件链按题材和章节任务选用，不再把固定次数当普遍义务。格式由调用方指定，受控部署副本和写手适配层同步更新。

Stage 6 在完整管道或续跑中、标记完成前，依据 `_progress.md` 现有阶段表和报告待补段回填「文风一句话」；单独补旧项目文风仍保留已有报告。收尾检查显式核对回填，不新增运行字段或产物。

合并前独立核对反例保护、资料消费路径与累计行为变更，逐项修复已确认问题。未找到足以整文件删除的冗余。

补漏时将当前 Issue 表单的人读文案纳入同一五步复核，精简反馈开场和排期旁白；Bug 与输出质量表单补齐已支持的 Google Antigravity 选项，其余宿主的相对顺序、字段 ID、必填状态、链接和质量案例 placeholder 原文保留。

## Alternatives considered

- 删除重叠 reference 能缩短资料目录，但已核实的质量规则、平台 rubric 和部署副本各有独立消费者，不能据此认定整文件冗余，因此保留文件，只修正实际混杂的规则。
- 只在情绪资料开头注明“比例仅供参考”改动最小，但后文检查项仍把固定节拍写成义务，整读消费者仍会收到矛盾要求，因此逐处修正执行语句。

## Consequences

写作方法与实例继续可用，长篇任务不再继承固定短篇节距，跨会话的拆文收尾也有明确交接。README 与实现一致；代价是需要同步部署副本、重新生成适配层，并等待依赖栈逐项满足严格 CI 后合并。
