# Agent Note: 写章代查作者记忆不再只靠部署标记认工作区，认不出时不拿书目录去查

Status: implemented
Date: 2026-10-09
Related: [注入预算改量写手读到的那几行](../architecture/2026-10-09-author-memory-budget-on-writer-text.md)、[作者记忆两级 store](../architecture/2026-09-18-author-memory-two-level-store.md)、[单书布局归位](2026-09-24-author-memory-single-root.md)；下游 zenstory-ai/oh-story-dsh#61 分诊时发现

## Problem

长篇写章的组装脚本代查作者记忆时，工作区取「书目录及其祖先里第一个带 `.story-deployed` 的目录」，找不到就把书目录当工作区。DSH 明确不写这个标记，于是：

- 书放在 `长篇/` 下：脚本拿书目录当工作区去查，作者记忆工具认出这是多书工作区里的一本书，报错不写；代查失败，退回主会话手查手填，全局与题材、流程条目全靠主会话自己补。
- 书直接放在没有任何迹象的工作区下（没有 `.active-book`、`长篇/` 等，工作区根也还没有项目级记忆），只有书级记忆：拿书目录当工作区等于声明「单书布局」，工具把书目录下那份带书名的记忆当成旧版误放的单书记忆，原样挪进 `书级/` 并在原处补一份空的项目级记忆。此后用正确工作区查询全部报「state.book must be a string」。本地复现确认。

## Decision

- 组装脚本按 `author-memory.md`「存放与路由」认工作区，依次：书目录或祖先里的 `.story-deployed`；书目录上一层叫 `长篇`／`短篇` 时取再上一层；书目录自己就有项目级记忆或 `书级/` 子目录（单书布局）时取书目录；最近一个带 `.active-book`、`长篇/`、`短篇/`、`拆文库/` 或项目级记忆的祖先，往上找到用户主目录为止（主目录本身不算）。
- 都认不出、而书目录下又是一份带书名的记忆时不代查，零写入，核对报告写明「认不出创作工作区」，交主会话按「存放与路由」定好 `--workspace` 手查。认不出但书目录下没有记忆、或只有项目级记忆时，照旧把书目录当单书工作区。
- 作者记忆工具本身不改：带 `--book-root {工作区}` 的任一命令（含 `query`）照旧会把单书布局里误放的旧版记忆归位。
- 回归测试覆盖：`长篇/` 下的书、有 `.active-book`、有 `拆文库/` 三种多书布局在工作区根还没有项目级记忆时就能认出、代查到本书条目，之后再记全局条目也都带上；`长篇/` 下的书目录里多出 `书级/` 时仍认上上层；单书布局外层恰好有 `拆文库/` 时仍认书目录（只有书级记忆、两级都有两种情况）；主目录里的 `.active-book` 不会把书认到主目录；无迹象布局不代查、记忆文件不动、正确查询照常可用。每条规则都做过变异验证。拿不到主目录时一路找到文件系统根，不让整个组装脚本崩溃。

## Alternatives considered

- **让只读查询永不归位**：最强理由是 `query` 名义上只读，从根上杜绝「查一次就把记忆挪了」。不采用：单书布局的旧版记忆归位是有意让只读查询也能自愈（[单书布局归位](2026-09-24-author-memory-single-root.md)），改掉要另找时机迁移；这次的错在组装脚本替主会话猜了工作区，修猜的那一步即可。
- **组装脚本直接导入作者记忆工具里的 `enclosing_workspace`**：最强理由是认法与工具的单书误用报错同源。不采用：那个函数回答的是「这个目录是不是某个工作区里的一本书」，会一路查到文件系统根、把主目录也算进去，用来选工作区太宽；组装脚本按文档的定义单独实现，并在主目录处停下。
- **认不出时仍拿书目录去查**：最强理由是单书布局的旧版记忆能在写章时顺手归位。不采用：这一步分不清「单书布局的旧版记忆」和「无迹象多书工作区里的一本书」，猜错就把后者弄坏；不代查只是让主会话手查一次，归位照样会在主会话按「单书布局」手查时发生。

## Consequences

- 收益：DSH 的多书布局写章时能自动带上全局与本书的作者习惯，不再静默退回手查；无迹象布局不会再被代查弄坏。
- 代价：单书布局里还留着旧版误放记忆、又没有任何工作区迹象的书，写章时不再自动归位，要主会话手查一次（手查会顺带归位）。祖先目录里恰好有 `拆文库/`、`长篇/` 等目录、自己还没有任何作者记忆的单书工作区，会被认到外层去：外层没有记忆时没有影响，外层恰好是另一个有记忆的工作区时会带上那边的全局习惯。
