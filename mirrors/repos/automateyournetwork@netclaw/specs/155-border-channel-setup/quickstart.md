# Verification quickstart — Comms installer

This is an installer acceptance workflow. It does not authorize model sessions, network/device operations, external messages/calls or meeting capture.

## Preparation

Use an isolated VS Code profile/workspace and new empty runtime homes. Preserve existing Mac/WSL installations. Select the inspected source and pinned runtime explicitly. Use dedicated test accounts where available; enter credentials only through native private prompts. Do not paste or bulk-export a running claw's `.env`.

Source-only preparation can run without any account credentials. Capture actual provider prerequisites and missing identities in the coverage ledger; do not count fixtures as live evidence.

## Catalog and planning

1. Browse Comms for each runtime. Compare every index/inventory entry and related interface against its recorded disposition.
2. Search Twilio and Zoom. Distinguish native conversation paths, optional runtime interfaces and NetClaw MCP/skill paths, including the actual eligible owner role.
3. Select two compatible channels, configure their independent access fields, remove one, restore it and reload the editor. Retained settings must survive.
4. Build equivalent wizard/CLI/assistant plans. No-channel and legacy single-channel plans must still validate.
5. Add Comms tools to an eligible member explicitly. Confirm full Border component bundles remain rejected and a Zoom meeting-input path explains its local Border attachment.

## Local deterministic checks

Run catalog/schema coverage and setup tests for plan validation, effects, native authority, configuration readback, secret ownership, service binding, cleanup and report projection. Run the extension typecheck/build and relevant tests. Controlled adapters exercise unknown process outcomes, wrong-account credentials, incompatible plugins and stale status without using real provider accounts.

Verify that Zoom MCP discovery is inert, Twilio credentials never enter OS argv, and native setup does not overwrite another selected channel or base provider configuration.

## Isolated actual installer acceptance

1. Create a fresh Focused OpenClaw installation and a fresh Focused Hermes installation with selected Comms choices. Review the complete plan and each bounded native handoff.
2. Verify actual files/dependencies, exact selected-home ownership, access settings and messaging process identity. For Hermes, distinguish the messaging gateway from the HUD companion.
3. Exercise cancel, editor closure and resume. Observe unfinished writes before retry and prove no duplicate service/account consumers are adopted.
4. Exercise an isolated Risk with eligible Comms member capabilities and a reviewed same-host Zoom binding. Do not start meeting capture or network investigation merely to test installation.
5. Inspect the browser/editor Comms view and redacted Claw Report, including per-channel configuration/authentication/transport/direction evidence.

## Optional actual provider checks

Only after an exact native review, authenticate the selected test account or send the approved fixed message to the approved destination. A call, attachment, meeting capture or model turn is a distinct effect and cannot be inferred from permission to test text messaging.

Capture actual evidence separately by channel/runtime/platform. For Twilio, accepted submission is not final delivery. Missing or uncertain receipts remain unverified/unknown without replay. If an inbound method would invoke a model or operational tool, keep it unverified unless a separately scoped test has been authorized.

## Closure

Reconcile every inventory entry and requirement/task. Record source commit, host/runtime versions, exact successful installer paths, unsupported-version/host evidence and open provider/platform qualifications. Publish no blanket 100% claim while required supported setup paths or claimed readiness remain incomplete. WSL qualification uses the same source handoff and preserves the running sandbox.
