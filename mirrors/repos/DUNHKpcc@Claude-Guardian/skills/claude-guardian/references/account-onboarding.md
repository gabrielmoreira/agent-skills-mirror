# A0: 新账号注册与使用节奏

依据项目参考资料（linux.do、V2EX、NodeSeek 等论坛的实践）。注册、登录、付款均由用户本人在官方页面完成，Agent 不代办；不承诺免封、免 KYC。

**第一次订阅、拿不定主意的新手，直接按 [A0a 新手试错推荐组合](#a0a) 来。**

1. **注册方式**：尽量用邮箱注册，少用 Apple、Google 授权登录。
   - **Google 授权登录与 Gmail 邮箱登录是 Claude 这边两个不同的账号**：同一个 Gmail 地址，用“使用 Google 继续”和用邮箱验证码/链接登录，注册出来的不是同一个账号，订阅、历史和额度互不相通。注册时选定一种方式并记下来，之后登录、付款、找回都用同一种；登录后发现是空账号或没有订阅，先核对是不是登录方式选错，不要重新注册，也不要两种方式各开一个。
2. **邮箱选择**：优先 Gmail、Outlook；需要防拦截时用 Proton 邮箱。刚创建的全新邮箱更容易触发额外验证。
   - **不碰成品号、成品邮箱（2026-10-25）**：不买别人注册好的 Claude 成品号，也不买成品邮箱来注册；邮箱用自己注册、自己掌握的 Gmail、Outlook 或 Proton，账号由用户本人用这个邮箱注册。**买来的教育邮箱是例外**，见第 5 条。
3. **升级节奏**：Free 账号至少使用 3 天后再升级 Pro；Pro 至少使用 15 天后再升级 Max。
4. **额度使用**：新号不要把额度用到顶满；刚开始有重置卡先不要使用；赠送的优惠和羊毛不要乱薅、不要集中领取。
5. **教育邮箱**：美国、英国教育邮箱账号权重很高，遇到手机号 KYC 的概率极低。教育邮箱可以免费注册，也可以通过合法渠道购买；买来的教育邮箱不算第 2 条说的成品邮箱，可以用。不伪造教育邮箱，不借他人身份。
6. **新号遇到 KYC**：原因通常是环境太差（出口、设备、网络不稳定）加上邮箱太新。**注册时就提示要 KYC 的号，可以直接放弃，存活率不高**；**注册阶段弹手机号验证（接码）的号同样直接放弃，不要备实体卡去接**；**注册时弹手机号验证、之后 24 小时内又要 KYC 的号，基本宣判死刑**，不要在这个号上继续使用或付费；换干净的环境和邮箱重新来过，重新注册的是新号，按第 8 条严格养号（这不是绕过风控，是按 [环境检查](routes-and-platforms.md) 先把环境修好再注册）。KYC 会检查 IP，做 KYC 时的 IP 和支付、使用环境不一致会增大风险。**Pro 用了一段时间后遇到 KYC，直接弃号。**其他使用中才弹出的 KYC，按 [accounts-and-payments.md 的 A3](accounts-and-payments.md) 在官方页面本人完成，做之前先确认出口和平时一致；不加工材料、不借身份。
7. **手机端**：在手机上注册、登录，或之后要用 Apple、Google Play 内购付款时，先按[手机端防封要点](mobile-guidance.md)检查网络出口、IPv6、DNS、WebRTC、支付与登录习惯；Android 手机要拔掉 SIM 卡。

8. **账号注册时间（2026-10-26）**：**Claude 账号注册得越早，权重越高；新号容易被风控。**已有能正常用的老 Claude 账号，优先继续用它，不要轻易弃号重注册；必须新注册时（第 6 条弃号、或第一次注册），新号严格按第 3、4 条的节奏养，不要一上来就高强度使用或直接升 Max。
   - **老 Gmail 邮箱目前没有定论**：用注册多年的老 Gmail 注册 Claude 是否更稳，目前没有一致结论。S03 原文写的“gmail老号最好”不当作结论；不为了“老号”去买或借别人的老 Gmail，用自己的 Gmail、Outlook 即可（第 2 条）。
9. **接码（2026-10-26，2026-10-31 修订）**：**不要找共享号码、虚拟号码接码。****注册阶段**出现接码或 KYC，这个号就死了，直接弃号，不用备实体卡，修好环境、换邮箱重新注册（第 6、8 条）。**账号已经在使用中**才遇到手机号验证，**有条件就用实体手机卡接码；没有条件就直接弃号**。用实体卡接码后，24 小时内又要 KYC 的号照样按第 6 条放弃。Android 手机平时拔卡，收验证码时插回（境外sim卡，别把自己卡插进去了）、收完再拔（[手机端防封要点](mobile-guidance.md)）。

10. **并发（2026-10-27）**：**新号并发尽量控制在 1 到 3 之间，不多用也不少用。**
    - **并发不是按 session 算的**：一个 session 不代表一个并发。并发是同一时间在跑的请求数：一个 Claude Code 会话里派出的每个**子代理也算一个并发**，同时跑的并行任务各算一个；同时在用的网页、桌面端、手机端和多个终端会话也要加在一起算。
    - **新号不要使用 workflow 模式。**
    - **Agent 要把并发讲清楚**：用户开始用之前，Agent 告诉用户现在开了几个会话、每个会话会不会派子代理、合起来同一时间有几个在跑；新号超过 3 个就让用户减下来。高并发也是 S03 说的疑似反代、分发、共享的操作。
11. **被封过号的设备（2026-10-27）**：**一台设备（手机和电脑都算）被封超过 3 个账号，就不要再用这台设备。超过 3 个，会标记 IP、设备 UUID、指纹等信息。**
    - Agent 遇到用户说这台设备被封过号（访谈 `Q-D01`），先问清楚这台设备上一共被封过几个账号。
    - **超过 3 个**：换一台没出过事的设备注册和使用，出口 IP 也一起换，这台设备不再登录 Claude；不靠清理、改设备标识或伪造硬件信息继续用它。
      - **换设备的同时换出口**：新设备用一个全新的出口 IP，不沿用被封账号用过的出口；来源见[固定出口 IP 的来源](egress-ip-options.md)，新设备装好后照[浏览器环境验收](whole-machine-ipv4.md#browser-acceptance)，除“语言”外全绿再注册；手机换设备时出口也一起换，并和电脑保持一致（[手机端防封要点](mobile-guidance.md)）。
    - **3 个以内**：按清理流程（[macOS](cleanup-cli-usage.md)、[Windows](windows-cleanup.md)、[Linux](linux-cleanup.md)、[环境痕迹](trace-cleanup.md)）清掉本地残留后可以继续用。
    - S03 原文“如果被封过号，不要再用该设备”以本条为准（原文与哈希不变）。
12. **内购用户保持移动端活跃（2026-10-28）**：**用 Apple 或 Google Play 内购订阅的，手机上的 Claude App 至少每周打开使用一次**，保持移动端活跃。手机的出口照[手机端防封要点](mobile-guidance.md)和电脑保持一致。Agent 在用户选定内购时就告诉用户这一条，续费时再提醒一次。

<a id="new-account-stage"></a>
## 新账号注册初期：优先原版 Claude Code CLI

新注册账号不要一上来就使用 CC Switch（ccswitch）、oh-my-pi（ohmypi）等需要 OAuth 授权的第三方插件或工具，尽量使用原版 Claude Code CLI。Agent 在确认用户是新注册账号时，先告知这条使用建议。

与 A1/A2 的关系：本文只给注册和使用节奏的建议，不改变 PC0 的接触前门禁、不触发任何实际账号操作；账号被停用时仍走 [M12](incidents-and-integrations.md) 事故分诊，充值、换号不是解除限制的办法。

<a id="a0b"></a>
## A0b：短期封号时间线（出问题时先对照排查方向）

出自项目参考资料 S03 第 5 页（图片表格，[S03 PDF](../sources/S03-claude-experience.pdf)）。按出问题的时间先定排查方向：

| 出问题的时间 | 常见原因方向 |
| --- | --- |
| 注册后几分钟到 1 小时 | 旧环境关联、账号来源异常、邮箱或 KYC 异常、刚被封后立即开号 |
| 开 Pro/Max 后几分钟到当天 | 支付方式、卡或账单地区、KYC、账号本身风险 |
| 第一次跑 Claude Code 后 0.5 小时到数小时 | CLI 环境、网络出口不一致、旧的 Claude 本地状态、第三方工具 |
| 注册后 1 到 2 天 | 新号突然高强度使用、Max、Code、出口变化等组合 |
| 几周到几个月后 | 更像累计行为：条款违规、账号共享、反代、多账号等长期因素 |

用法：用户说“多久被封的”，Agent 先对照这张表说出该时间段最常见的原因方向，再按 [M12 事故分诊](incidents-and-integrations.md) 查证据定原因。
