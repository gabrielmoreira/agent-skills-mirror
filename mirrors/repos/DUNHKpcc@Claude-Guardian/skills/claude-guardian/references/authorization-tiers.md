# 分级授权：什么时候需要用户在场

2026-10-21。适用于所有"Agent 在用户的电脑、虚拟机或服务器上做改动"的指引：本机、VM、VPS 路线，以及线路优化、防火墙、代理和客户端安装。

**目标：**用户不需要每一步都在现场，只在真正重要的点在场；Agent 在这个 Skill 的加持下按用户的需求和环境灵活处理，而不是执行固定程序。做法是按风险分三档，不是按"每一步"。

## 先做一次范围确认

访谈确定路线和目标机器之后，Agent 给出一张**范围确认单**，用户在对话里明确确认一次：

- **目标：**哪台机器（别名）、哪个用户、哪条路线。
- **允许的动作类别：**A 档和 B 档里的哪些类别。
- **保底条件：**有没有云控制台或虚拟机控制台的独立入口、能不能再开一个会话、有没有快照。
- **保留项：**哪些东西不能动（项目、历史、其他应用、局域网内必须保留的设备）。
- **时效：**只对当前任务和当前目标有效。

范围确认单不会自动通过，沉默、超时、默认选项都不算确认。换目标、换路线、换账号，或者保存的记录被重新载入，都不恢复授权，要重新确认。

## 三档

| 档位 | 用户要做什么 | 判定 | 例子 |
| --- | --- | --- | --- |
| **A 范围内自行做** | 范围确认后不再问 | 只读，或只写 Agent 自己的临时文件；不改用户系统、不联网到用户服务以外 | 只读诊断、读配置（不读密钥）、查资料（论坛等）、出方案和变更卡、`render`、`nft -c`、`-WhatIf` 这类预演、跑本地检测页、访谈 |
| **B 整个计划批准一次** | 看完整计划，批准一次；Agent 连续执行，不必在场 | 会改系统，但**可由 Agent 自己撤销**，且**不会切断自己的访问**，不涉及账号、钱、凭据 | 装 Clash 客户端、加 `guardian-` 开头的允许规则（此时默认出站仍放行）、前台 SSH 转发、临时切 BBR（已记原值）、装 FlClash TUN、开客机 SSH、在自己目录写文件、导出防火墙备份、布置回滚保险丝 |
| **C 必须当场确认** | 到这一步 Agent 暂停叫用户，用户确认后才继续 | 任一条为"是"：可能锁死或切断访问；涉及账号、钱、凭据；删除或不可逆；影响他人或组织管理的设备；需要用户本人完成 | 见下一节 |

**判定方法：**对一项动作问五个问题——Agent 能不能自己撤销？会不会切断自己的访问？涉及账号、钱或凭据吗？删除或不可逆吗？影响他人或组织设备吗？后四个任一为"是"，或第一个为"否"，就是 C 档。拿不准时按更高一档处理。

## C 档清单

1. **可能锁死自己的改动：**把默认出站切成阻止、启用 killswitch 或 `vps-guard`（保险丝需要用户 `confirm`）、改 SSH 端口和授权密钥、关闭唯一访问入口、故障演练会切断唯一入口时（远程机器）、关闭远程机器的网卡 IPv6；Agent 和被改的网络在同一台机器上时，会切断 Agent 自己连接的步骤（[agent-on-target.md](agent-on-target.md)）。
2. **账号和钱：**注册、登录、KYC、OAuth 授权、付款、订阅、续费、买服务器。这些一直由用户本人完成，Agent 不代做。
3. **凭据：**任何密钥、节点链接、订阅链接、密码的输入输出；删除钥匙串条目或 `.credentials.json`（退出登录）。
4. **删除和不可逆：**清理本地数据（C5）、永久删除、重装系统、持久化改内核参数（如写入 BBR 配置文件）、修改系统时区、启用 `CLAUDE_CODE_SIMPLE`（订阅登录在该模式下不可用）。
5. **组织管理的设备**上的策略类改动：停下，不由用户决定。
6. **接触 Claude 或 Anthropic：**接触前门禁 PC1、PC2 各自的授权。

## B 档：计划批准单

Agent 出一张计划，用户批准一次。计划包括：

- **步骤清单：**按顺序列出每一步做什么、属于哪个类别。
- **每一步的原值→新值**和**回滚方法**（Agent 自己能执行的）。
- **失败时怎么办：**任一步失败，自动撤销本计划已做的变更，回到原值，然后汇报；不继续往下做。
- **验证：**每步做完怎么确认。
- **不包含的：**明确写出这张计划不涉及任何 C 档动作。

批准之后，Agent 可以在计划范围内**按环境调整具体命令和参数**（不同的网卡名、包管理器、路径、版本号），这是它灵活处理环境差异的地方。**不能**：增加计划之外的新类别动作、扩大目标、做任何 C 档动作。超出范围就停下回来问。

## C 档：确认单

到 C 档时 Agent 暂停，写一张确认单：

- **为什么现在需要确认：**属于 C 档的哪一条。
- **要做什么**，影响，**怎么撤销**（含保险丝和回滚时限）。
- **暂停期间系统现在是什么状态：**前面 A、B 档已经做了哪些变更，哪些还在生效。
- **用户可以回复：**确认、取消，或者要求修改。

用户**不需要全程在场**：确认单写清楚，用户什么时候看到什么时候回复都可以。等待期间 Agent 可以继续做**不依赖这一步**的 A、B 档工作，依赖这一步的部分等待。超时不等于确认。

## 不变的硬规则

分级授权放宽的是**"每一步都问"**，不放宽下面这些：

- 接触前门禁 PC0、PC1、PC2 和 PC-G1、PC-G2 各自独立；不通过任何渠道接触 Claude 或 Anthropic 来补证据。
- 付款、注册、登录、KYC、OAuth 由用户本人完成。
- 不收集、不保存、不转述凭据；不把订阅链接、节点密码、UUID 写进规则说明或报告。
- 用户的授权不能覆盖宿主策略和组织策略。
- 不能用代码里的布尔值、回调、临时脚本或终端模拟来伪造授权；范围确认单和计划批准单必须是用户在对话里明确给出的，不能由 Agent 自己生成并默认通过。
- 不承诺免封；不把网络成功当作平台许可。

## 报告

B 档计划结束后汇报：做了什么、原值→新值、验证结果、怎么回滚。`proposed`、`applied`、`verified` 分开写；用户自己报告的观察保持 `reported`，不写成工具已验证。

## 各路线里的动作分档

| 动作 | 档位 |
| --- | --- |
| 只读诊断、IP 质量检测报告、WebRTC 探测页、`render` 预演 | A |
| 导出防火墙备份、布置回滚保险丝、加 `guardian-` 允许规则（默认仍放行）、装 Clash 客户端、装 FlClash TUN、开客机 SSH、前台 SSH 转发、noVNC 本地入口、Realm 中转（只放行用户自己的 IP）、临时切 BBR、关闭本机（Windows 默认）网卡 IPv6、装 Chrome WebRTC 插件或写浏览器 WebRTC 策略、VPS 建 swap、改 swappiness、装 earlyoom | B |
| 默认出站切成阻止、启用 killswitch 或 `vps-guard`、故障演练（目标是远程机器或唯一入口时）、改 SSH 配置、持久化 BBR、关远程机器网卡 IPv6、清理数据 | C |
| 注册、登录、KYC、OAuth、付款、订阅、凭据 | C，由用户本人完成 |

故障演练在用户本机、用户在控制台前时可按 B 档；目标是远程机器时按 C 档。

## 状态机里的可追溯记录（ADR-026）

范围确认单、计划批准单和确认单会写进访谈状态的 `authorization` 段，供宿主和 Agent 查证、复盘。记录只是**追溯**，不执行任何动作；访谈里的回答不会产生记录，G3 仍是 blocked。

| 记录 | 函数 | 规则 |
| --- | --- | --- |
| 范围确认单 | `record_scope_confirmation` | 路线必须已明确选择；只能含 A、B 档动作，含 C 档或未知动作直接拒绝；绑定目标、账号、任务和路线 |
| B 档计划批准 | `record_plan_approval` | 需要有效范围；步骤必须全是 B 档且都在范围内；计划编号不能重复 |
| 计划结果 | `record_plan_result` | 只记 completed、rolled_back、failed；同一结果重复提交是幂等的 |
| C 档确认单 | `request_critical_confirmation`、`resolve_critical_confirmation` | 只能对 C 档动作开；用户回复 confirmed、cancelled、modified；沉默不会自行解决 |
| 一次性使用 | `use_critical_confirmation` | 已确认的 C 档确认只能用一次 |
| 查询 | `authorization_check`、`authorization_summary` | 只读；评估结果里的 `authorization` 字段给出摘要 |

**来源必须是用户的明确回复**（`user:` 开头），`agent:`、`host:` 或空来源一律拒绝，防止 Agent 自己给自己批准。**失效是永久的：**换路线、撤回路线选择、会话恢复，都会让范围、计划和确认单变成 stale，再改回原路线也不复活，必须重新确认。存档被改过（比如把来源改成 `agent:`、往范围里塞 C 档动作）读取时会被拒绝。

**`authorization_check(action)` 的判定：**A 档在有效范围内即可；B 档要有已批准且未结束的计划列着这项动作；C 档要有已确认且未使用的确认单；未知动作按 C 档；注册、登录、付款、凭据、接触 Claude 这四类**永远返回不允许**（`user_performs_this`），即使用户确认过，也由用户本人完成。这是供 Agent 自查的辅助判断，不是执行授权，宿主不能把它当成通行证。
