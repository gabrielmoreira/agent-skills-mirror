# Agent Note: 作者记忆集中到长短篇写作 skill

Status: implemented
Date: 2026-10-15
Related: [跨 skill 保持真实副本](../architecture/2026-05-07-cross-skill-copies-not-symlinks.md)、[作者记忆两级存储](../architecture/2026-09-18-author-memory-two-level-store.md)、[作者记忆按时刻拆分](../architecture/2026-09-26-author-memory-by-moment.md)

## Problem

作者记忆的协议与事务脚本同时出现在 story 路由、长篇写作、短篇写作、去 AI 味与审稿五处。入口和文本处理任务因此各自承担偏好查询、记忆管理与写入责任。维护者要求保留功能，把责任集中到 write skill，而不是删除记忆机制。

## Decision

只在 story-long-write 和 story-short-write 保留作者记忆管理、查询与写入；以长篇写作为共享真源，短篇保留独立安装所需的真实副本。仅管理习惯的请求完成后停止；同时要求写作时继续所请求的写作流程。story 只按书类型路由管理请求，去 AI 味和审稿不独立访问记忆，接续写作流程已经形成的文风裁决；单独调用时使用当前要求与本书文风。两级存储、回执、现有写作召回和数据格式保持不变。同步各端项目指令、共享清单、预算、测试与公开说明。

## Alternatives considered

- 完全移除作者记忆：能消除所有协议与运行时成本，但不符合维护者保留功能的要求，因此撤回。
- 全部集中到 story：单一管理入口最省副本，但仍让路由 skill 承担创作状态，违背明确的 write 归属。
- 长篇与短篇共用跨 skill 文件：能只留一个物理文件，但破坏现有独立安装契约；采用显式清单管理的两份真实文件，其他 skill 不再带副本。

## Consequences

记忆实现从五处收敛到两个写作入口，保留跨会话习惯与现有查询能力；代价是单独审稿或去味不再自动召回作者记忆，需要当前请求、本书文风或写作调用方的裁决。历史偏好数据无需搬迁，长短篇副本仍由共享守卫保持一致。

## Validation

作者记忆事务行为回归、42 项写手管线 CLI 回归与 7 项文风回归通过。静态结构、编号、热路径预算、共享副本与消费可达性、当前契约及宿主适配/部署检查通过。长短篇事务脚本和长篇自动拼包代码保持原样，仅调整归属、路由与后续执行者的接收边界。
