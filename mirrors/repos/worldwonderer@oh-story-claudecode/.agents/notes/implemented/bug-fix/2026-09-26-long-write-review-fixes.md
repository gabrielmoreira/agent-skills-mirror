# Agent Note: 长篇写作审查与开书实测发现的一批断链

Status: implemented
Date: 2026-09-26
Related: [开书按作者确认点分时刻](../architecture/2026-09-26-opening-by-author-moments.md)、[叠加语义与 solo 按时刻少读](../architecture/2026-09-26-budget-stacking-and-solo-reads.md)

## Problem

v0.8.2 开书按时刻拆分、35K 上限落地后，审查与一次长篇 solo 开书实测发现流程之间有断链：

- 任务包对执行者说「不读包外文件」，但包里的流程又点名包外的判据和参考：细纲、卷纲要按 SKILL.md「新增物三级」分级却拿不到原文（实测架构师自己编值写进设定），卷纲流程点名跨书召回、弧线速查、反转类型、灵感库。
- 定设定时作者确认的一句话梗概、核心冲突、终极阻碍、世界观骨架在设定文件里没有落点，下一时刻换上下文只读 `设定/` 就丢了；定设定要建哪些文件三处说法不一，solo 时先提案还是先落盘没说，「八节点位置」在定设定时根本填不了；实测里 1979 年物价、收入量级被直接写进设定，只在汇报里概括。
- 定方向的对标复制规则被删后两处还指向不存在的位置；书级「作者已定」（偏好、红线）写章时写手看不到。
- 细纲任务包在请求章节只被剧情单元部分覆盖时照样成功，缺作用域行时报错把人引向「要写章节范围」；新卷纲验收没用 `--strict`。
- 大修只读 workflow-revision，但字数出带、缺 Node、净删一次和问作者字数的话术只在单章流程里；改写一章的 prompt 缺 `style_resolution` 与作者偏好槽。
- 「定设定」「出卷纲」是新开对话建议里的说法，却不是入口触发词；作者可见的 `Fallback:`／`Notice:` 守卫只认「报告 `Fallback:`」这一种句式，换个动词就绕过。

## Decision

- **任务包自带判据与条件参考**：三种任务包末尾附 SKILL.md「新增物三级」原文，再列「按条件可读」：给出绝对路径与小节、写明条件，满足才读；包头的「不读包外文件」改为「只读本包和条件满足的那几节」。卷纲包的情绪方法只带「长篇单元情绪引擎」一节。请求章节有未被覆盖的，退出码 2 并列出缺的章；单元卡缺作用域行时点名那张卡。新卷纲验收跑 `outline_view.py --check --strict`，往旧卷纲追加单元时去掉 `--strict`。
- **定设定落点**：题材定位模板新增「核心设定」小节；Phase 2 写清交付题材定位补全、关系、主角与关键角色卡、影响全书的世界观，其余角色出细纲时补，与 project-files 对齐；solo 与子代理一样先提案后落盘；物价、力量档位这类全书刻度按新增物三级先问作者；「题材框架」标为出卷纲时补；`.active-book` 缺了就补建；女频定设定另读女频手册。新开对话的建议放在汇报正文最后一句，技术备注仍在最末一行。
- **定方向对标**：资料代际只看两份主产物在不在，首次引用的复制规则写回「对标发现」第 3 条，入口指向那里。
- **写章**：组装脚本把题材定位「作者已定」注入写手 prompt（上限 600 字，超了截断并指回原文，优先于作者记忆）；手动组装同样摘入。
- **大修**：workflow-revision Step 3 加检测状态处置表，Step 4 加字数出带的作者问法与三个选项的去向；改写一章的 prompt 补两个槽。
- **入口与守卫**：description 加「定设定」「出卷纲」，场景表加定设定一行；作者记忆 query 命令写进入口，作者说出长期偏好时才读协议；长篇入口的 `Notice:`／`Fallback:` 原文改为只进技术备注行，并纳入守卫；守卫改为「每处 `Fallback:`／`Notice:` 必须在同一句写明进技术备注」。
- **小修**：参考索引的后宫女主、男频爱情线指向 character-relations；组装脚本 docstring 的槽位说明更新。

## Alternatives considered

- **把包外参考整份拼进任务包**：最强理由是执行者一次拿全、不用判断条件。不用：卷纲包加上跨书召回、弧线、反转三份整份会超 35K，而它们多数书用不上；按条件列出、只读点名那节，最坏叠加 32K。
- **把新增物三级抄一份进 workflow-outline**：最强理由是 solo 主会话与任务包读到同一处。不用：SKILL.md 与 workflow-outline 两份会漂移；由拼包脚本从 SKILL.md 原文截取，solo 主会话本来就读着入口。
- **作者已定改写进 `设定/文风.md`**：最强理由是文风文件已进写手 prompt。不用：作者已定里有剧情红线（不写感情线、否掉的开局），不属于表达维度；放进文风会被 style-resolution 按表达裁决误用。
- **大修时借读单章流程的收口段**：最强理由是不重复文字。不用：借读就是整读 6K 的单章流程，正是按时刻拆分要避免的；大修的问法（退回原稿）也和新写一章不同。

## Consequences

- 收益：执行者不再因拿不到判据或参考而自编；作者在定设定时确认的核心要素、书级红线都有落点并传到写章；大修遇到字数出带和缺 Node 有明确处置；作者可见文本的机器行守卫更难绕过。
- 代价：任务包里写绝对路径，换安装位置后旧包失效（任务包本就每次现拼）；拼包脚本对部分覆盖更严格，老卷纲单元卡范围写得不全时需要先补卷纲；作者已定超过 600 字会被截断，写手要回原文读。
- 待办：story-review 入口仍有 3 处「报告 `Fallback: …`」写法，纳入守卫前需先改（审稿由另一改动负责）。
