# Agent Note: 去味定档只用一套标准

Status: implemented
Date: 2026-09-27
Related: [给 35K 上限留余量](../simplification/2026-09-27-load-headroom.md)

## Problem

story-deslop「诊断与分级」里有两套定档标准，读法互相打架：

- 第一张表按「禁用词密度 + 有没有连续三句套路」定档，重度另有一条「7 Gate 中 4 个以上有问题」；
- 第二张表列六项指标，下面的综合规则先说「取最高档位」，紧接着又说「无重度时中度指标 ≥3 项才按中度」。

同一段文字，禁用词 8 处/千字、其他五项都轻：按第一张表是中度，按综合规则后半句是轻度。选中度还是轻度决定过哪些 Gate、删除上限是 15% 还是 25%。另外「核心场景（开篇、高潮、收束）」没说开篇指哪一段，长篇单章里可以理解成全书开头，也可以理解成本章开头。

## Decision

- 第一张表只留「特征 → 处理策略」，定档只看六项指标。
- 定档规则写成一句：任一项到重度、或四项及以上到中度，按重度；有一项到中度，按中度；六项都在轻度，按轻度。「四项中度算重度」承接原第一张表「4 个以上有问题」的意思；「一项中度即中度」与原第一张表和「取最高档位」一致。
- 「要紧处加一档」写明：本次处理的文字里开头约 500 字、高潮那场戏、最后约 500 字；短篇按全篇、长篇按本章算开头结尾。
- Gate 速查里「按此换算计数」一句随旧规则删掉，速查只用来选 Gate。

## Alternatives considered

- **保留「中度指标 ≥3 项才按中度」**：最强理由是少改稿、少删字，防止一项指标偏高就整篇动刀。不用：这与同一段里的「取最高档位」和第一张表都相反，三处里只有它一处这么写；删除比例上限本身已经挡住过度删改。
- **开篇按全书前三章算**：最强理由是长篇的开头确实最要紧。不用：去味一次处理的是一段文字，按这段的开头结尾判断，执行者才知道看哪里。

## Consequences

- 收益：同一段文字只会定出一个档，选 Gate 与删除上限不再看执行者读到哪一句。
- 代价：原先按后半句会定成轻度的文字（只有一两项中度）现在定为中度，多过 C、D、G 三道 Gate，删除上限从 15% 放到 25%。本次没有跑对比。
