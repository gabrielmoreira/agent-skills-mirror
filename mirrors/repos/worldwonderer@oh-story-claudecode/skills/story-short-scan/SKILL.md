# story-short-scan：短篇网文扫榜

基于真实榜单样本分析短篇市场，给作者可写的情绪方向、题材候选和验证办法。

---

## 核心哲学

### 原则 1：短篇市场是情绪市场

扫榜从题材和简介中判断读者读完的感受、触发场景与情绪爆发点，说明这些内容如何吸引读者。仅凭题材名无法判断具体情绪体验。

### 原则 2：热度只按各平台自己的口径比

榜单给的收藏、赞同、在读、评分各有口径，只在同一口径内比较。排名和互动量只说明样本受到的关注，不能据此断定故事质量或情绪拉扯效果。

### 原则 3：短篇风口来得快去得快

报告写明样本日期、覆盖范围、结论可信度和复扫日期。题材信号可能在数周内失效，过期后只作候选参考。

---

## 扫榜流程

### Phase 1：确认平台和方向

用户已给出平台或方向时直接采用，只问缺项：**「想看哪个平台、男频还是女频、哪类短篇？点众可直接采集；黑岩要有黑岩后台账号、先登录；知乎盐言、番茄和七猫短篇请发榜单截图、文字或链接。手里有编辑的征稿要求也可以一起发来。」**

关键判断：
- 用户已有方向 → 针对该方向做深度扫榜
- 用户没有方向 → 做全榜概览 + 找趋势
- 用户想跨平台比较 → 做平台对比分析

---

### Phase 2：确定数据来源

| 优先级 | 模式 | 说明 | 何时用 |
|--------|------|------|--------|
| 1 | **脚本采集** | 点众、黑岩：抓取平台页面，产出结构化文件 | 有 Chrome 环境时（优先） |
| 2 | **作者提供** | 没有脚本的平台，或作者已有榜单 | 知乎盐言/番茄短篇/七猫短篇等 |
| 3 | **内置知识** | 用历史资料提出待验证的选题 | 无法联网、作者也没有数据时 |

命令中的 `scripts/` 相对本 skill 根目录。

1. 只读所选平台那一份：[点众](references/platform-dianzhong.md) / [黑岩](references/platform-heiyan.md) / [没有脚本的平台](references/manual-rank-input.md)。其中有网址、命令、字段、故障排查、平台分析维度和作者榜单的整理格式。
2. 每次扫榜新建输出目录 `扫榜/{YYYYMMDD}/`（同日再扫加 `-2`）存本次榜单，不往旧目录追加（聚合会混进旧榜）。脚本自动命名文件，作者榜单按平台参考命名；某平台失败就跳过。对比时读上个日期目录的 `扫榜聚合.md`。
3. 聚合：`node scripts/aggregate-rank.js {输出目录} --out {输出目录}/扫榜聚合.md --sparse 10 --scale short`。**主会话只读这份聚合**，需要原始简介与人设信息时再抽样：`node scripts/aggregate-rank.js {输出目录} --sample {题材/标签/书名词} --n 5`。
4. 看聚合的「采集情况」：标了问题（书名没解出来、没采到、详情没取到）的榜单按平台参考排查重采；重采不了就在报告里说明结论不含它。
5. 作者发来征稿要求：原文存进输出目录的 `征稿要求.md`，题材、字数、截止日期当硬条件。

**内置知识：** 跳过聚合，加载 [references/real-market-data.md](references/real-market-data.md)，明确标注「以下分析基于历史趋势数据；未完成实时榜单校验前只能作为候选假设。」并列出需要复扫的平台页面。

---

### Phase 3：数据分析

有真实样本时，以聚合结果和平台参考的「分析维度」为准。趋势需对比同口径的多期样本；仅用内置知识时只给待验证候选，不填写当前数量、占比或涨跌。

1. **情绪排行**：按本节末的情绪表把题材、标签归入六种写作情绪，按样本数量比较。每本书根据简介判断读者读完的感受，只归一类；标签只是线索，无法判断的计「待定」。悬疑题材按简介落点分：最后揭开真相的归反转震撼，留下寒意的归细思极恐
2. **题材热点**：聚合的题材表和标签热词里反复出现的设定、场景
3. **篇幅分布**：聚合的字数分布与各题材字数中位
4. **简介与书名写法**：抽样简介怎么前置冲突、留悬念，书名常见词与代表作标题；可对照 [real-market-data](references/real-market-data.md) 的历史写法
5. **结尾类型**：HE（好结局）/BE（坏结局）/开放式，只在作者提供的内容看得出结局时统计
6. **人设模型**：抽样简介里反复出现的主角类型

| 情绪 | 归入的题材与标签 | 难度 |
|------|------------------|------|
| 意难平 | 虐恋、遗憾、错过、追妻、白月光 | 中 |
| 反转震撼 | 悬疑、身份错位、反转 | 高 |
| 爽感释放 | 打脸、逆袭、复仇、重生改命、宅斗 | 低 |
| 治愈温暖 | 成长、亲情、友情、甜宠 | 中 |
| 细思极恐 | 悬疑、心理、民俗怪谈 | 高 |
| 共鸣感动 | 现实、职场、婚姻、家庭 | 中 |

### Phase 4：输出扫榜报告

报告讲市场结论和能写的方向。脚本名、命令和采集状态不进报告；未采到的平台用一句话说明原因。模板中缺数据的项直接省略；单期样本不写「变化」一节，历史资料不填当前数量和热度。点众、黑岩采的是在架书目，并非热度榜：只有它们的数据时，「榜上数量」写「在架数量」，热度中位一列点众写「评分中位」、黑岩省略，不说哪篇火。

报告展示给作者，同时写进输出目录的 `短篇扫榜结论.md`：文件不存在就先按 [references/topic-match.md](references/topic-match.md) 的模板写文件头，再把报告作为「扫榜结论」一节写入（已存在就整节替换）。

### Phase 5：选题匹配

先读 `短篇扫榜结论.md` 的「扫榜结论」及同目录 `扫榜聚合.md` 和 `征稿要求.md`（有的话）；内置知识模式没有聚合表，只读历史候选。

作者未提供的信息集中问一句：**「打算投哪个平台（还是自己发）？手里有什么素材、擅长写什么？计划写多少字？」** 作者不想答就按样本给方向，可行性最高写「中」。

按 [references/topic-match.md](references/topic-match.md) 写进同一文件的「选题匹配」一节。优先选样本信号明确、作者素材和条件撑得住的方向，写作难度按 Phase 3 情绪表定。

**关键判断**：
- 先说明选题提供的情绪体验，再说明题材创新如何支持它
- 开头 3 句话是留存高风险区，必须建立冲突、身份差或情绪钩子
- 反转是短篇常见传播引擎；若不使用反转，必须用强共鸣、强话题或强余韵补足传播风险
