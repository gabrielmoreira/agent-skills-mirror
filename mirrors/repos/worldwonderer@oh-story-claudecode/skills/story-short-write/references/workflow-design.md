# Phase 2：短篇构思与设计

#### Agent 调用：story-architect

已部署 story-architect 时可 spawn `Agent(subagent_type: "story-architect", prompt: "项目目录：{dir}\n任务类型：短篇构思\n查询参数：{目标情绪+题材方向}")` 辅助框架设计；不可用由主会话直接执行。

与作者确定核心框架：

情绪设计中的反转项仅用于有反转篇；无反转时在该位置记录报应兑现或甜度变化，按本篇设计安排高潮。

```
## 短篇核心框架

### 基本信息
- 标题（暂定）：{}
- 目标字数：{} 字（短篇通常 8000-20000 字）
- 目标平台：{知乎盐选 / 小程序 / 番茄短篇}（三选一）
- 平台基调：{按 submission-craft.md 平台表记下视角、矛盾烈度、章末钩子、结局质感；小节标记与引号按 short-craft.md 第 4 节}
- 目标情绪：{读者读完的感受}

### 一句话梗概
{主角 + 困境 + 反转 + 情绪落点}

### 核心支点
- 类型：{身份/视角/动机/时间线/信息/认知反转，或无反转}
- 核心兑现：{一句话描述主揭示；无反转时写报应或关系兑现}
- 铺垫/期待：{关键铺垫点；无反转时写读者等待兑现的因果或关系节拍}

### 情绪设计
- 开头情绪：{}（强度 {1-10}）
- 中段情绪：{}（强度 {1-10}）
- 反转情绪：{}（强度 {1-10}，峰值维持 ≥2 节）
- 结尾情绪：{}（强度 {1-10}）
- 反转高潮不要骤降：反转前 1 节开始升温，反转节达到峰值，反转后 1 节维持峰值不骤降

### 人设速写
- {角色}：{一句话人设}；声线：{}；口头禅：{}；禁忌：{}（每人一行）
- 关系：{他们之间的关系}

### 题材招式
- {招式名}：{本篇怎么用、落在哪几节}（2-3 条，与校验区核心招式一致）
- 冷门题材另记：{所用公式、情绪节拍、必选场景、规则要点}

### 作者已定
- {作者在对话里定下的人称、偏好、红线，一条一行；否掉的方案也记一行，写明为什么不要}
```

框架确定后按以下任务设计，再将结果写入工作目录。

#### 设计任务（框架确定后执行）

从目标情绪反推剧情，按 `references/writing-workflow.md` 的步骤和模板依次完成：

1. 定平台基调并加载题材风格包：先读 `references/submission-craft.md`，定投稿平台及正文视角、矛盾烈度、章末落点；再读核心 10 题材对应的 `references/genre-styles/{题材}.md` 和通用方法 `references/short-craft.md`，选 2-3 个核心招式，写明本篇用法并存入 `设定.md`「题材招式」。冷门题材将所用公式要点按模板写入该区，供正文与精修直接使用
2. 设计反派（如有）：加载 `villain-and-reveal.md`
3. 确定揭露方式：按同一文件选择；无需揭露时写明原因
4. 编写 `小节大纲.md`，使用 writing-workflow.md 的 12 列表格。**标出付费点卡在哪一节末**：按 `submission-craft.md`「付费点」，用未完成动作、身份/证据变化或两难选择形成断点；先想透该节，再倒排前后。任务卡点仅在能推动情绪、证据、关系、反转或反击时使用
5. 反转信息差验证（公式见 writing-workflow.md）
6. 伏笔回查清单（标准见 writing-workflow.md）

将以下设计字段写入 `设定.md`，供机器验收与后续写作使用：

```markdown
## Phase 2 设计校验
- 题材参考：`references/genre-styles/{题材}.md`（冷门题材写 `references/genre-writing-formulas.md`）
- 核心招式：{招式一}；{招式二}[；{招式三}]
- 反派设计：不适用（{原因}）
- 反转类型：{身份/视角/动机/时间线/信息/认知/无反转}
- 反转位置：第 {X} 节 ÷ 共 {Y} 节 = {Z}%
- 付费点：第 {N} 节末
```

有反派时按 `villain-and-reveal.md` 人设模板，在本块内把“不适用”换成身份、动机、作恶方式、致命弱点、报应五行（一字段一行）。`short-reversal.md` 判断确属无反转题材时，写 `反转类型：无反转` 和 `反转位置：不适用（{报应兑现/甜度递进等原因}）`，不要硬编节号。付费点写进 `小节大纲.md` 对应节的“结尾承接/钩子”单元格。

#### Agent 调用：character-designer

设计任务完成后、跑完成门禁前，已部署 character-designer 时可 spawn `Agent(subagent_type: "character-designer", prompt: "项目目录：{dir}\n任务类型：角色设定\n查询参数：{人设速写+关系}")` 辅助角色设定和语言风格档案；不可用由主会话直接执行。结果压成每人一行（声线、口头禅、禁忌）写进 设定.md「人设速写」，写正文只读这里。

#### Phase 2 完成门禁

两份文件生成后、向用户声明构思完成或进入 Phase 3 前，运行 `node scripts/check-phase2-contract.js --json {短篇目录}`：

- exit 0：Phase 2 机械契约通过，可进入下一阶段；故事质量仍需判断
- exit 1：只把 `repair_scope` 中的检查 ID、证据、期望、reference 路径和修复范围交给本轮 writer；只改失败字段，再运行同一命令
- 最多做 2 轮定向 repair；仍失败则停止，用中文告诉作者设计还缺什么，不得声称 Phase 2 已完成
- exit 2、脚本缺失或不可执行：告诉作者自动检查没跑成，不得用泛化“自检”替代后继续
- 向作者汇报构思只讲故事（梗概、反转、付费点在第几节）和待拍板的问题（附推荐默认），不提脚本、检查 ID、字段或表格列数；作者拍板的改动先写回两份文件并重跑本门禁，汇报末尾按 SKILL.md「写前必读」建议新开对话写正文
