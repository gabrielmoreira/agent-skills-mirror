## Purpose

Pinleaf Forge stores and edits **commercial MCU board/module specs** — pin capabilities, physical layout, and hardware metadata. These specs are consumed by the Role Editor to build pin assignment maps.

**This is NOT where roles, hwrevs, or build targets live.** Those live under `device/pds/pds_hal/board/`.

---

## Naming Clarity

| Term | Definition | Example |
|------|------------|---------|
| **Board** (`boardId`) | A specific commercial MCU module/dev board | `esp32-sm` |
| **`boardAlias`** | Human-readable board label | `"ESP32 C3 Super Mini"` |
| **MCU Target** (`mcuTarget`) | Firmware build target in the HAL | `esp32c3_sm` |
| **HwRev** | PCB revision of the **custom PDS circuit board** built around this MCU module. **HwRev does NOT belong to the commercial board spec.** It is stored in each saved role JSON (`pds-role/saved_roles/*.json`) and drives the Role Editor HwRev dropdown. Board files have no awareness of hwrev. |

---

## Board File Storage

Boards live **flat** in `pds-board-editor/boards/` — one JSON per commercial MCU module, no subdirectories.

```
pds-board-editor/boards/
├── esp32-sm.json
├── esp32-esp32s.json
└── <boardId>.json
```

## Board JSON Schema

```json
{
  "id": "esp32-sm",
  "name": "ESP32 C3 Super Mini",
  "boardId": "esp32-sm",
  "boardAlias": "ESP32 C3 Super Mini",
  "mcuTarget": "esp32c3_sm",
  "sku": "ESP32-C3 Super Mini",
  "description": "...",
  "architecture": "RISC-V",
  "cores": 1,
  "frequency_mhz": 160,
  "ram_kb": 400,
  "flash_kb": 4096,
  "gpio_total": 22,
  "adc_channels": 6,
  "pwm_channels": 6,
  "wifi": "802.11b/g/n",
  "ble": "5.0",
  "supported_interfaces": ["i2c", "spi", "uart"],
  "usb_ports": { "usb1": 1 },
  "system_features": ["rtc"],
  "toolchain": "ESP-IDF",
  "notes": "...",
  "pin_capabilities": [
    {
      "pin": 0,
      "header_id": "J1",
      "physical_pin": "1",
      "group": "Power",
      "var_alias": "pwr_vin",
      "name": "VIN",
      "capabilities": ["VIN"]
    },
    {
      "pin": 2,
      "header_id": "J1",
      "physical_pin": "3",
      "group": "I2C",
      "var_alias": "i2c_sda",
      "name": "GPIO2 / SDA",
      "capabilities": ["GPIO", "ADC", "I2C", "SDA"]
    }
  ]
}
```

**Key fields**:
- `id` / `boardId` — slug, matches the filename (both keys output for compatibility)
- `name` / `boardAlias` — human label (both keys output for compatibility)
- `mcuTarget` — firmware build target used to auto-select MCU Target in Role Editor
- `pin_capabilities[]` — read by Role Editor to populate pin assignment map

> **→ Root `.ai/instruct.md`** — Device Identity Model shows how `mcuTarget` maps to the `board` DB column at provision time.

> **⚠️ Board files do NOT contain `hwrev`.** HwRev is a property of the custom PDS circuit
> board built around the MCU module — it lives in each saved role JSON and is
> never stored in, generated by, or read from the commercial board spec.

**`var_alias` conventions** (board-level, generic):
- Power: `pwr_vin`, `pwr_5v`, `pwr_3v3`, `pwr_gnd`
- GPIO: `gpio_N` (e.g. `gpio_4`) — use GPIO number
- I2C: `i2c_sda`, `i2c_scl`
- SPI: `spi_mosi`, `spi_miso`, `spi_sck`, `spi_cs`
- UART: `uart_tx`, `uart_rx`
- Special: `rst`, `boot`, `en`
- **Never** use role-level names at board level (e.g. `adc_ph`, `step0_dir`)

**Available capabilities**: `VIN`, `GND`, `3V3`, `5V`, `RESET`, `GPIO`, `ADC`, `PWM`, `UART`, `RXD`, `TXD`, `SPI`, `MISO`, `MOSI`, `SCK`, `I2C`, `SDA`, `SCL`, `CAN`, `RMT`, `INTERRUPT`

## Technology Stack

**React 18 + Vite + vite-plugin-singlefile**

The editor is a React SPA that builds to a single self-contained `dist/index.html` (all JS and CSS inlined). No external assets, no CDN dependencies.

| Tool | Purpose |
|------|---------|
| React 18 | UI framework — all state in React, no DOM manipulation |
| Vite 5 | Build tool |
| vite-plugin-singlefile | Inlines all assets → one `dist/index.html` |
| `css/board-editor.css` | Styles (imported directly by Vite) |

Build command:
```bash
cd pds-board-editor
npm install     # first time only
npm run build   # outputs dist/index.html (~190 KB)
```

## State Model

All state lives in `App.jsx` and flows down as props. No global state / context / Redux.

```js
// Board metadata (flat object)
board = {
  boardId, processor, boardAlias,
  website, sku, description,
  architecture, cores, frequency,
  ramKb, flashKb, gpioTotal,
  wifi, ble, adcChannels, pwmChannels,
  commInterfaces: [],   // ['i2c', 'spi', ...]
  systemFeatures: [],   // ['rtc', 'sdcard', ...]
  usb1, usb2, usb3, usb4,
  toolchain, notes,
}

// Each pin (array)
pins = [{
  id: 'pin-<timestamp>-<idx>',  // React key
  headerId: 'J1',               // J1/J2 — controls which column in pinout preview
  physical: '1',                // physical pin number on PCB
  name: 'GPIO 0',
  capabilities: [],  // subset of ALL_CAPABILITIES
}]
```

`boardJson` is derived (`useMemo`) from `board + pins` via `buildBoardJson()`.

## VS Code Extension Integration

The extension (`pds-vscode-extension/extension.js`) opens the editor in a webview panel:
1. Checks for `dist/index.html` first — uses it if present
2. Falls back to `board-editor.html` (legacy) if no dist build

The extension injects a bridge `<script>` before `</body>`:
- Sets `window.__vscodeApi` (acquired via `acquireVsCodeApi()`)
- Sets `window.__isVSCodeWebview = true`
- Bridge runs **synchronously** (inline script); React module defers — bridge is always ready first

**Message protocol (webview → extension)**:

| command | payload | Action |
|---------|---------|--------|
| `saveBoard` | `{ data, filename }` | Save board JSON to `boards/` |
| `loadBoardByName` | `{ boardId }` | Load board from `boards/<boardId>.json` |
| `listBoards` | — | Request saved board list |
| `askCopilot` | `{ prompt }` | Send AI research prompt to Copilot LM API |

**Message protocol (extension → webview)**:

| command | payload | Action |
|---------|---------|--------|
| `boardLoaded` | `{ data }` | Populate form from loaded JSON |
| `boardList` | `{ boards }` | Populate board dropdown |
| `copilotResult` | `{ data }` | Populate form from Copilot JSON response |
| `copilotError` | `{ error }` | Show error message |

## Development Guidelines

### CSS

`css/board-editor.css` is the single stylesheet. Import it via Vite — do not duplicate it.

**Critical column widths** (pin row fields — do not change without updating `pin-overrides.css` and `PinRow.jsx`):
```
.pin-header    — 70px
.pin-physical  — 70px
.pin-label     — 140px
```

Dark mode is implemented via `@media (prefers-color-scheme: dark)` CSS custom properties — no JS needed.

### Adding a New Capability

1. `src/components/PinRow.jsx` — add to `ALL_CAPABILITIES` array
2. `css/board-editor.css` — add `.capability-btn.NEWCAP.active { ... }` rule
3. `src/utils/promptGenerator.js` — add to the capabilities list in the prompt template

### Adding a New Board Field

1. `App.jsx` — add to `INITIAL_BOARD` and `importBoardData()`
2. Appropriate section component (e.g. `BoardBasicsSection.jsx`)
3. `src/utils/buildBoardJson.js` — add to the output object

### Rebuild After Changes

```bash
cd pds-board-editor
npm run build
```

Commit `dist/index.html` — the extension uses it directly.

### DO
- Keep all state in React (App.jsx → props down)
- Keep utils as pure functions (no DOM, no imports from React)
- Import `board-editor.css` once in `main.jsx`
- Commit `dist/index.html` after every build

### DON'T
- Manipulate the DOM directly (`document.getElementById`, `innerHTML`, etc.)
- Add state management libraries (unnecessary)
- Move CSS into component files (keep `board-editor.css` as single source)
- Delete `board-editor.html` (legacy fallback for when dist doesn't exist)
