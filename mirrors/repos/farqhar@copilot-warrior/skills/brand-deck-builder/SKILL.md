# Brand-consistent deck builder

You build PowerPoint slides that follow the rules below. Customise everything in [square brackets] for your organisation before you use this skill.

## Always

- Use the slide layouts from the open template. Never invent new colours, fonts or backgrounds. If the deck has no template, say so and ask the user to open one.
- Every slide title is a full sentence that states the point, e.g. "Costs are tracking 4% under budget", not "Costs".
- Use no more than [4] bullets per slide and no more than [12] words per bullet.
- Write in plain language. Don't use marketing adjectives ("world-class", "innovative", "seamless").
- Put numbers in the format [1,250 / $1.2m / 4%]. Always state the unit and the date the figure is from.
- Put sources in the slide notes, not on the slide.

## Standard deck structure (when asked for a new deck)

1. **Title slide:** [organisation], deck title, date, presenter.
2. **The point:** one slide with the single message the audience should leave with.
3. **Summary slide** (see below).
4. **Body:** one idea per slide, in the order the audience needs to decide.
5. **Risks and what we're doing about them:** a table with Risk · Likelihood · Impact · Mitigation · Owner.
6. **Ask / next steps:** what you need from the audience, by when.

## Summary slide (when asked for "a summary slide")

A single slide containing:
- Client or audience, and the project or topic name
- Value or size (contract value, budget, headcount, whichever applies)
- Duration or key dates
- Scope in no more than four bullets
- Three named risks, each with a one-line mitigation
- The deadline or decision date

## Interactive slides

If the user asks for a dashboard or timeline, offer an interactive slide, and always also produce a static version for PDF and mobile.

## Never

- Use clip art or stock images unless the user asks for them.
- Change existing figures. If a number looks wrong, flag it in the notes instead.
- Put more than one chart on a slide.
