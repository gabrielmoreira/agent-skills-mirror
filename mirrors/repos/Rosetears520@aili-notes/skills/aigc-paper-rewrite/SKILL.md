# AIGC Paper Rewrite

把中文论文正文从“AI式标准论文表达”调整为“保留学术信息的人工复述”。最高方法原则是：**事实不动、术语保留、连接降调、结论收住**。

本文件负责路由、边界和执行顺序。技能包内已经把论文方法、合法改写边界、AI 痕迹识别和论文式自然化规则合并为自包含材料。真正改写前，如果任务不是很短的一两段，必须同时参考 `references/method-detail.md`；需要快速查替换和段落模板时，再看 `references/patterns.md`。不要只凭本文件的压缩摘要发挥。

## When to Use

用户要求处理中文论文、毕业论文、本科论文正文段落时使用，常见说法包括：

- “降低这段论文的 AIGC 风险 / AI 率 / AI 腔”
- “改得像本科论文一点，但不要乱改数据和术语”
- “保留表号、变量、模型和引用，把模板感降下来”
- “按原文、修改后、说明输出论文段落改写”

路由优先级：当任务明确是中文论文/本科论文正文、整篇论文段落、论文 AIGC 检测报告风险段落时，优先使用本技能；如果是非论文文本、泛用正式文本或论文范围不明确，先澄清体裁和目标，不要硬套论文规则。

不要用于：

- 通用朋友圈、营销文案、口播稿、英文 stylome 或非论文人性化改写；这些不属于本技能的论文正文改写范围。
- 伪造数据、案例、访谈、引用、实验过程、检测结果或个人经历。
- 故意加错别字、语病、低质量表达来“降风险”。

## Built-in Method Principles

本技能按以下内置原则执行；规则已经写在本技能包内：

1. 用户当前保留要求和论文语境优先：用户指定不能改的数据、术语、表述、格式和段落范围，必须先保留。
2. 论文准确性优先：事实、术语、数据、引用、变量、表图编号和研究对象不能为了降风险而漂移。
3. 方法改写优先：先做“事实不动、术语保留、连接降调、结论收住”，再考虑句式和词语变化。
4. 合法边界优先：不伪造数据、引用、访谈、实验、个人经历，不故意加错别字、语病，不承诺检测过检。
5. 论文式自然化优先：吸收 anti-AI-register 方法时，只保留“去模板、去宣传、去过度完整、变节奏、落到已有材料”的部分；不把第一人称、情绪、幽默、混乱旁白直接用于论文正文。

如果这些原则冲突，按论文准确性处理。可以少改、轻改或在 `说明` 里说明保留原因，但不能牺牲事实和专业性。

## Non-Negotiable Boundaries

- 保留硬信息：年份、数字、比例、样本量、模型、方法、变量名、图表编号、题项编号、引用、专有名词、专业术语。
- 只改表达、组织和判断力度；不做事实纠错，除非用户另行要求并提供证据。
- 不新增原文没有的低概率细节、案例、访谈、引用、数据或实验过程。
- 不把统计方法、模型名、变量名全部白话化；可以改术语周边连接和判断。
- 不把论文改成聊天、宣传稿、政策文件、情绪化随笔或默认第一人称。
- 不承诺任何官方检测系统结果，也不证明文本一定是 AI 写的或人写的。只能说明这是启发式降低模板感和 AI 腔。

## Workflow

### 1. 先圈出不能动的信息

在改写前标记：数字、年份、模型、变量名、方法名、图表编号、引用、专有名词、专业术语、样本范围和论文上下文。

如果某个事实或术语的含义无法判断，优先原样保留该硬信息，只调整周边表达；不要自行补事实或改口径。必要时在 `说明` 中写明“该处按原文保留，未做事实判断”。

### 1.5 忠实度与有效修改门槛

- 忠实度：`修改后` 必须和 `原文` 属于同一语言、同一主题、同一段落语境，不能把其他段落、摘要句、模板句或无关示例误放进来。
- 硬信息：关键数字、变量、路径、表号图号、方法名、引用和核心事实不能丢失、错位或被近义词误换。
- 有效修改：不能只把“本文”改成“本研究”、把“说明”改成“显示”、把标点换一遍。至少要改善结构、判断力度、抽象名词、连接链、宣传腔或段落顺序之一。
- 成稿要求：`修改后` 是可直接放回论文的正文，不写“建议处理、待补充、需补充材料、可改为”等编辑指令。
- 边界模板：不要默认追加“该判断限于……不宜外推”“本样本/本研究/已有结果……”等通用限制句；只有原文确实过度外推，且限制依据来自原文材料时才加入。
- 长度控制：不要为了降风险把段落明显拉长；需要补出对象、动作、过程时，优先替换空泛句，而不是在句末堆限制。
- 敏感文本：如果输入包含密钥、账号、身份证号、联系方式等隐私凭据，不要在报告中引用；请用户脱敏后再处理。

### 2. 找风险来源

重点检查这些高风险模式：

- 模板连接链：基于、结合、通过、从而、进一步、为……提供依据连续出现。
- 抽象名词串：价值、机制、路径、体系、维度、基础、赋能、触达、转化、格局连续堆叠。
- 高完成度论文腔：句句完整顺滑，结论过满，每段都像“背景—机制—意义”闭环。
- 宣传或政策腔：独具魅力、底蕴深厚、璀璨明珠、重要引擎、广阔前景、高质量发展。
- AI 论文腔：清晰呈现、充分体现、深刻揭示、有效促进、全面提升、具备重要意义。
- 文献综述套话：研究热点、研究前沿、演化脉络、实证范式、价值挖掘密集出现。

### 3. 按论文段落降调

- 具体材料优先于宏大意义：先写已有材料、数据、表图、样本、方法或过程。
- 普通动词优先于抽象名词：用“说明、反映、可以看出、主要是、用于、作为参考”等普通表达替代密集高级动词。
- 有限判断优先于圆满结论：在结论、评价、推断、策略意义处适度使用“较为、一些、一定、相对、主要、目前、可以、能够”，但不要每句都加限定词。
- 材料顺序优先于连接词闭环：不要把“通过……从而……进一步……为……”换成另一套固定句式。先判断这一段真正要交代的是材料、动作、结果还是后文用途；只保留原文需要的关系，能拆句就拆句，能直接说对象和用途就直接说，不为凑完整链条硬补环节。
- 保留自然重复：不要为了避免重复不断换高级同义词。论文中“游客、景区、满意度、产品”等词重复出现是正常的。
- 句长和节奏要有差别：方法段可以保留较长的过程说明，数据和判断句可以更短；不要每句都同样完整、对称、圆满。

### 4. 按段落类型处理

- 文献综述：来源或图表 → 阶段划分 → 每阶段关注点 → 代表研究或数据 → 不足。少写“范式”“前沿”，多写谁研究了什么、用了什么数据/方法、得到什么结果。
- 理论基础：概念是什么 → 常用在哪类研究中 → 本文用它解释什么。可以用“也就是”式普通解释，但不要闲聊。
- 研究方法：使用什么方法 → 处理什么数据 → 得到什么结果 → 用于后文哪一步。长句可以保留，但要像作者在说明获取、发放、回收、筛选、覆盖、访谈对象等过程。
- 数据结果：表图位置 → 核心数字 → 直接含义 → 有限参考价值。不要把百分比拔高成战略结论。
- 景区或案例概况：位置 → 面积/人口/资质 → 核心资源 → 与研究主题的关系。避免宣传语堆叠。

更完整的方法解释、分段处理细节、反例和检查表见 `references/method-detail.md`；快速替换思路和段落模板见 `references/patterns.md`。其中的替换只作语境参考，不是固定词表。

## Non-Body Defaults

默认只处理正文散文段落。以下内容默认跳过或简短说明跳过，除非用户明确要求编辑：

- 章节标题、节标题、表格标题、表格正文、图题、图注。
- 参考文献、问卷选项、附录工具文字。
- 单独统计读数、题项编号、假设编号、目录式条目。

不要把非正文材料扩写成解释段，也不要为只有表格读数或编号的材料创建修改项。

## Output Scope and Contract

先判断用户给的是哪类任务：

1. **整篇文章、章节或连续正文**：按原文顺序逐段处理所有可处理的正文段落，不要只挑“看起来最有价值”的段落，也不要因为某段风险较低就偷懒跳过。
2. **AIGC/AI率检测报告或风险段落清单**：只处理报告中标出的风险段落，不需要扩展到全文。
3. **混合材料**：处理其中的正文散文段落；非正文材料按默认规则跳过或简短说明。

默认格式：

````markdown
### 修改项 1

原文：
```text
<原段落>
```

修改后：
```text
<可直接放回论文的改写段落>
```

说明：<说明保留了哪些硬信息，降低了哪些模板感/抽象词/过满结论/宣传腔。>
````

要求：

- `修改后` 必须是可直接放回论文的成稿，不写“建议改为”“需要补充”等编辑指令。
- 修改项默认以段落为单位，不把完整段落拆成孤立句子逐条改；检测报告通常给出的也是风险段落，按报告中的风险段落逐段处理。
- 整篇文章模式下，每个正文段落都要给出对应修改项。风险较低的段落也可以轻改，但不要为了显得修改多而改变事实、术语或原意。
- 风险报告模式下，按报告中的风险段落逐项输出；不把风险段落再拆成单句清单。
- 如果某一段确实不应改动，在 `说明` 中写明原因，而不是直接漏掉。
- “风险来源”不设默认独立字段；需要时写进 `说明`。
- 控制格式痕迹：正文改写尽量少用加粗、破折号、装饰性项目符号、行内标题、引号和括号。必要 Markdown 代码块除外；原文已有的引用、统计符号或专业括号按原文保留。

## Final Self-Check

交付前逐项检查：

- 忠实度：数字、年份、术语、模型、变量、图表编号、引用、原文语境未丢失或改变。
- 有效修改：不是同义词游戏，而是结构、判断力度、抽象名词、连接链或段落顺序发生实质改善。
- 论文风格：正式、平实、可放回本科/学术论文；没有聊天化、情绪化、默认第一人称、宣传口吻。
- 限定使用：只在结论、评价、推断、策略意义处适度限定，没有机械堆“较为/一定程度上”。
- 句长节奏：长短句按段落内容自然变化，没有每句同长、同结构、同结尾。
- 段落差异：综述、理论、方法、数据、案例概况没有被套成同一种句式。
- 格式痕迹：没有为了显得“规整”而滥用加粗、破折号、引号、括号、装饰性项目符号或行内标题。
- 安全边界：没有检测保证、AI/人工来源证明、伪造材料、故意错别字或泄露敏感文本。
- 输出格式：每个修改项都有一个 `原文` 代码块、一个 `修改后` 代码块和一条 `说明`。
- 不确定处：如果缺少上下文或无法确认事实，不自行补事实；优先按原文保留，并在 `说明` 中写明该处未做事实判断。
