# 空间、站位与画面方向

## 为什么单独管理空间

复杂画面最常见的失败不是“风格不够”，而是人数、左右、前后、距离、出入口和唯一物体不稳定。空间契约应先于表演和镜头运动建立。

## 四套坐标不要混用

| 坐标 | 示例 | 说明 |
|---|---|---|
| 场景坐标 | 北门、工作台东侧、A 区 | 不随摄影机改变 |
| 摄影机坐标 | camera-left、camera-right | 相对摄影机位置 |
| 屏幕坐标 | 屏幕左、屏幕右 | 最终画面中的左右 |
| 解剖坐标 | 人物解剖左手、解剖右脸 | 永远跟随人物身体 |

“人物左边”有歧义。需要严格控制时写：

```text
摄影机位于人物解剖左侧，看到左侧脸；鼻尖指向屏幕右。
人物解剖右手位于屏幕左侧并握住门把。
```

## 深度层：前景、中景、背景

- **前景**：靠近镜头，可用于遮挡、尺度和引导线，不自动等于主体。
- **中景**：主要动作关系所在层。
- **背景**：空间锚点和环境状态，不能擅自加入未登记人物。

写法：

```text
前景左下是唯一破损椅背；中景两名角色相距一臂；背景中央卷帘门保持关闭。
```

不要只写“有层次感”。

## 精确人数和允许集合

先声明总数，再列允许主体：

```text
画面中精确人数为 3：AST-CHAR-001、AST-CHAR-002、AST-CHAR-004 各出现一次。
没有群众、倒影人物、照片中的脸或重复角色。
```

注意：镜子、屏幕、海报和玻璃反射也可能被模型当作额外人物。只有在当前风险存在时才列入禁止出现。

## 唯一物体

关键道具和家具记录四件事：

- 数量：恰好一个。
- 所有者：属于谁或哪个区域。
- 位置：场景坐标和画面深度。
- 接触：谁的哪只手、身体或表面正在接触。

示例：

```text
唯一红色工具箱属于 AST-CHAR-004；位于她身体屏幕左侧，由解剖左手托底、右手握提手；场景中没有第二个工具箱。
```

## 轴线与屏幕方向

### 对话轴线

两人视线形成轴线。若 A 在屏幕左看向右，B 通常在屏幕右看向左。换机位跨过轴线前，应设计中性镜头、移动镜头或明确的越轴意图。

### 运动轴线

角色向屏幕右移动时，连续镜头默认保持相同屏幕方向。若方向改变，镜头中必须看见转身、绕过锚点或经过中性正面/背面状态。

### 动作接点

上一镜结束时的手、脚、道具、身体朝向和动作阶段，构成下一镜 open state。不能只写“连续”。

## 多人站位表

复杂镜头先建立表，再写自然语言：

| 主体 | 场景区域 | 屏幕位置 | 深度层 | 面向 | 视线 | 接触物 | 允许动作 |
|---|---|---|---|---|---|---|---|
| A | 门内侧 | 屏幕左 | 中景 | 屏幕右 | 看 B | 门把 | 保持静止 |
| B | 走廊 | 屏幕右 | 中景 | 屏幕左 | 看 A | 无 | 后退一步 |

若每个人都同时移动、说话和操作道具，先降低动作密度或拆镜头。

## 场景空间参考的继承范围

场景参考常用于布局和材质，不应自动控制镜头：

```text
inherit: 空间分区、墙面材质、卷帘门与工作台的相对位置
exclude: 参考图构图、机位、焦段、曝光、调色、景深、画面中的临时人物
```

## 空间建立顺序

- 先选场景区域和固定锚点。
- 再声明精确人数和允许集合。
- 再放置主体到屏幕位置与深度层。
- 再写朝向、视线和接触。
- 再选择摄影机，不用摄影机描述代替场景布局。
- 最后增加当前镜头特有的禁止项。

## 常见失败与最小修复

| 症状 | 责任层 | 最小修复 |
|---|---|---|
| 左右反转 | 坐标歧义 | 同时写解剖侧、摄影机侧和鼻尖屏幕方向 |
| 额外人物 | 允许集合不清 | 写精确人数、列 ID、针对反射/背景风险 |
| 角色重复 | 身份和数量 | 每个 ID 各出现一次，避免同一描述多次注入 |
| 家具复制 | 唯一物体 | 声明数量、位置、所有者和同一物体引用 |
| 场景布局变化 | 场景资产 | 引用空间图和固定锚点，排除参考原构图 |
| 越轴 | 镜头连续性 | 保持屏幕方向或设计可见转向/中性镜头 |
| 接触漂浮 | 动作物理 | 明确哪只手、接触面、重量和接触阴影 |

## 空间质量门

- [ ] 精确人数与允许 ID 一致。
- [ ] 屏幕左/右和解剖左/右无歧义。
- [ ] 前景、中景、背景各有明确职责。
- [ ] 关键锚点、出入口和唯一物体可定位。
- [ ] 每个重要道具写了所有者和接触关系。
- [ ] 对话或运动轴线明确。
- [ ] continuity in/out 记录屏幕方向和动作接点。
- [ ] 场景参考只继承批准的空间与材质属性。
