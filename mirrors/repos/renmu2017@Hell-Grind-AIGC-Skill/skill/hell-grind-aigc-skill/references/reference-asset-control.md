# 参考资产、状态版本与继承范围

## 资产不是一张漂亮图片

资产的任务是让不同镜头能引用同一个可批准对象。一个可用资产至少需要稳定 ID、身份不变量、可变状态、参考媒体、引用范围、批准状态和权利状态。

## 五类资产

| 类型 | 稳定内容 | 常见可变状态 | 重点检查 |
|---|---|---|---|
| 角色 character | 脸、体型、比例、核心轮廓 | 服装、伤势、妆发、湿度、携带物 | 身份与状态是否分开 |
| 生物 creature | 解剖结构、尺度、轮廓、运动方式 | 变形阶段、伤害、污染、附着物 | 多角度是否保持同一结构 |
| 道具 prop | 几何、尺寸、材质、功能结构 | 开合、破损、污渍、装载状态 | 握持、接触和唯一性 |
| 场景 location | 平面关系、尺度、出入口、固定锚点 | 时间、天气、破坏、陈设状态 | 是否可建立空间图 |
| 视效 vfx | 形态规律、颜色、运动和影响范围 | 强度、阶段、方向、残留 | 是否作用于人物和环境 |

## identity invariants 与 state variables

**identity invariants** 是换镜头也不应变化的身份事实，例如脸部骨相、核心体型、怪物肢体数量、道具几何、场景主平面关系。

**state variables** 是由剧情改变的当前事实，例如服装版本、伤势、血迹、湿度、门是否开启、道具是否破损、场景是否起火。

资产记录示例：

```text
asset_id: AST-CHAR-004
identity invariants: 窄长脸、左眉尾缺口、短黑卷发、瘦高肩线
state version: AST-CHAR-004@v003
state variables: 深灰雨衣湿透、右袖撕开、左手持红色工具箱
```

禁止把状态变化合并进新的身份描述，否则跨镜头会出现“同名不同人”。

## 多视图参考资产表

“多视图”比“三视图”更准确：公开素材中并非每个资产都有严格同尺度、同姿态的正侧背视图。缺失的角度必须登记，不能假装已经存在。

### 角色与生物建议视图

- 正面全身：比例、服装层级、左右标记。
- 左右侧面：鼻、下颌、脊柱、尾巴、道具厚度等轮廓。
- 背面全身：发型、背带、伤势、服装背部结构。
- 面部近景：肤质、眼睛、发际线和稳定标记。
- 关键材质近景：皮肤、鳞片、骨骼、织物、金属连接处。
- 动作范围：站立、下蹲、奔跑或生物特有姿态，标记解剖限制。

### 道具建议视图

- 正侧背和顶部/底部。
- 开启/关闭或装载/空置状态。
- 与手、身体或场景接触的尺度图。
- 材质和磨损近景。
- 唯一识别面与左右方向。

### 场景建议视图

- 平面草图与分区 ID。
- 主出入口方向。
- 关键锚点和唯一家具。
- 四个主要观察方向。
- 日/夜、完整/破坏等状态版本。
- 真实光源和天气入口。

## 引用范围：inherit / exclude

每个参考都必须写明继承与排除：

| 字段 | 说明 |
|---|---|
| `inherit` | 明确允许继承的身份、状态、材质、空间、构图、摄影机、光线或颜色 |
| `exclude` | 明确不允许带入的姿态、背景、构图、镜头、曝光、颜色、文字、IP 元素等 |

推荐写法：

```text
reference REF-017
inherit: 角色身份、脸型、发型、当前服装
exclude: 原图姿态、构图、机位、背景、光线、调色、景深
```

不要写：`完全照着参考图，但换个场景和镜头。` “完全照着”与“换掉”本身冲突。

## 资产状态版本

版本号表达批准的状态快照，不表达镜头顺序：

```text
AST-CHAR-004@v001  干燥初始服装
AST-CHAR-004@v002  雨中湿透
AST-CHAR-004@v003  湿透且右袖撕裂
```

规则：

- 新状态不能覆盖已被镜头引用的旧状态。
- 状态版本记录从哪个版本变化、因何变化。
- 镜头只引用批准状态。
- 多个角色共享同类服装时仍各自拥有状态记录。
- 变形生物按阶段版本化，不在一个镜头里含糊混用多个最终形态。

## 权利状态与批准门

每个参考记录 `rights_status`：

- `owned`：项目自有。
- `licensed`：有明确许可并记录范围。
- `user_supplied`：用户提供，仍需确认用途。
- `research_only`：仅用于研究，不能进入生成交付。
- `unknown`：权利不明，不通过生成前门。

批准状态：`proposed → reference_ready → approved → deprecated`。

公开可访问不等于允许再分发。Skill 不把研究项目的角色、怪物、道具、场景或长提示词复制到新项目。

## 资产质量门

- [ ] 稳定 ID 唯一。
- [ ] identity invariants 与 state variables 分开。
- [ ] 当前状态版本可追溯。
- [ ] 关键多视图存在；缺失视角已登记。
- [ ] 角色/生物比例跨视图一致。
- [ ] 道具结构、尺度和交互面清楚。
- [ ] 场景分区、出入口和唯一锚点清楚。
- [ ] 每个参考含 inherit 与 exclude。
- [ ] 权利状态和批准人明确。
- [ ] 已废弃版本没有被新镜头继续引用。

## 失败定位

| 症状 | 先检查 | 不应先做 |
|---|---|---|
| 脸漂移 | 身份锚点是否稳定、参考是否混入多个身份 | 堆更多通用负面词 |
| 服装回退 | 镜头是否引用正确状态版本 | 重写整个人物小传 |
| 背景照抄参考 | inherit/exclude 是否只写“参考” | 删除所有参考 |
| 道具复制 | 唯一性、数量和接触关系 | 只写“不要重复”十次 |
| 怪物结构变化 | 多视图与解剖不变量是否足够 | 增加无关材质形容词 |
| 场景重建 | 空间图和固定锚点是否批准 | 用一个构图参考控制所有镜头 |
