# 开局、呈现与诊断

解决“玩家如何进入、第一眼看到什么、游戏哪里不好玩”。世界与角色见 `world-and-cast.md`，状态与规则见 `state-and-rules.md`，规划与回合见 `planning-and-scenes.md`。

## 开局目标

开局不是设定说明，是玩法演示。它要让玩家：

- 知道自己是谁、在哪、现在要面对什么；
- 遇到一个具体压力/异常，而不是一段世界概述；
- 看见可互动的人/物/环境；
- 理解这个游戏怎么玩：可以观察、交谈、行动、承担后果；
- 感受到基调：文风、节奏、危险程度、内容边界；
- 做一个有意义的选择，而不是看一段过场。

开局结束时，玩家应该有一个**现在就想做**的动作。

## 常见开局类型

| 类型 | 适合 | 注意 |
| --- | --- | --- |
| 半路开场 | 冒险、生存、动作 | 从压力中间开始，边做边解释；不要先讲背景 |
| 冷开场 | 悬疑、恐怖、异常事件 | 用一个反常细节抓住注意力；不要故弄玄虚 |
| 关系开场 | 恋爱、群像、日常 | 用一个具体互动展示关系和张力；不要只介绍人设 |
| 委托/任务开场 | 调查、经营、冒险 | 委托要带压力/代价，不要只是“去某地杀某怪” |
| 选择开场 | 多路线、沙盒、自定义主角 | 让选择建立角色/立场；不要用选择代替世界 |
| 余波开场 | 续作、阶段过渡 | 先处理上一阶段后果，再打开新方向 |

开局类型不是模板；关键是“具体情境 + 可行动 + 有压力”。

## 开局检查清单

- 第一段有没有具体动作/感官细节，而不是世界观概述？
- 玩家有没有一个立即想要/需要做的事？
- 有没有一个会回应玩家的角色/环境？
- 有没有一个未解问题/威胁？
- 第一个选择是否有 3 类以上不同方法，且各有代价？
- 有没有一口气倒出太多设定/人名/地名？
- 基调是否和后续一致？
- 内容边界是否清楚？
- 玩家是否知道自己能做什么、不能做什么？
- 开局是否留下了下一步，而不是总结？

## 题材承诺

开局要让玩家知道这是哪种体验：升级爽文、凡人流、江湖庙堂、无限流、规则恐怖、都市隐杀，或它们的混合。至少让一个承诺立刻可见：

- **升级爽文**：一个可见的成长阶梯、被低估的起点、可反击的压力。
- **凡人流**：资源/寿元/信息差的现实压力，以及“谨慎准备”能带来的掌控感。
- **江湖庙堂**：名声/人情/势力/规矩，一个需要看人脸色的场面。
- **无限流**：一个明确的副本契约/任务/时限，以及“失败有代价”的信号。
- **规则恐怖**：一个可观察的规则/禁忌/异常，以及“信息能救命”的暗示。
- **都市隐杀**：公开身份与隐藏身份的张力，一个日常与危险交错的场面。

不需要在开局展示所有系统，但不要用 A 题材的开局承诺 B 题材的体验。六类题材的完整构建清单见 `web-novel-patterns.md` 的「六类题材 lens」。

## 第一选择

第一选择是玩家对“这个游戏怎么玩”的第一印象。

- 让玩家做“方法/立场/代价”的选择，而不是“是否继续”。
- 每个选项都应有理由被选；不要让一个选项明显最优。
- 选择应揭示世界规则/人物关系，而不是考试。
- 允许玩家不选菜单，直接自由输入。
- 选项要和正文结尾一致；不要在选项里引入正文没建立的资源/人物。
- 选项文本要短、具体、可判断；不要把选项写成小说段落。
- 至少一个非战斗/非正面选项；让玩家可以选择谨慎、社交、迂回或放弃。
- 不要把唯一必要线索藏在单一选项后。

示例结构：

```text
眼前压力：一个受伤的信使倒在门口，手里攥着半枚印章。
可行动作：
1. 先救人。
2. 先看印章。
3. 先去马厩查看动静。
4. 问在场的 NPC。
5. 熄灯，观察外面。
每个选项的代价：暴露、耽误、欠人情、失去主动权、错过信息。
```

## 开局常见问题

- **设定倾倒**：一上来解释世界、历史、势力、等级；玩家还没有理由关心。
- **没有压力**：只是“你来到一个地方”，没有眼前要处理的事。
- **没有选择**：开局是过场，玩家只能点“继续”。
- **选择是假的**：所有选项都通向同一结果，或只有一个正确选项。
- **NPC 抢戏**：NPC 做完了所有事，玩家只是旁观。
- **信息过载**：一次出现太多人名/地名/组织名，玩家记不住。
- **基调错位**：开局像喜剧，后续是恐怖；或开局很严肃，后续是日常。
- **边界不清**：恋爱/暴力/恐怖内容没有前置说明，玩家不知道会遭遇什么。
- **开局太长**：把第一章写完才给第一个选择；玩家还没有参与感。

## 呈现契约

呈现方式也是游戏设计的一部分。它决定玩家如何接收信息、如何判断节奏。

- **视角**：第一人称/第二人称/第三人称；是否限制在主角感知内；是否允许导演旁白。
- **长度**：每回合目标字数；开局可以略长，但不要变成小说章节。
- **对话**：引号/自由间接引语；NPC 说话风格；是否展示内心活动。
- **信息密度**：每段只给玩家能处理的信息；不要一次塞完。
- **状态展示**：哪些值出现在状态账本；玩家如何看到变化；不要把导演秘密放进账本。
- **选项呈现**：选项是建议，不是限制；正文不要写成菜单；允许自由输入。
- **内容边界**：什么可以出现、什么不可以、以什么方式呈现；在故事简介/叙事风格/自定义游戏 Agent 提示中明确。
- **图像/音频**：可选，服务氛围和信息，不替代文字决策；不要用图像泄露未揭示内容。

呈现契约要和开局一致。开局展示什么节奏，后续就应该是什么节奏；如果后续要改变，先让玩家知道。

## 诊断表

| 症状 | 可能原因 | 最小修复 |
| --- | --- | --- |
| 玩家不知道做什么 | 没有即时压力/目标/线索 | 加一个眼前威胁、一个明确目标、三条可追线索 |
| 选择都一样 | 选项只改措辞，不改后果 | 给每个选项不同代价/受益者/信息/后续压力 |
| 剧情推不动 | 没有时钟/NPC 议程，世界等玩家 | 加一条前线时钟，让 NPC 先行动 |
| NPC 像工具 | 没有独立目标/知识/底线 | 补“想要什么、会怎么做、知道什么、不会做什么” |
| 世界很空 | 资料是百科，没有可行动接口 | 把条目改写成“能做什么/会被什么阻止/代价” |
| 状态越记越乱 | 字段太多、没有更新规则、与资料重复 | 删到只剩会被读取的字段，补更新触发，分开三层账本 |
| 判定太多/太随机 | 没有赌注也掷骰、难度不透明 | 只对“不确定 + 有意义后果”掷骰；先定赌注和难度依据 |
| 失败就卡住 | `blocked`/`hard_failure` 用错，缺少替代路线 | 改 `fail_forward`/`success_at_cost`，给代价和另一条路 |
| 剧情像写好的 | 规划是剧本、强制主线、量子食人魔 | 改情境/议程/分支可能，转移剧情功能而不是强制路线 |
| 升级无感 | 阶段没有新权限/社会反应，只是数字变大 | 给阶段新的访问权、NPC 态度、地图/任务门槛 |
| 爽点不足 | 没有铺垫、见证者或玩家贡献 | 加压制、公开场合、准备选择、可见回报 |
| 金手指万能 | 没有代价/限制/反制，所有问题都靠它 | 加成本、暴露风险、天敌、不能解决的问题 |
| 题材不像 | 开局/资料/规则没有兑现题材承诺 | 回到题材 lens，补一个标志性体验、场景或规则 |
| 设定前后矛盾 | canon/state/plan 混在一起 | 三层账本分开；冲突以已确认正文为准，修正另一边 |
| 玩家没有代入感 | 玩家没有身份/选择权，NPC 抢戏 | 明确玩家角色与目标，让选择改变关系/局势 |
| 节奏拖沓 | 场景没有目标/出口，过多无意义检定 | 每场写清目的和出口，剪掉无决策流程 |
| 结局仓促 | 没有终局条件/铺垫/回收 | 提前定义可能终局，布置线索，回收主要承诺 |
| 内容越界 | 边界没前置/没写进呈现契约 | 在故事简介/叙事风格/自定义游戏 Agent 提示中明确边界与处理方式 |

## 最小修复原则

诊断不是重写。先定位一个失效环节，再做最小有效修改：

1. **先问玩家现在缺什么**：目标？信息？压力？选择？反馈？
2. **只改一个主要原因**：不要同时加人物、改规则、重写规划。
3. **保留已确认事实**：不要为了修复节奏 retcon 玩家选择或已发生事件。
4. **优先改局势，不是改数字**：加一个时钟、一个 NPC 行动、一个可见信号，通常比调难度更有效。
5. **改完跑一回合**：看玩家是否能做出不同选择，世界是否回应，状态是否变化。
6. **如果问题反复出现**：再考虑改规划/规则/状态结构，而不是继续打补丁。

## 交付前总检查

- 玩家现在能做什么？为什么要在意？
- 如果玩家不动，什么会恶化？
- 这次选择改变了什么？失败会怎样？
- 玩家知道什么？角色知道什么？导演知道什么？
- 新增事实放对账本了吗？
- 这段是否只交付了作者要的范围？
- 是否过度构建？是否应该先跑一局再补？
- 开局是否展示了玩法，而不只是设定？
- 选项是否有不同方法/代价，且没有明显最优？
- 结尾是否留下有意义的选择，而不是总结？

## 规模匹配

- **短局**：一个强开场 + 一个压力 + 一个选择即可；不要为 10 分钟的游戏建 50 条资料。
- **中局**：开场可以稍微铺陈，但要尽快给第一个选择；不要用前 3 回合讲设定。
- **长局**：开场可以埋长线，但必须先有一个当下可解决的问题；不要用“未来会很重要”代替现在的压力。
- **连载**：每个阶段都要有阶段性收束和再出发；不要把开局拖成序章。

先跑一局，再决定要不要加系统。一个能跑起来的简单游戏，比一个设计完整但没人能开始的游戏更有价值。

## 检查清单

- 开局是否让玩家知道自己是谁、在哪、要面对什么？
- 是否有具体压力/异常，而不是世界概述？
- 是否有可互动的人/物/环境？
- 第一个选择是否有 3 类以上不同方法，且各有代价？
- 是否避免了设定倾倒、NPC 抢戏、假选择、信息过载？
- 基调/边界是否清楚且与后续一致？
- 呈现契约（视角/长度/对话/状态/选项/图像）是否明确？
- 诊断是否只改一个主要原因，保留已确认事实？
- 修复后是否跑过一回合，确认玩家能做不同选择、世界有回应、状态有变化？
- 是否只交付了作者要的范围？是否应该先跑再补？
