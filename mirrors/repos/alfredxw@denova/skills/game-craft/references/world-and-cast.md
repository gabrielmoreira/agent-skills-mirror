# 世界、角色与资料库

解决“这个世界是什么、谁在推动它、玩家能拿它做什么”。整体判断见 `SKILL.md`，状态与规则见 `state-and-rules.md`，未来安排见 `planning-and-scenes.md`。角色性格的三层设计、属性库和可演出写法见 `character-personality.md`；本文件只处理角色条目与资料库位置。

## 先写一页纸

在写条目之前，先用一页纸定住游戏承诺。没有一页纸，资料库很容易变成碎片化百科。

```text
玩家扮演：
玩家想要：
玩家反复做的事（核心循环）：
阻碍 / 压力：
一次典型回合：
失败会怎样：
这局最终可能变成什么：
基调与边界：
不做什么：
```

检查：

- 玩家是否有一个**现在就想做**的动作，而不是一个宏大目标？
- 核心循环是否能重复，而不是一次性剧情？
- 阻碍是否会产生选择，而不是只延迟结果？
- 失败是否会改变局势，而不是让游戏结束？
- 这局可能变成什么，是否留下了多种合理走向？
- “不做什么”是否明确？它和“做什么”同样重要。

如果一页纸写不出来，先不要建资料库。先和作者确认玩家体验、核心循环和边界。

## 核心循环

核心循环是玩家反复做的动作组合。它决定资料库需要哪些“可行动接口”。

用四个问题检查：

1. 玩家通常先做什么？（观察、交谈、搜索、交易、战斗、建设、选择路线）
2. 这个动作会得到什么信息或资源？
3. 什么会阻止或改变它？（人物、规则、时间、代价、风险）
4. 结果如何把玩家送回下一个决定？

常见循环：

| 类型 | 循环 | 资料库重点 |
| --- | --- | --- |
| 调查 / 悬疑 | 进入现场 → 找线索 → 形成判断 → 对质/行动 → 新压力 | 地点接口、嫌疑人议程、线索网、真相 |
| 关系 / 恋爱 | 互动 → 试探/误会 → 选择 → 关系变化 → 新情境 | NPC 欲望与边界、关系张力、情感节拍 |
| 生存 / 经营 | 评估资源 → 投入/取舍 → 世界回应 → 压力上升 → 再分配 | 资源、时钟、基地/经济、外部势力 |
| 冒险 / 战斗 | 侦察 → 准备 → 冲突/检定 → 代价 → 新区域 | 规则、敌人、关卡、资源消耗、失败推进 |
| 开放 / 沙盒 | 选择目标 → 探索/交涉 → 势力反应 → 局势变化 | 势力议程、地点接口、事件表、世界时钟 |
| 无限流 / 副本 | 进入副本 → 找规则 → 完成任务 → 结算 → 下一副本 | 副本规则、任务、空间资源、异常实体 |

循环不需要复杂。一个短局可以只有“观察 → 选择 → 后果”三步；关键是每一步都能改变下一步。

## 最小可玩世界

一个能开始玩的世界，至少要有：

1. **一个起始地点**：3 个可行动的细节（能看、能碰、能利用），不是一段风景描写。
2. **2–4 个有自主性的角色/势力**：各自想要什么、会怎么做、知道什么、底线是什么。
3. **1–3 条世界规则**：会限制选择、产生代价的规则，不是百科条目。
4. **1–3 个压力/时钟**：如果玩家不干预，什么会恶化。
5. **3–5 条线索/秘密**：每条都有至少一个可发现的入口；揭示时机放规划。
6. **一个玩家想要的资源/回报**：钱、情报、信任、通行权、力量、真相。
7. **一个开局 + 第一个有意义的选择**。
8. **内容边界**：什么可以出现、什么不可以、以什么方式呈现。

规模提醒：

| 规模 | 资料条目 | 地点 | 角色/势力 | 压力 |
| --- | ---: | ---: | ---: | --- |
| 短局/一夜 | 5–12 | 1–2 | 2–3 | 1 个时钟 |
| 中局/一章 | 10–30 | 2–4 | 4–6 | 2–3 条前线 |
| 长局/连载 | 30+ | 4+ | 6+ | 3+ 条前线/时钟 |

数字是提醒，不是硬门槛。先做能玩的最小集合，再按实际需要扩展。不要一开始就建 300 条资料、20 个状态字段、10 条主线。

## 资料库条目

### 条目边界

- 一个条目只放一个可独立检索的实体或主题：人物、地点、势力、物品、世界规则分别成条。
- 只写稳定事实和已确认 canon；不写当前状态、未来剧情、人物猜测。
- 名称唯一、稳定，能被 `[[名称]]` 直接引用；别名和常用称呼放进正文或关键词，不另建同义条目。
- 简介负责让模型判断“这条是否相关”：3–5 句，写清类型、身份/用途、别名、关键事实、适用场景和触发词。
- 正文按“稳定事实 → 可行动接口 → 阻力与代价 → 关系与接口”组织；同类信息放在一起，不按时间流水账记录。

### 可玩条目模板

```text
名称：
类型：
一句话定位（玩家会怎么遇到 / 使用它）：
稳定事实（不可随意改变）：
可行动信息（能做什么、能得到什么）：
阻力与代价（会被什么阻止、失去什么）：
外观 / 物件 / 感官锚点（可选；重要人物、物品、地点至少一个可记忆细节）：
关系与接口（[[相关条目]]）：
玩家可能不知道的真相（可选；揭示时机放规划）：
```

检查：

- 删掉设定介绍后，它还剩下可行动的东西吗？
- 它带来什么选择、冲突、代价或线索？
- 它是否只包含一个可独立检索的实体/主题？
- 它是否把当前状态、未来剧情、人物猜测混进来了？
- 它是否依赖标题/关键词被看到？如果只注入名称，模型能知道正文吗？
- 它是否和其他条目重复？重复的关系优先用 `[[名称]]`，不要复制正文。

### 各类型写什么

| 类型 | 在通用模板上补充 | 常见问题 |
| --- | --- | --- |
| `character` | 目标、方法、资源、底线、信息边界、关系张力、议程、外观/声音/物件 | 只写履历和性格标签，不写他会做什么 |
| `location` | 谁控制、普通人怎么生活、进入条件、资源、危险、可行动接口、感官细节 | 只写风景，不写权力、资源和行动可能 |
| `faction` | 目标、资源、手段、内部派系、对外关系、行动节奏、标志/仪式 | 只有名称和首领，没有组织行为逻辑 |
| `item` | 来源、功能、使用条件、代价、归属、可被谁利用、外观/材质/磨损 | 只写数值和外观，不写限制与归属 |
| `world` | 世界事实、规则/能力体系、历史、文化、经济、地理 | 写成百科词条，规则没有限制和代价 |
| 自定义分类 | 按项目定义，但至少保留稳定事实、可行动接口、边界 | 为每个想法新建分类，导致条目无法检索 |

Denova 的默认分类是 `character`、`location`、`faction`、`item`、`world`；旧项目可能还有 `rule`、`other`。规则优先归入 `world` 或项目自定义的规则分类，`other` 只在没有更合适分类时使用。

### 外观、物件与感官锚点

资料条目不能只有“事实”，还要能让玩家看见、听见、记住。重要人物、关键物品、核心地点至少有一个可记忆细节：

- **人物**：1–2 个视觉/声音/行为特征，例如旧伤、口音、总在擦的刀、从不摘的手套；外观要透露身份、阶层、职业或经历，不写“万能美人”。
- **事物**：材质、重量、温度、磨损、声音、气味、来历、主人、代价；物品要能引发“拿/不拿、用/不用、给/不给”的选择。
- **地点**：3 个感官细节 + 谁控制 + 普通人怎么生活 + 外来者要付什么；不要只写风景。
- **势力**：标志、制服、建筑、仪式、称呼、等级、黑话；让玩家一眼认出“这是谁的地盘”。
- **场景**：一个“明信片画面”——如果截一张图，玩家能认出这是哪里、发生了什么、暗示什么危险/机会。

模板不必每条填满；但重要条目没有可记忆细节，玩家就很难对世界产生沉浸感。更多人物/事物/地点/势力的写法见 `web-novel-patterns.md` 的「沉浸感」。

### 加载方式与索引

Denova 的资料不是“全量注入”，而是通过 Lore Index 分级展示：

- `resident`：常驻，通常给全文。只给每轮都在场的最小 canon，例如世界前提、核心规则、主角/核心 NPC 的最小身份。
- `auto`：按需。索引通常给名称或简介，模型需要时再按名称读取全文。
- `manual`：手动/显式引用。仍可被查询，只是不会自动注入；适合不希望在普通回合自动出现的条目。
- 自定义分组：可以按“当前地区”“当前势力”“当前案件人物”等组织，并统一设置名称/简介/全文。

使用原则：

- 常驻全文是上下文预算，不是奖励。能通过名称/简介发现的内容，不要常驻全文。
- 资料条目可以被 `[[名称]]` 引用，但引用不会自动展开正文；需要时用 `query_lore_items` 按名称读取，`detail=full` 才返回完整正文。
- 只被名称引用、没有读过正文的内容，不能当作已知 canon；不要在正文里编造未读条目的细节。
- 索引分组是“发现入口”，不是事实源。修改分组不会改变资料正文，也不会自动让模型理解正文。

## 角色条目

### 先写功能，再写人设

NPC 是功能性角色，围绕功能设计，不写用不到的内容。一个 NPC 可以同时承担多种功能：

- 推动目标；
- 施加阻力；
- 提供或遮蔽信息；
- 制造关系压力；
- 代表世界/势力反馈；
- 提供不可完全预测的变量。

不需要给每个路人建条目。只给会反复出现、会改变局势、会被玩家记住的角色建。功能性 NPC 只写与当前冲突有关的部分，不写完整履历。

### 角色模板

```text
姓名 / 常用称呼：
叙事功能（在故事中推动什么）：
性格（MBTI 原型 + 按重要度选 1–5 个属性标签，每个标签配一个可演出细节）：
内核（核心欲望、核心恐惧、价值观、缺陷；可选）：
外在目标（想要什么，可判断成败）：
方法 / 资源（会怎么做、凭什么做到）：
底线（不愿牺牲什么；压力下会怎么选）：
信息边界（知道什么、不知道什么、误以为什么）：
关系张力（与玩家、与其他关键人物）：
外观 / 标志性细节（1–2 个可记忆特征）：
可演出的声音 / 行为细节：
议程（如果玩家不干预，他会做什么）：
登场条件 / 退场条件：
```

填写原则：

- 目标要可判断成败，不要写“想变强”这种无法验证的愿望。
- 方法/资源决定他能做什么；没有资源的角色只能提供态度，不能推动局势。
- 信息边界比“性格”更重要；它决定角色会不会被骗、会不会说漏嘴、会不会误解玩家。
- 声音/行为细节要能被演出：口头禅、说话节奏、习惯动作、避免的话题。不要只写“温柔”“冷酷”。
- 性格要能演出，也要能预测：每个标签至少对应一句台词、一个动作和一种压力下的反应；写不出就说明它还不属于这个角色。
- 性格与议程、底线、信息边界要互相解释：他为什么会这样做，比“他是什么性格”更重要。
- 同一 MBTI 的 NPC 要靠属性与内核区分；不要让同类型角色共享同一套语气。
- 议程让世界在玩家之外运转；即使玩家不找他，他也在行动。
- 登场/退场条件让角色出现在该出现的地方，而不是随机刷出。

### 主角

- 玩家扮演的角色需要有**可行动的身份**和**至少一个当下目标**；不能只是“一个普通人”站在世界里。
- 主角的能力边界要清楚：能做什么、不能做什么、代价是什么。不要让主角什么都会。
- 主角的初始关系、资源、位置要能支撑第一场戏；不要等玩家自己发明。
- 如果主角来自资料库快照，保持其核心 canon；故事内的变化放状态，不要改写资料库。
- 不要让 NPC 替玩家做决定、替玩家承担所有风险，或抢走玩家的核心行动。

### 对手

- 对手要有独立目标、合理信息、自己的底牌；不能只负责阻拦。
- 对手的行动要有节奏：试探、施压、交易、升级、收网；不要原地等玩家。
- 对手的失败要改变局势，而不是“被打败后消失”；留下后果、资源、关系或新威胁。
- 对手不一定是人；也可以是制度、自然灾害、期限、规则、群体压力。

## 势力与前线

势力不是背景板，是能自主行动的行动者。把势力写成“前线”，可以直接用于规划。

```text
势力 / 前线：
目标：
资源：
手段：
时钟（4 / 6 / 8 段，每段发生什么）：
玩家能观察到的信号：
玩家干预会改变什么：
不干预会发生什么：
```

原则：

- 时钟每段都要有可见信号；不要隐藏所有进度，否则玩家无法判断风险。
- 玩家干预可以改变时钟速度、资源、目标或联盟，而不是只有“阻止/不阻止”。
- 不干预也要有结果；世界不会等玩家。
- 一个势力可以有多条前线（军事、政治、经济、情报），但不要给每个势力都建全套；只建与当前故事有关的。
- 势力内部可以有派系；派系冲突是选择来源，不是设定装饰。
- 世界阶梯、名声/武评/贡献/机构地位等社会资本，以及宗门任务/拍卖/公开比试等场景，见 `web-novel-patterns.md`。

## 秘密与信息

### 三类知识

- **导演真相**：世界实际上怎样、谁做了什么、结局可能是什么。放 Lore 的稳定事实和 Planning 的揭示安排。
- **角色知识**：每个角色知道什么、误以为什么、隐瞒什么。放角色条目的信息边界；需要逐回合追踪时，才放状态字段。
- **玩家知识**：玩家已经发现什么、能推断什么。放状态（已知旗标/线索）或正文；不要让玩家“应该知道”却没有任何获得路径。

### 线索设计

- 每个重要结论至少准备 3 条不同入口的线索：不同地点、不同人物、不同行动方式。
- 线索可以被误解，但不能不存在；失败给代价、噪音、延迟或新压力，不给“什么都没”。
- 不要把唯一必要线索藏在单一选项、单一技能或单一角色后面。
- 线索要有物理/社交存在：一封信、一道痕迹、一个说谎时的停顿、一个账本、一个目击者。
- 玩家可以错过线索，但不能因为一次错过就永远无法推进；准备替代路径或让线索以代价再次出现。

### 秘密与揭示

- 秘密的真相放 Lore；什么时候揭示、向谁揭示、需要什么前提，放 Planning。
- NPC 可以说谎，但要有可观察的破绽；不要用“读心”或旁白直接告诉玩家真相。
- 不要把所有秘密都设成“只有问对问题才存在”；秘密应该在场景里有痕迹。
- 揭示要改变局势：新信息应带来新选择、新风险或新关系，而不是只解释过去。

## 常见错误

- 世界只有风景，没有权力、资源、规则和行动可能。
- 资料条目写成百科，玩家无法用它做任何事。
- 每个想法都建条目，资料库无法检索。
- 角色只有性格标签，没有目标、方法、资源和议程。
- 角色卡写满性格标签，却没有可演出的台词、动作和反应。
- 所有 NPC 对玩家同一种态度，换名字也分不出谁在说话。
- 反差没有揭示条件，玩家看到的是随机变脸。
- 对手只负责阻拦，没有独立目标和底牌。
- 势力只有名字和首领，没有行动逻辑和时钟。
- 秘密没有线索，或线索只有单点入口。
- 把当前状态、未来剧情、作者猜测写进资料库。
- 让 NPC 原地等待玩家，世界不运转。
- 用资料库正文替代规则判定，或把判定规则写进世界设定。

## 检查清单

- 一页纸能否说清玩家、循环、压力、失败和边界？
- 起始地点是否有 3 个可行动细节？
- 是否有 2–4 个有目标、有方法、有议程的角色/势力？
- 每条资料是否只包含一个可独立检索的实体/主题？
- 每条资料是否至少提供一个行动、冲突、代价或线索？
- 资料是否把稳定事实、当前状态、未来计划分开了？
- 重要角色是否有信息边界、议程、登场/退场条件？
- 重要角色是否有可演出的性格细节？遮住名字，玩家能否从对话和行为认出他？
- 角色的性格是否解释了议程、底线和翻脸条件？
- 重要结论是否至少有 3 条不同入口的线索？
- 常驻全文是否只给了真正每轮都在场的内容？
- 是否存在“只有名称、没有正文”的引用被当成已知 canon？
