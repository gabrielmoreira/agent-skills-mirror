# 人物与规则

解决「谁在推动故事、规则如何产生选择与阻力」。整体结构见 `premise-and-outline.md`，场景中的信息边界见 `scene-and-payoff.md`。

## 人物卡

**怎么做**：先写外在目标，再写内在需求，最后写压力下的底线。配角和对手也要有独立目标与信息边界。

**主角模板**：

```
姓名 / 身份：
外在目标（他想要什么，可判断成败）：
内在需求（他真正需要理解或改变什么）：
初始缺口（缺能力 / 缺认同 / 缺信任 / 错误认知）：
行事方式（性格与经历如何形成）：
底线（不愿牺牲什么；压力下会怎么选）：
信息边界（知道什么、不知道什么、误以为什么）：
关系张力（与谁目标冲突 / 价值冲突 / 亏欠）：
变化节点（哪次选择让人物不同）：
```

**配角 / 对手补充**：

- 他要什么？为什么不能退让？
- 他掌握哪些主角不知道的信息？
- 他如果是对的，故事会怎样？
- 能否设置镜像人物：面对同一困境做出另一种合理选择，用来照出主角的变化？

**检查**：把人物换成「功能性帮手」后，冲突是否仍然成立？如果不成立，说明人物有独立动机。

## 规则卡

**怎么做**：只设计当前故事要用的规则；每条规则都要能生成选择、限制、代价或冲突。通过使用和后果逐步展示，不先灌输设定。

**模板**：

```
规则 / 能力名称：
来源（谁制定、如何获得）：
触发条件：
效果（能做什么，不能做什么）：
限制（次数、范围、时机、对象）：
代价（资源、风险、关系、暴露）：
谁掌握 / 谁被排除：
如何被既有规则克制或利用：
资源如何获取、消耗、分配：
可能引出的选择（获取 / 交易 / 准备 / 暴露 / 竞争）：
```

**金手指检查**：

- 它解决哪个瓶颈？解决后还剩下哪些约束（知识、渠道、保密、时机、合作、责任）？
- 对手能否用既有规则限制它？
- 是否每次危机都靠它？如果是，先加限制，而不是加更强的敌人。

**检查**：删掉设定介绍后，人物是否仍要因为规则做选择？如果不会，规则只是背景。
