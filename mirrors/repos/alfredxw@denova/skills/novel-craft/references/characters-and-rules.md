# 人物、规则与资料库

解决「谁在推动故事、世界规则如何产生选择与阻力、设定和当前状态分别放在哪里」。整体结构见 `premise-and-outline.md`，场景中的信息边界见 `scene-and-payoff.md`，长篇中的状态累积见 `long-form.md`。人物性格的三层设计、属性库与群像区分见 `character-personality.md`；本文件只处理这些结论写到哪里、如何检索。

## 先分清记录位置

同一件事写错位置，后文就会互相打架。先判断它是否跨章节稳定，再决定放哪里。

| 要记录的内容 | 放在哪里 | 判断标准 | 常见错位 |
| --- | --- | --- | --- |
| 身份、性格、背景、长期关系、能力体系、地点、组织、物品、世界事实 | 资料库（Lore） | 去掉当前章节仍然成立，后文需要反复引用 | 把「目前受伤 / 正在逃亡」写进人物条目 |
| 当前所在地、伤势、心理、短期目标、持有物、能力与关系变化、未解决伏笔 | `setting/character-states.md` | 只对当前进度成立，下一章可能改变 | 把完整人物小传重复进状态文件 |
| 未来章节安排、伏笔兑现阶段、卷 / 章组目标 | `setting/outline.md`、`setting/chapter-groups/` | 还没发生，属于计划 | 把计划写成既成设定，或写进资料库 |
| 已完成章节摘要、近期事件、下一章衔接 | `setting/progress.md` | 已经发生，供连续写作回看 | 把进度摘要塞进大纲或资料库 |

- 资料库通过 `write_lore_items` 写入、`query_lore_items` 读取，不直接编辑 `setting/lore/items.json`。
- 稳定事实发生变化时才更新资料库；普通章节里的状态波动只更新 `character-states.md`。

## 资料库条目

### 条目边界

- 一个条目只放一个可独立检索的实体或主题；人物、地点、组织、物品、规则体系分别成条，不写「全书设定大全」。
- 只写稳定设定和已确认事实；不写当前章节状态，不写未来剧情，不写人物猜测。
- 名称保持唯一、稳定，能被 `[[名称]]` 直接引用；别名和常用称呼放进简介或关键词，不另建同义条目。
- 条目之间用 `[[名称]]` 建立关系。引用不会自动展开正文，需要时再按名称读取。
- 简介负责让模型判断「这条是否相关」：3–5 句，写清类型、身份 / 用途、别名、关键事实、适用场景和触发词。
- 正文用 Markdown，按「稳定事实 → 边界与限制 → 关系与接口」组织；同类信息放在一起，不按章节流水账记录。

### 通用模板

```
名称：
类型：
一句话定位（是谁 / 是什么，在故事中承担什么）：
稳定事实（身份、外观、能力、规则、资源、关系）：
边界与限制（不能做什么、代价、未知部分）：
关系与接口（[[相关条目]]；可引发的冲突、选择、线索或场景）：
```

补充项按需填写：别名 / 关键词、重要度（major / important / minor）、加载方式（resident / auto / manual）、适用场景。重要度和加载方式由写作流程按叙事地位决定，不写进正文冒充设定。

- 重要度按叙事地位：`major` 为主线或反复出现，`important` 为常用，`minor` 为背景。
- 加载方式默认 `auto`；`major` 默认 `resident`。常驻会占用上下文，只给真正需要每轮在场的条目；`manual` 用于需要显式引用、不希望自动注入的条目。

### 各类型写什么

| 类型 | 在通用模板上补充 | 最小可写内容 | 常见问题 |
| --- | --- | --- | --- |
| `character` | 人格原型、性格表现、目标、需求、底线、信息边界、变化弧线 | 身份与角色功能、外在目标、内在需求、底线、长期关系 | 只写履历和性格标签，不写他会做什么选择 |
| `location` | 位置与尺度、控制者、日常与异常、进入条件、资源、感官特征 | 谁控制、普通人怎么生活、外来者要付出什么、能发生什么 | 只写风景，不写权力、资源和行动可能 |
| `faction` | 目标、资源、规则、内部派系、对外关系、成员典型 | 它要什么、靠什么运转、谁说了算、与其他势力为何冲突 | 只有名称和首领，没有组织行为逻辑 |
| `item` | 来源、功能、使用条件、代价、归属、象征或剧情作用 | 谁能用、怎么用、用了会怎样、为什么重要 | 只写数值和外观，不写限制与归属 |
| `world` | 世界事实、规则 / 能力体系、历史、文化、种族、经济、地理 | 稳定事实、边界、与人物选择的接口 | 写成百科词条，规则没有限制和代价 |
| 自定义分类 | 按项目定义，但至少保留稳定事实、边界、剧情接口 | 与 `world` 不重复的独立主题 | 为每个想法新建分类，导致条目无法检索 |

- 当前默认分类只有 `character`、`location`、`faction`、`item`、`world`；`world` 是通用兜底，适合放规则、能力体系、历史、文化、种族等世界事实。世界很大时拆成多个条目，不要合并成一篇。
- 旧项目或导入数据还可能保留 `rule`、`other` 等分类。规则优先归入 `world` 或项目自定义的规则分类；`other` 只在没有更合适分类时使用，不主动创建。

### 人物条目

适用于主角、对手和重要配角；不需要给每个路人都建条目。

```
姓名 / 常用称呼：
身份与角色功能（在故事中推动什么）：
外在目标（想要什么，可判断成败）：
内在需求（真正需要理解或改变什么）：
行事方式（性格与经历如何形成）：
人格与性格（MBTI 原型；按重要度选 2–6 个属性标签及对应行为；可选）：
人物内核（核心欲望、核心恐惧、价值观、缺陷、成长方向；可选）：
底线（不愿牺牲什么；压力下会怎么选）：
长期关系（[[相关人物]]；目标、价值或亏欠上的张力）：
信息边界（长期能接触 / 被排除的信息领域；当前是否知道某事放人物状态）：
变化弧线（起点与预期终点；只写人物设计，不写具体章节事件）：
```

- 人物条目不是问卷；不需要写满所有字段，配角只写与当前冲突有关的部分。
- 属性标签必须附一个可观察行为或选择；只写形容词的标签不进资料库。
- 人格卡是设计工具，资料库只保留稳定结论；当前情绪和临时关系变化放 `character-states.md`。
- 同一 MBTI 的不同角色应靠属性与内核区分；不要把类型写成行为说明书。
- 对手要有独立目标、合理信息和自己的底牌，不能只负责阻拦。
- 配角至少有一个不能退让的目标，或一项不能被主角替代的作用；否则容易变成送情报的工具。
- 镜像人物可选：面对同一困境做出另一种合理选择，用来照出主角的变化。

### 规则与能力体系

规则是人物做选择时绕不过去的条件，不是背景说明。只设计当前故事要用的部分，通过使用和后果逐步展示。

```
规则 / 能力名称：
来源（谁制定、如何获得，世界内如何解释）：
触发条件：
效果（能做什么）：
限制（不能做什么；次数、范围、时机、对象）：
代价（资源、风险、关系、暴露、后果）：
掌握者与排除者（谁会用、谁被排除、为什么）：
反制与利用（既有规则如何限制、放大或绕过它）：
资源流转（如何获取、消耗、分配）：
可能引出的选择（获取、交易、准备、暴露、竞争、放弃）：
```

**特殊优势检查**（金手指、独特能力、核心资源都适用）：

- 它解决哪个瓶颈？解决后还剩下哪些约束（知识、渠道、保密、时机、合作、责任）？
- 对手能否用既有规则限制它，或迫使它付出代价？
- 是否每次危机都靠它？如果是，先加限制，而不是加更强的敌人。
- 它是否让其他人物失去选择？如果是，给其他人独立的应对手段。

## 人物当前状态

`setting/character-states.md` 只记录「写下一章时马上要用」的当前事实。它不是人物小传，也不是未来计划；完整身份、背景和长期关系放资料库。

**每个需要持续跟踪的角色一节**（主角、对手、重要配角；路人不单列）：

```
## 角色名

- 最近出场：第 N 章 / 场景
- 当前位置：
- 身体状态（伤势、疲劳、中毒、伪装等）：
- 心理状态（当前情绪、顾虑、误判）：
- 当前目标（这一阶段想要什么，为什么不能退）：
- 持有物与资源（关键物品、钱、权限、人脉）：
- 能力变化（新学会 / 新暴露 / 暂失去的能力）：
- 关系变化（信任、亏欠、敌意、承诺）：
- 未解决伏笔与承诺（与这个角色有关、尚未兑现的部分）：
- 掌握的关键信息（可选；谁知道、谁还不知道）：
```

- 只写当前事实，不写「他以后会……」。
- 一章结束后更新；被改写章节的旧状态要按最终正文修正。
- 长期身份、性格、能力体系发生永久变化时，先更新资料库，再让状态文件只保留当前结果；临时变化只留在状态文件。

## 检查

- 把当前章节的事件全部删掉，这条资料库记录还成立吗？不成立就移到 `character-states.md`。
- 下一章开始时，读者和人物各自知道什么？状态文件能否直接回答他在哪、能做什么、想要什么、被什么限制？
- 同一事实是否同时出现在资料库和状态文件？两边冲突时，以已确认的最终正文和作者确认为准，并修正另一边。
- 规则是否有明确的边界、代价和反制？删掉设定介绍后，人物是否仍要因为它做选择？
- 人物是否只有功能、没有自己的目标？把关键人物换成「功能性帮手」后，冲突是否仍然成立？
- 人物条目里的每个性格标签，能否对应一个已知行为或选择？不能就删掉或补上。
- 同一 MBTI 的两个角色，能否仅凭对话和行为区分？
- 新条目是否只包含一个可独立检索的实体？跨条目引用是否使用 `[[名称]]`，名称是否唯一？
- 是否把未来计划、章节摘要或当前状态写进了资料库？如果有，移回大纲、章组计划、进度或状态文件。
