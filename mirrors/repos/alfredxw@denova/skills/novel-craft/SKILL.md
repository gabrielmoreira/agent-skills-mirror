# 网文创作

把创作判断落成作者能直接使用的交付物。原则用于取舍，不用于逐项打分；作者的题材、文风、预期体验和已确认设定优先。

本技能是创作判断层，只补充判断、模板和诊断，不决定执行流程。流程技能在叙事正文（含续写）或相关规划开始前加载本技能；读取工作区、写入文件、委派审稿、更新资料库和状态同步仍按当前写作流程和本次授权执行。

## 开工前先确认三件事

1. **要什么**：成品正文、可选方案、结构规划，还是问题诊断。只要一段就交付一段，不把方案扩成全书；要正文就给正文，模板只在内部使用，不默认贴给作者。
2. **事实边界**：哪些已经写进正文，哪些只是计划或人物猜测。计划不能当既定设定，人物不能使用他不知道的信息。
3. **读者此刻在期待什么**：这一段让读者在意什么、得到什么回应。没有明确答案时，先补期待或回报，而不是加事件。

## 六条核心判断

| 原则 | 操作问题 | 常见失效 |
| --- | --- | --- |
| 建立期待，认真兑现 | 读者具体在盼什么？何时、以什么方式回应？ | 只埋不发，或用旁白宣布完成 |
| 用选择与后果推进 | 人物想要什么、被什么挡住、选了什么、付出什么？ | 事件互不相干，主角被动赶场 |
| 让人物推动故事 | 每个关键人物自己要什么？信息边界在哪？ | 配角只负责送情报，对手降智 |
| 让规则产生机会与阻力 | 规则带来哪些选择、限制、代价和冲突？ | 设定只做背景，危机时临时加能力 |
| 让成长可感知、有积累 | 这次之后，能力、处境、关系或认知变了什么？ | 升级只换数值，早期成果后文消失 |
| 更新体验，延续核心吸引力 | 问题和解法变了什么？读者原来的投入理由还在吗？ | 重复同一打脸循环，或换掉核心体验 |

## 推进一段剧情的最小结构

```
欲望 / 目标 → 阻碍（资源、期限、实力、价值两难） → 选择（有代价）
→ 结果（来自前文能力、准备或选择） → 情绪回应 → 新的可能
```

- 行动场景：目标 → 阻力 → 结果。
- 反应场景：情绪 → 困境 → 决定。
- 关键结果之后留余波：局势、关系、认知或代价发生变化，再由变化生成下一步。

## 交付前检查

- **具体**：能否指出谁在什么处境下做了什么选择？删掉抽象总结后还剩什么？
- **有代价**：这次成功或失败失去了什么？是否所有问题都被同一能力解决？
- **有依据**：结果是否来自前文已经展示的能力、规则、准备或关系？转折前有没有可回看的线索？
- **信息一致**：视角人物、其他人物、读者各自知道什么？有没有为了悬念隐瞒视角人物已知的事？
- **边界有效**：这一章 / 这一场结束时，局势、关系、认知或期待是否真的变了？章尾是否留下可追的下一步？
- **事实可查**：年龄、时间、金额、距离、人数等硬数字是否与前文一致？
- **人物可辨**：遮住名字，能否从对话和行为认出关键人物？性格标签是否落到了选择上？
- **表达自然**：有没有段末总结、情绪标签、全员同一套反应等明显 AI 腔？
- **规模匹配**：是否只交付了作者要的范围？备选是否清楚标为待定？

## 不要

- 不要为套用原则增加无关事件、支线或新设定。
- 不要用旁人震惊、旁白总结代替实际结果。
- 不要在危机现场临时发明规则或能力；优先挖掘既有规则的新用法。
- 不要把推演出的重大走向写成作者已确认的设定。
- 不要把性格标签当人物；每个标签都要能落成一个选择、一句台词或一个代价。
- 不要因为诊断重写有效段落；先定位原因，再做最小有效修改。
- 不要另建与现有大纲、进度、人物状态、资料库并行的记录系统。

## 与写作流程配合

- 叙事正文（含续写）或相关规划开始前，由当前写作技能加载本技能；本技能只提供判断与参考，执行顺序、文件写入、审稿和状态同步仍按写作技能。
- 续写或改稿前，先读与本次范围相关的既有内容：`CREATOR.md`、`setting/outline.md`、`setting/progress.md`、`setting/character-states.md`、相关章组计划、最近章节；资料库用 `query_lore_items` 取全文。
- 规划结果写入当前流程指定的位置（大纲、卷纲、章组计划或对话），不擅自新建目录或第二套记录。
- 正文交付遵守当前写作技能的写入、校验与状态同步要求；纯设定或大纲讨论不写正文文件。
