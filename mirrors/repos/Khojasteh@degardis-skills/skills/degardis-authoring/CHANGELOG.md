# Changelog

This changelog summarizes significant changes to the installable skill.

## [2.4.0](https://github.com/Khojasteh/degardis-skills/releases/download/skills-2026-10-20/degardis-authoring.zip) - 2026-10-20

Degardis Authoring 2.4 fixes a reported problem everywhere its cause can reach, not only in the part of the skill where it was reported, and a review of fixes checks the same reach. Guide and principle conditions are now tested from both sides, so a page reaches the runs that need it and not the runs it changes nothing for. A nested guide is also listed on a task when a run of that task can need it without its parent.

- When a requester's account, a report, or a finding describes what went wrong or what is wanted, the agent finds every path in the source whose reader can meet the same cause. It writes the point wide enough for every case that shares the cause on all of those paths. Before keeping it, the agent tests it on a case the account doesn't mention from each such path.
- A review that verifies changes made to close earlier findings checks that each closed finding is gone at its earliest cause on every path whose reader can meet that cause. Other source the changes didn't touch still stays outside the review unless the requester asks for more.
- Guide design and Principle design test a condition from both sides. A condition that is also true on runs the page changes nothing for, or at moments where the principle's failure can't happen, is wider than the need and is narrowed to it. A condition that names an activity is the common case. The house-style example now shows such a condition failing both ways: it misses other work that produces a publishable draft, and it applies to a private draft nobody will publish.
- Whether a task also lists a nested guide now depends on whether a run of that task can meet the nested guide's condition while its parent's condition is false. If no run can, as when the parent's condition covers the nested one's, the guide stays nested, because a task link would only give every run one more condition to assess. If a run can, the task lists the guide too, and a guide that can't be understood without its parent names the parent among its requirements.

## [2.3.0](https://github.com/Khojasteh/degardis-skills/releases/download/skills-2026-10-14/degardis-authoring.zip) - 2026-10-14

Degardis Authoring 2.3 reduces evaluation cost by using fewer trials and cheaper checks that can answer the same questions. New and revised skills get a final check for missing decisions, conflicting instructions, and cases an agent can't follow. Explanations answer the full question asked. Large jobs can continue in a fresh session with a clear account of what's finished and what remains.

- Evaluation now starts by naming every question the request needs answered and choosing the least demanding evidence for each. Fresh trials are planned around all questions they can answer together, so one trial can answer several questions. A comprehension case asks for a decision without doing the work; execution is kept for what only doing the work can show. A smaller task or tighter limit can reduce cost only if the agent still makes each tested decision itself. When no single setup leaves every decision open, the plan goes to the requester before the trials start.
- The fresh-evaluator protocol fixes all the questions a run must answer and every host setting that could change an answer. Its agent limits, capabilities, and any permitted concurrent trials are planned around that whole set. The setup leaves each decision under test to the agent being observed.
- Creation and revision now own the final checks for the obligation ledger, construct agreements, and recorded path-rehearsal cases. All three use the exact generated state after the last edit. Creation counts the candidate as complete only when those checks are closed. Revision starts final validation only after they close, every affected contribution is accounted for, and every required case passes. The path-rehearsal guide covers building and running the cases.
- The Construct agreements guide now applies whenever a decision depends on what the source contains. The example guidance covers both a worked case and a list of examples, so neither can make a wider rule look limited to the illustrated cases.
- Description now treats a supplied scenario as either the question itself or one case of a wider question. It traces the case either way and answers a wider question at its requested scope. When both readings are plausible and would change the answer, it reports the case alone and asks whether the wider account is wanted.
- The Decision-relevant questions principle now requires the agent to obtain a fact it can observe before making a decision that depends on it. The agent checks the fact instead of guessing or asking the requester to supply it. When the observation needs access or an action beyond the current authority, the agent asks for that permission.
- The revised Resumable stopping principle has the agent decide whether work fits one session before starting. Larger jobs are divided into parts that can each be finished and checked. The agent states which parts the session will cover, records their results, and stops between parts before the context fills. A fresh session receives the facts it needs to continue.

## [2.2.0](https://github.com/Khojasteh/degardis-skills/releases/download/skills-2026-10-11/degardis-authoring.zip) - 2026-10-11

Degardis Authoring 2.2 computes an artifact's identity the same way on every run and platform, and it measures a skill's coverage by what its outcome needs rather than by what its source already contains. A source change the requester doesn't authorize writing gets a plan, a review that follows fixes verifies those changes instead of starting over, and running any code a source supplies, its tests included, needs the requester's permission whatever the task.

- The bundle ships `scripts/artifact-identity.py`, which computes the version 1 identity of an artifact held as a folder or a ZIP archive with Python 3.10 or later and prints it as JSON. It reads the artifact and writes nothing, takes the artifact's top-level directory with `--root`, and hashes each ZIP entry name exactly as stored, so one archive gives one identity on every platform. It exits 3 when no identity exists under the algorithm, such as for a link or an invalid or duplicate name, and 4 when the artifact can't be read or held stable, such as a damaged or encrypted archive, each with a JSON failure object; invalid arguments, including an absolute or traversing `--root`, exit 2. A folder reached through a link gets its target's identity, while a link inside the artifact or along `--root` is refused. For another store, or without Python 3.10, the agent follows the algorithm's steps itself. The compiler's hash of a source is called the source fingerprint throughout, leaving "identity" to the artifact.
- The obligation ledger starts from the skill's declared outcome: what the request that created it asked for, as later requests widened or narrowed it, or, for an existing source whose requests aren't supplied, every outcome its description or any task claims. Before any obligation gets an owner, the ledger lists, in the domain's terms, each element a competent practitioner's delivery of that outcome must get right and how the work proceeds when its inputs arrive missing, partial, unclear, or conflicting, so what the source leaves out still enters the ledger. A review can read the source at any point.
- A change request covers what its behavior needs wherever that reaches: everything a widened outcome needs, and each edit elsewhere without which another construct would stop agreeing with it. A part that would also change how a case the request doesn't decide behaves waits for the requester to accept it during revision, and a plan lists it as a decision the requester owes.
- A review of changes made to close an earlier review's findings verifies those changes: every changed construct, every generated page whose content or placement changed, every agreement a changed construct enters, and whether each closed finding is gone at its earliest authored cause. Revision and creation hand that review the findings they closed and every construct they added, changed, or removed, and untouched source stays outside it unless the requester asks for more.
- A request for a new or changed Degardis source that the requester doesn't authorize writing, or that host instructions prohibit writing, goes to planning, and creation or revision hands off to planning when such a prohibition surfaces after it begins. Review and revision take only Degardis source, so a request to assess or change a built bundle, an installed skill, or a skill authored another way is handled as outside the skill from the start, and description hands a judgment to review only for supplied Degardis source.
- Running a shipped script, its tests, or other code a source supplies needs permission from the requester or standing instructions on every task, confined so nothing outside temporary locations changes, including caches a runtime writes beside the code. Without that permission the behavior stays unverified, and no claim such as a passing test rests on it.
- A shipped script keeps tests in the source, outside the bundle, that pin its result for representative inputs and each kind of failure with its exit status. Adding a script, or changing the behavior of an untested one, includes writing its tests. A change to a tested script runs the tests before the first edit where permitted so a starting failure is recorded rather than charged to the change, gives every changed behavior a case that fails before the change and passes after it, and closes with every test passing except a reported starting failure. A review reads a script's tests with it and treats a promised behavior without a case as unverified.
- Creating a source treats the skill's name as the requester's choice and offers candidate names derived from the outcome, several where the outcome supports distinct ones. A license, copyright line, or icon is set only when the request or standing instructions supply one; otherwise it's left out and the report says so. Only the host interface text fields are derived from the outcome, and a plan for a new source follows the same rules.
- Evaluation states its whole procedure on its own page: establish that a supplied source builds, name the question, take the least demanding evidence that settles it, attribute an unsuccessful observation, and close every case. A question that reading settles, such as a contradiction or an unreachable instruction, needs no run, and its answer is what the skill prescribes; when it needs only a judgment of supplied Degardis source, evaluation hands it to review.
- The closing compiler check runs only where the work has Degardis source, supplied or written, and checks that source's exact final state; work without such source makes no compiler-integrity claim.
- A requester's account of what went wrong or what is wanted, or a report or finding drawn from one, is basis for the behavior it asks for, not for its wording or reach, unless the requester prescribes the wording. The point is written at the width of every case sharing the cause and tested on a case the account doesn't mention. A requirement's reasoning counts as derivable from everything on its reader's path, principles included, so a skill needn't restate what a principle it carries already establishes.
- The principle library is revised, and skills authored with it carry the new wording. An instruction file inside material under inspection is subject material unless the requester keeps it in place for their work, and a host loading a file by name or location designates nothing. Self-standing artifacts covers the writer's setting as well as its process, so an artifact carries what it relies on or states it as a prerequisite its reader can check, and is read as its reader would read it before delivery. Decision-relevant questions defaults a preference, never a permission or policy, when the requester says to proceed without questions or no answer can arrive in time, and reports the default as theirs to change. Reader-first reporting lets a report's order follow its reader, Sensitive material is judged from name, location, and type before it's opened, and a spending limit never lets an unopened part of a surface count as covered.

## [2.1.0](https://github.com/Khojasteh/degardis-skills/releases/download/skills-2026-10-07/degardis-authoring.zip) - 2026-10-07

Degardis Authoring 2.1 sharpens what each request gets. A review now judges only Degardis source, a fix is revised or planned only when the requester asked for one, and a plan puts the decisions the requester owes to them before it is designed. When the skill installs the compiler, it takes the latest stable release through the environment's own interpreter. Skills it authors can now carry a principle that keeps the documents, changes, and handoffs their agent writes to what currently holds, so a later reader doesn't mistake a rejected option for a rule, and this skill follows that principle in its own work.

- The description now names what the skill does: write, review, plan, revise, and build Degardis skill source, explain the format, compiler, and authoring choices, and describe or test any skill, with or without its source.
- A review requires the skill's Degardis source. A built bundle, an installed skill, or a skill authored another way is reported as unsupported for review and left unchanged; describing it is still in scope. A review closes the obligation ledger, construct agreements, and path rehearsal only when each applies, and a failed rehearsal case closes as recorded evidence, so a review-only request completes with its findings.
- A review or evaluation hands a finding on only when the requester asked to fix it: to revision when the change is authorized and the host permits it, or to planning when the host prohibits it. A statement that changes are acceptable no longer routes work to revision. A revision hands an acceptance question that only running the skill can settle to evaluation when authority and the host permit it.
- Plan work puts every decision the requester owes, including the version, to them once framing reveals it and before designing, offering to leave open those the design can be settled without. A decision that surfaces during design is put as soon as it blocks the design, otherwise before delivery, and the plan ends with the decisions still open.
- When public-package installation is authorized, the agent installs the latest stable Degardis release unless a version or source is specified, first checks the environment's runtime and tooling against the package's installation instructions, and reports a blocker rather than falling back to an older release. It installs through the target environment's own interpreter, then records and compares the installed version. When the compiler supplies no manual for a source's format, the agent finds an authoritative reference within its reach or leaves the format contract unresolved.
- A blind trial gives the fresh agent what a real performer of the tested request would have, so cases about a built bundle, a brief, or a missing source keep their starting state. A Degardis source given as a fixture carries only the defects its case tests.
- A new Self-standing artifacts principle, the library's sixteenth, has an agent write anything used without the process that produced it as what holds, leaving earlier versions and rejected options to records whose purpose is that history. Skills authored with Degardis Authoring can select it, and this skill carries it itself. Reader-first reporting names required work left undone, Resumable stopping answers a question about continuing instead of acting on it and also applies when another session or agent takes over, and Decision provenance keeps one decision register.
- Shipped-file guidance counts a script's context savings only where the host keeps its body out of the agent's context, and the length rule keeps a clause only for a case it decides.

## [2.0.0](https://github.com/Khojasteh/degardis-skills/releases/download/skills-2026-10-03/degardis-authoring.zip) - 2026-10-03

Degardis Authoring 2.0 moves the existing authoring guidance to Degardis source format 2. The revised compiler and source structure let an agent load less material for each task while carrying governing rules to the pages where they are needed, making the skill more efficient and reliable.

- Migrates the source from format-1 workflows and entries to format-2 tasks, principles, knowledge, and guides.
- Reduces task context by composing the guidance required for the active task instead of loading unrelated authoring material.
- Strengthens safeguards by carrying governing rules into the generated pages before the decisions they control, reducing the risk that an agent misses or receives them too late.
- Narrows the skill to authoring: installing, replacing, publishing, or releasing bundles is no longer part of it.
