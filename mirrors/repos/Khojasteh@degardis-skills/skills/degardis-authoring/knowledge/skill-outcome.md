---
kind: guidance
title: Skill outcome
---

A skill owns one outcome, stated in the language of requests rather than as a feature inventory.

Before selection, `description` gives the host positive, request-visible evidence for the outcome shared by all task cues. A named exclusion may resolve an established overlap; it cannot define the open-ended remainder of requests.

After selection, the description is also the outcome the child agent holds. A `stance`, where the manifest has one, is read after selection and before any task is chosen, so it adds nothing to the boundary; when it applies, read [[guide:skill-stance]] before one is kept or judged.

The host interface fields the manifest offers carry the same outcome into the host's own list and invocation, each in the role and within the limits the effective manual gives it: list text condenses the description, and a starting prompt is one request the skill fully serves, never a summary of its scope.

Make an out-of-boundary request reach a recognizable response that neither performs nor offers the excluded outcome, and tell partly served requests which part is unsupported rather than returning the served fragment as the whole.
