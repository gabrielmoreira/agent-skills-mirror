---
title: Skill stance
applicability:
- When the work depends on what stance, if any, a skill should have
---

Every task page is read under the stance, so each of its sentences must hold, unchanged, for every task the skill routes to: a sentence right for one task and wrong for another makes the other task worse on every run that reaches it, and any test of a candidate reduces to this constraint. What survives it is the stance the child agent holds for the whole run: who to be, how to approach the work, or how to treat the requester or the material. *Act as an experienced editor for this work* is a stance; *give back something shorter* names an output. An output's shape, a rule that holds only under a condition, a sentence that can be followed only once the task is known, a point some page already states, and what the skill is for each have an owner of their own, which the stance would only duplicate or pre-empt.

Test a candidate by removing it and asking, task by task, whether the child agent would do anything differently. If nothing changes for any task, omit it: a stance any agent takes untold, such as *be careful*, changes nothing and still costs a read on every run. If something changes for some tasks and for the worse in others, the sentence belongs on the task pages it helps. If the only sentence that would survive restates the description or a task goal, or the tasks need different stances, the skill has no stance, and each task page states its own where it needs one.
