---
title: Wording and references
applicability:
- When the work depends on how source prose is written
---

Where a change is free to choose a form the source leaves open, take the one that source already uses. A source in two styles reads as two authors, and the second style arrives through edits that each looked locally reasonable. The compiler's own headings and instructions are part of every generated page, so a source in the language and spelling the effective manual gives for them keeps each page in one voice.

## Length

Before accepting prose, test each clause in scope by removing it from the final page. Keep it only for a concrete case that would then be decided wrongly or left unclear, and record in re-readable working state why the rest of the reader's path cannot resolve that case. Recheck after each deletion so removing duplicates does not erase a needed point. Preserve conditions, exceptions, evidence bars, and reasoning that decides unlisted cases, however much length they need. Name concrete actions, objects, and thresholds rather than categories the reader must translate.

## Terms

Use one term for each thing the source names, constructs included, with identifiers distinguishable from ordinary prose: a second term reads as a second thing. Translate vocabulary only at a human-facing boundary.

Take each term from what the child agent can resolve: its own field, the bundle, or its host contract. A word naming a tool, format, or practice of the author's host or field asserts that the child agent has it, an unstated field claim; describe the thing instead, or declare the dependency where the skill needs it.

Where a skill has its agent keep a record that tracks the work, such as a ledger, register, account, or set of cases, name where the record lives as *re-readable working state*, in exactly those words each time. The phrase carries both properties the record needs: re-readable, so the agent reopens it instead of trusting memory, and working state, so it belongs to the run alone and is discarded with it. A paraphrase such as *notes* or *session state* reads as another place with other rules.

## Checked references

Take from the effective manual which constructs compile to pages of their own, which references it checks, and how each reference and hand-off is rendered. Where prose sends the reader to another page, write the reference the compiler checks rather than the construct's id or title: a checked reference fails the build when its target stops existing, where an id or title typed into prose survives the rename and leaves a sentence that still reads correctly and points at nothing. Work is sent to a task through the sending task's declared hand-off, whose rendered link already carries the condition; prose names the stage in ordinary words rather than linking the task page again.

One checked reference per construct on a page is what that costs: link where the prose first sends the reader there, and name the stages that follow in ordinary words. A title written to head a page rarely fits mid-sentence, and repeating it turns a sequence of stages into a list of titles the reader parses before reaching the instruction. A target the compiler offers no reference for is not a destination, since nothing would check the pointer; a knowledge unit is such a target, read whole on the task page carrying it. Declare a dependency between units where the manual says the compiler places and reports it; a guide or principle may assume what every page that opens it carries, and says nothing about where it sits.
