---
title: Using an example
applicability:
- When the work depends on an example
---

One worked case — the input, the decision, and why — does more than another paragraph of description, and it is worth its bytes exactly where prose hides a discriminator. Label an example as an example, and never let an invented one become the only source of a behavior.

An example you were handed arrives at the scope of whoever handed it over, which is rarely the scope of the construct receiving it: before it goes in, check that it still reads as one case of the rule rather than as the rule's subject, and generalize it where it does not. A construct that is wider than its only example is read at the width of the example.
