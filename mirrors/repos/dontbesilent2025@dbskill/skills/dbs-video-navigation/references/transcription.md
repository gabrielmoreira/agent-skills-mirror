# 转写与时间映射

本工具不提供语音识别模型，不依赖特定服务。先检查宿主现有转写工具、用户配置的服务或本地模型。没有能力时如实说明，不能从文件名猜正文；缺凭证时由用户安全配置，不能读取其他项目的密钥。不得为转写上传目录中的其他资料。

## 推荐路径

1. `python3 scripts/navigation.py extract-audio input.mp4 audio-v1`：需要 FFmpeg 和 ffprobe。使用原片时间戳，补足音轨晚于视频开始的静默并处理时间间隙，输出 16 kHz 单声道 PCM WAV。不会上传。
2. `audio-manifest.json` 保存按采样数确定的偏移。默认每 900 秒分段，可用 `--segment-seconds` 修改。将每个 `segment-NNN.wav` 交给可用的语音识别工具，得到同名 `.srt`；时间从该 WAV 的 0 秒开始，不能先裁掉静默或变速。
3. 若某段确实没有对白，核对音频后写同名空 SRT；工具错误或识别失败不能以空文件代替。
4. `python3 scripts/navigation.py merge-subtitles audio-v1/audio-manifest.json input.srt`：验证音频指纹与分段连续性，使用采样偏移合并；保留识别原文。再 `prepare`，审核字幕异常。
5. 查看并核对开头、中间、末尾及每次分段附近的语音与字幕定位。检查 `decoded_duration` 与原片时长；音频提前结束可能是无声片尾，应看画面确认。异常偏差需调查，不通过整体拉伸字幕掩盖漂移。

这里使用 PCM，避免 MP3 编码延迟和填充时长累积。每段偏移来自输出采样位置，不能改为转写服务报告的容器时长之和。对于极长文件，先检查磁盘空间；16 kHz、16 bit、单声道 PCM 约每小时 115 MB，全轨加分段约双倍。

若宿主能直接对视频转写，确认返回时间对应原片播放时间；记录工具、是否裁剪静默及时间校验结果。已有外部字幕也需抽查匹配版本。容器编辑列表、异常时间戳和服务预处理可能改变基准，发现偏移时重新从原片提取并核对，不保证一个固定偏移修复所有情况。

若只有画面而没有可用对白：Agent 需实际查看画面。每个无字幕板块在 `visual_evidence` 记录 `time`（原片秒）与 `note`（所见动作或界面）。脚本只能检查这些记录存在且位于区间内，真实性和语义仍须 Agent 验收。无法访问视频画面时不要伪造记录。
