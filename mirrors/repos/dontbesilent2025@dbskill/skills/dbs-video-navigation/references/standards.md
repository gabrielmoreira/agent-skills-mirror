# 视觉与时间验收

## 可观察标准

1. 观众读第一行能知道大章节，第二行能知道当前问题、话题或步骤；单行导航时标题应独立表达当前位置。清楚标记序号含义，不用内部编码充当用户导航。
2. 第一行更大且更粗；使用两行时，同一字体家族、左边缘对齐。标题和问题不换行、不碰撞进度条、不出现缺字。PNG 按最终像素渲染，不放大小图。
3. 黑底白字、蓝色已播放、深灰未播放、黑色章节间隙。进度条不加密集文字，不用每章不同颜色。章节数及比例随内容变化。
4. 样式中的尺寸比例以导航宽度为参考，是起始预设；不同画幅必须重新核对导航高度与最终观看尺寸。横屏不能机械沿用竖屏高度占比。手机缩小后仍要能读；不要用高分辨率替代可读性检查。
5. 顶部区域结合实际画面、人物运动和正文字幕检查；平台 UI 遮挡需用户提供目标平台或实际预览。没有信息时报告未验证，不能保证。
6. 导航对应最终剪辑。开场是否排除、结束是否包含片尾、正文进度分母均明确。当前脚本分母为 coverage 时长，若用户要全片进度需另行实现并测试，不能只修改文字说明。
7. 所有板块覆盖连续、帧数为正、首尾同步、进度单调递增，最终到终点。很短章节在进度条上可能细到不可辨认；保留真实时长，合并章节须有内容依据并获授权，不能伪造等宽比例。

## 固定检查顺序

参数来源 → 全文结构 → 最长/最短标题 → 实际画面位置 → 时间边界 → 完整输出 → 解码与视觉抽检 → 交付说明。

能自动判断的由脚本检查；语义归属、中文可读性和遮挡由 Agent 结合字幕及画面判断。不存在「脚本成功所以章节正确」的推断。
