# 每步理论锚定

新建或大改时，为判断骨架中的每个步骤匹配理论；修问题时，只对出错的步骤执行。目标是让每一步都有一个可靠的判断方法，而不是让模型临场发挥。

理论不保证 Skill 好用，但缺少理论的步骤更容易出错。理论只服务于具体判断：它进入 Skill，需要改变至少一项判断顺序、分类标准、中间产物、适用边界或验证方法。名人辨识度和术语新鲜感不能单独构成入选理由。

## 1．审查这一步的规则

先检查这一步原本打算写的规则，或已有 Skill 中这一步的规则：

| 风险 | 检查问题 |
| --- | --- |
| 绝对化 | 是否使用「都、一定、只要、凡是」？反例能否轻易成立？ |
| 因果跳跃 | 是否把相关或结果写成了原因？ |
| 定义偷换 | 核心词前后含义是否改变？ |
| 经验普遍化 | 是否把单个案例扩展成所有场景的规律？ |

判断状态：保留／收窄／重构／放弃。先写出修正后的规则，再找理论。

## 2．写出这一步需要解释的机制

把“找一个理论”改写成 1～2 个具体问题，例如：

- 为什么作者容易高估读者已知的背景？
- 什么机制决定一条反馈值得进入产品决策？

理论必须回答这个问题。只和步骤共享关键词，不算匹配。

## 3．候选评分

每步提出 2～4 个候选，按下表评分：

| 维度 | 分值 | 判断标准 |
| --- | ---: | --- |
| 机制匹配 | 0—3 | 能否解释这一步的主要判断 |
| 来源可靠 | 0—2 | 是否有原著、论文、行业标准或权威档案 |
| 能导出行为 | 0—3 | 能否改写成 Agent 可执行的判断条件或检查点 |
| 边界清楚 | 0—2 | 是否能说明何时成立、何时失效 |

总分低于 7 分不得入选；`机制匹配 < 2`、`来源可靠 < 1` 或 `能导出行为 < 2` 时直接淘汰。

每步保留 1 个主理论。辅助理论只在解释主理论覆盖不了的新机制时保留；只能得出「要清楚」「要有价值」一类常识结论的，删除。

找不到达标的理论时，写「暂未找到足够匹配的理论，保留经验判断」，并把这一步标为验证重点。不硬套，也不因此停止。

## 4．理论卡

```markdown
步骤：
理论名称：
理论要解决的问题：
核心机制：
原始出处：作者，《作品》，年份；只有确知时才补章节或页码
核实状态：用户材料／本地资料／基于已有知识，未在本轮外部核实／原始来源已核实／权威二手来源已核实／尚未核实
```

未核对原文时，只用中文意译并标注「意译」，不把记忆中的近似措辞写成逐字引文。无法确认的页码、原话和首创关系写明核实状态，不补写推测信息。

## 5．映射到 Skill 步骤

```markdown
| Skill 步骤 | 理论锚点 | 解决什么判断 | 导出的做法 | 失效边界 | 核实状态 |
| --- | --- | --- | --- | --- | --- |
```

「导出的做法」写成 Agent 能执行的动作，例如“先列出观众看懂标题需要的前提，再逐条检查标题是否交代”，而不是“遵循知识的诅咒理论”。

每个锚点至少写出一个失效边界：在什么情况下，这一步按理论执行也会出错。

## 6．小样本试跑

把这一步用于一个真实片段，检查：

- 按理论执行，比不用理论多得出了什么判断；
- 能否导出具体动作；
- 什么信号能推翻它。

跑不出新判断、无法导出动作或无法设置失败信号的理论，从方案中删除。

## 写进 Skill 的内容

理论卡、候选评分和试跑记录只在方案中展示给用户。Skill 正文只写「导出的做法」和失效边界，每步最多加一行依据，例如「依据：知识的诅咒」。不在 Skill 中堆砌人物、术语和引文。

## 联网

默认离线，用已有知识完成匹配并标注核实状态。只有外部事实会改变主理论是否入选，或用户要求准确来源、原话时，才联网核实；用户要求不联网时，禁止联网。同一事实连续 2 次无法核实，标注「尚未核实」并停止。
