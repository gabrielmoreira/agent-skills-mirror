# 验证 Skill

在方案中设计验证计划，或写入后执行验证时读取本文件。默认使用轻量对比；只有满足 SKILL.md 列出的加码条件时，才使用完整评测。

## 轻量对比（默认）

### 选样本

| 规模 | 样本 |
| --- | --- |
| 小改 | 改动影响行为时，1 个能体现改动的真实任务 |
| 修问题 | 1～3 个：原始失败任务；至少 1 个原来做对、改动后需要保持的任务；有余量时加 1 个表面不同、问题相同的任务 |
| 新建 | 3～6 个：正常正例、边界样本（缺关键输入或风险升高）、近邻反例（相似但不该处理的请求），有余量时加 1 个留出样本 |

样本优先来自用户的真实请求和材料。没有真实材料时，按用户日常任务构造，并在报告里注明是构造样本。

### 运行

- 改进已有 Skill 时，同一个样本分别用改动前和改动后的版本运行，保持输入、工具权限和模型配置一致。改动前的版本来自 Git 提交或写入前的快照。
- 环境支持子 Agent 时，让子 Agent 只读取 Skill 文件和样本请求后执行，不告诉它改动意图和预期结果。
- 没有子 Agent 时，由当前 Agent 试跑，并在报告里注明“由修改者自行试跑，结论置信度较低”。

### 判断

逐项对照本轮改动涉及的行为，记录每个样本改动前后是否做到、差异在哪里。向用户展示关键差异的原文片段，文风、审美和策略质量交给用户判断，不用机械断言代替。

## 完整评测（按需加码）

### 样本组合

| 样本类型 | 检查内容 |
| --- | --- |
| 失败复现 | 用户发现的问题真实存在，且改动后得到改善 |
| 正常正例 | 主要任务能否完成 |
| 边界样本 | 缺少关键输入、权限不足或风险升高时能否收窄、追问或停止 |
| 近邻反例 | 相似请求是否误触发或越界处理 |
| 回归样本 | 旧版本已经做对的关键能力是否保持 |
| 留出样本 | 修改能否迁移到未参与设计的任务 |

留出样本在设计改动前选定，设计时不看它。高风险或准备公开发布的 Skill 扩大覆盖。

### 隔离与盲评

- 执行者只能读取样本请求和必要输入文件，不能读取预期行为；
- 对主观输出采用盲评：隐藏版本名称，随机排列改动前后的结果，按同一组标准判断；
- 触发描述的改动，用同一组查询比较改动前后的触发和误触发，单独报告，不把触发率当成任务质量。

### 样本格式

样本保存在目标 Skill 的 `evals/evals.json`，默认不发布：

```json
{
  "skill": "skill-name",
  "behavior_contract": {
    "must": ["可观察行为"],
    "must_not": ["关键失败"]
  },
  "cases": [
    {
      "id": "normal-01",
      "type": "normal",
      "prompt": "用户原始请求",
      "input_files": [],
      "expected_behavior": ["只交给评分者的验收标准"]
    }
  ]
}
```

每次执行的结果记录在 `evals/results/<candidate-id>.json`，至少包含改动前后的标识、环境、逐样本结果、回归和最高验证等级。标识必须能指向一个文件快照或 Git commit，不使用“最新版”一类无法恢复的说法。

## 保留、继续或回退

保留改动需要同时满足：

- 原始失败得到改善；
- 原来做对的任务没有变差；
- 没有安全、事实、权限或任务边界方面的关键回归；
- 收益没有依赖答案泄露或单个案例补丁；
- 新增的指令长度与收益相称。

使用完整评测时，还需要留出样本支持迁移。

证据不足时写“继续试验”。候选整体变差时按回退方式恢复，保留失败记录。失败原因的判断方式见 [improvement.md](improvement.md)。
