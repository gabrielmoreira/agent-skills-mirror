# `/dbs` 多方法处理契约

当前目标需要多个 Skill 时读取本文件。先明确方法之间的关系，再安排执行；不要求用户重新发送组合提示词。

## 一、共同约束

- 聚焦同一个当前目标，可以产生配套文件、多个候选结果或尚有分歧的解释。
- 完整读取入选 Skill 和必要引用，核对输入、证据、权限和停止条件。
- 每个成员都有明确用途：补上不同环节，或检验不同假设。仅仅相关不足以入选。
- 从最少足够的方法开始，删除重复贡献；没有新信息增量时停止扩展。
- 交接保留用户原始材料与约束，区分确认事实、方法推断和待核实事项。
- 不预设跨任务长链，不因多方法处理自行创建代理或扩大权限。

## 二、互补组合

适用条件：一个目标包含多项必要工作，成员分别负责不同环节。单个 Skill 足够时直接采用单项。

确定一个负责整体交付的主 Skill，通常以 1 个主 Skill 和最多 2 个辅助 Skill 开始。确需更多成员时，逐项说明现有分工覆盖不了的必要贡献；不要为了全面堆叠方法。

分工可以是前置筛选、证据补充、部分制作、验收检查等，角色名称无需固定。每项分工写清：

- 使用的 Skill 与必要贡献；
- 输入、依赖和产出；
- 验收与停止条件。

按依赖执行：能阻止无效工作的筛选先做，核心产出所需的证据先取得，验收检查针对实际产出。独立部分无需强行串行，但执行方式服从宿主能力和已有授权。

辅助成员只完成当前分工必要的深度，保留硬门槛。主 Skill 汇总有效结果，避免机械拼接多份全流程报告。交付数量服从用户目标：可以是一篇整稿，也可以是文稿及配套标题等多项产物。

成员结论冲突时，显示冲突及证据来源，检查前提；未解决的冲突保留，不用汇总措辞掩盖。

## 三、对照尝试

适用条件：同一问题有多种合理解释或处理方法，通过比较可以减少不确定性；用户明确要求分别尝试时，也按本节执行。

先写清待区分的假设与比较依据。若一个低成本事实问题就能区分，优先取得事实；仍有必要时，通常从两种方法的有限尝试开始，不自动展开全部候选。

对照遵循：

1. 各方法使用相同的原始材料和已确认事实，各自形成分析或候选产出；不要把第一种方法的结论作为第二种方法的既定事实。
2. 保留各自假设、依据、缺口和适用条件；不强制建立主辅关系或合并成唯一答案。
3. 对产出比较用户的验收条件；对解释比较事实覆盖、反证和可验证预测。文字说服力、用户觉得像自己、多个方法结论一致，都不足以证明因果或效果。
4. 同一模型的多种分析仍可能共享偏差，不声称构成独立证据。
5. 事实足以淘汰某个假设、得到满足要求的结果，或继续比较已无信息增量时停止。缺现实证据时指出需要观察什么，不能凭空宣布胜出。

对照与组合可衔接：只有实际结果显示必要时，才将某项结果交给互补能力继续处理。保留原有不确定性，不把试探性解释升级成事实。

## 四、停止与调整

以下情况停止相关分支，其他不依赖它的工作可以继续：

- 前置判断推翻后续工作的必要前提；
- 缺失必需证据、工具或授权；
- 成员硬边界冲突，无法在当前目标内调和；
- 继续尝试没有新增信息，或当前目标已满足。

停止时交代当前结果、未完成部分、缺口和恢复条件。新事实或反馈推翻前提时，返回入口重新判断，沿用已有上下文。

## 五、用户交付

用户要求执行时，简短说明必要分工或比较目的，随后在当前对话中工作。交付实际结果，或当前推进所需的关键问题。

开始使用时明确每个 Skill 的标准名和本轮用途；对照时说明分别检验什么解释，调整成员时说明原因。最终交付简短保留本轮实际使用的名称与分工，不让这些信息只出现在进度消息中。仅预读、推荐、计划使用或受阻未执行的成员，不列为已经使用；部分执行按实际贡献描述，不声称完成全流程或启动独立 Agent。

用户只要推荐时给出选择理由与用途差异。需要导出提示词时，才把目标、材料、事实与假设、成员关系、依赖、验收及授权边界整理成可携带的调用说明。
