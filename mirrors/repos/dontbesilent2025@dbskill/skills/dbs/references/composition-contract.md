# `/dbs` 单任务组合契约

只有 `/dbs` 已经判断当前任务需要组合时，才完整读取本文件。

## 一、组合目标

组合提示词只描述一个任务中的多项独立判断。它需要同时满足：

- 一个当前任务；
- 一份最终交付物；
- 一个主 Skill；
- 最多两个辅助 Skill；
- 每个成员都有独立、必要且可验证的贡献。

组合仅服务当前任务，不保存为默认工作流，不预设跨任务长链。

## 二、内部任务卡

```markdown
当前唯一任务：
最终交付物：

主 Skill：
主责：

辅助 Skill 1：
角色：前置筛选／证据补充／验收约束
必要贡献：

辅助 Skill 2：
角色：前置筛选／证据补充／验收约束
必要贡献：

建议执行顺序：
提前停止条件：
最终验收标准：
权限边界：
```

任务卡只用于编排。最终向用户展示精简后的推荐、组合理由和可复制提示词。

## 三、兼容检查

每个候选依次检查：

1. 是否处理同一个对象；
2. 是否服务同一份最终交付；
3. 是否产生其他成员没有覆盖的判断；
4. 其结论是否会改变候选、顺序、证据、停止条件或验收结果；
5. 当前输入、权限和工具是否足以开始；
6. 是否与其他成员的硬边界冲突。

缺少独立贡献时删除该辅助 Skill。两个 Skill 都争夺最终输出时，按照最终交付确定主 Skill。仍无法确定时只问 1 个问题。

## 四、依赖顺序

顺序由当前任务的依赖关系决定：

1. 能淘汰方向或阻止高成本工作的前置筛选先运行；
2. 主 Skill 需要的证据补充在核心结论形成前运行；
3. 主 Skill 完成主体结果并汇总辅助结论；
4. 验收约束检查已经形成的结果；
5. 验收失败时，只修改对应缺口；修改会推翻核心命题时回到主 Skill。

多个前置筛选并列时，优先安排成本低、淘汰力高、输入更充分的一项。

## 五、最小充分约束

辅助 Skill 只执行当前角色需要的深度：

- 保留事实、证据、风险、权限和停止边界；
- 只输出会改变主任务的结论与条件；
- 省略与最终交付无关的完整背景和下游建议；
- 不因压缩输出而跳过硬门槛。

主 Skill 接收辅助 Skill 已经确认的状态，避免重复处理同一材料。上游结论与证据冲突时，降低结论强度并显示冲突来源。

## 六、提前停止条件

组合提示词根据任务写入相关条件：

- 前置筛选判定方向不成立；
- 必要证据不存在，且无法在当前权限内取得；
- 组合会违反任一成员的隐私、安全或授权边界；
- 辅助结论推翻主 Skill 的核心输入；
- 用户指定的组合存在无法调和的职责冲突。

停止后的交付可以包含当前结论、失败位置、已经保留的价值、重新启动条件和未执行步骤。

## 七、组合提示词模板

```markdown
同时使用 `/{主 Skill}`、`/{辅助 Skill 1}` 和 `/{辅助 Skill 2}` 完成以下一个任务。

我的任务：
{保留用户的对象、目标、材料和关键疑问。}

最终交付物：
{写清用户最终想得到什么。}

角色分工：
- `/{主 Skill}` 负责 {主体流程与最终交付}；
- `/{辅助 Skill 1}` 作为 {角色}，负责 {独立贡献}；
- `/{辅助 Skill 2}` 作为 {角色}，负责 {独立贡献}。

执行要求：
1. 按 {依赖顺序} 工作；
2. {事实、证据、隐私、权限或时效边界}；
3. 如果 {提前停止条件}，停止后续步骤并说明重新启动条件；
4. 最终只交付一份由主 Skill 统领的结果，不要依次拼接多份 Skill 报告。
```

没有第二个辅助 Skill 时省略对应内容。业务结论全部留给用户下一轮发送提示词后生成。

## 八、冲突与降级

- 单个 Skill 已经完整覆盖：降级为单 Skill 提示词。
- 指定 Skill 不存在：其余成员足够时降级编排；缺失成员承担硬门槛时停止。
- 候选超过 3 个：删除重复贡献，只保留最接近最终交付的主 Skill 和必要辅助。
- 多个互不相干的交付物：停止组合，让用户确定当前优先结果。
- 主辅目标冲突：说明冲突；不同选择会改变最终交付时，只问 1 个问题。

## 九、交付即停止

输出推荐和组合提示词后立即结束。不得继续搜索业务事实、运行入选 Skill、给出原任务判断或产出下游内容。
