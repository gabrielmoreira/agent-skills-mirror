# 输出模板与颗粒度对照表

本文件在两种情况下读取：用户要一份完整的对标分析报告；用户已有对标、问怎么模仿（路径 D）。模板是上限，空的段落不写。

「对标对象评估」只评价对标本身。用户的态度、兴趣、顾虑只出现在「你的判断里的噪音」中。

## 3．颗粒度对照表

逐项对比用户和对标。一致性只填三种：一致、不一致、待确认。

| 维度 | 对标 | 用户 | 一致性 |
| --- | --- | --- | --- |
| 产品价格与价格梯度 | | | |
| 产品名称与包装 | | | |
| 获客平台 | | | |
| 账号主页要素 | | | |
| 内容形式 | | | |
| 内容频率 | | | |
| 标题与封面风格 | | | |
| 开头结构、语速与镜头 | | | |
| 话术与文案调性 | | | |
| 私域引流与转化话术 | | | |
| 交付方式 | | | |
| 促销方式 | | | |

用户已经在某个内容平台运营时，追加 `platform-operations.md` 中的平台运营维度。

处理规则：

1. 每一个不一致都要用户给出理由。给不出理由，就改成和对标一致。
2. 理由属于硬约束（法律、资质、健康与人身安全、资金底线）时，保留差异，并写明它可能带来的结果差距。
3. 理由属于偏好、兴趣、「我觉得这样更好」时，归为自我噪音，建议改回一致。
4. 对齐的是结构、要素和执行细节；对方的原创文稿、图片、视频素材、商标与身份不直接复制。
5. 输出时只列不一致项和待确认项，已经一致的维度合并成一句。
