为项目创建或更新面向人类阅读的 `README.md`。

编写目标：
项目的 `AGENTS.md` 和 `specs/` 主要服务于 Agent，而 `README.md` 服务于人类读者。许多项目实际上是由存放工作流产物的目录、若干 Skill 与 Workflow、Agent 编写的临时脚本或参数复杂的工具脚本，以及未推送到远端的大型媒体文件共同组成的集合。`README.md` 的目标是确保在无法使用 Agent 的情况下，人类依然能够通过阅读它来理解、使用、维护和迁移项目。

在动笔前，先阅读现有文档、目录结构、脚本源码以及版本控制忽略状态，基于项目真实情况组织内容。若项目中已有 `README.md`，优先在原有结构上补充和更新。

文档应当帮人类读者弄清以下内容（可根据项目实际形态自行组织章节与详略）：
- 项目解决什么问题、最终产出什么，以及目前处于什么阶段。
- 项目的目录结构与各自含义，帮读者分清代码、规约文档、工作流产物、原始素材以及可清理的中间目录。
- 如何了解和运行项目的工作流，特别是将平时依赖 Agent 或工作流文档驱动的操作，还原为人类可以独立跟进和执行的步骤。
- 如何使用项目自带的命令或脚本，结合脚本源码说明其真实用途、参数含义与环境依赖，并帮读者区分日常核心脚本与一次性或临时脚本。
- 项目在推送、部署、归档或跨机器迁移时容易遗漏的事项，例如未推送到远端的大型媒体或数据文件存放位置与获取方式、本地配置、软链接或外部环境依赖。
