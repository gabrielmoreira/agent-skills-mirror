Follow one request

A guided walkthrough of an architecture diagram, one step at a time.

Introduce the goal: by the end, everyone can retell the path of one request.
Architecture · step by step

Follow one request through the governed path

The whole picture first · press → or Space to follow the flow, one step at a time

1A customer asks about an order in the web app.

~30 s · Point at: Customer, then Web app.

Say: Everything starts with one plain question. Keep this request in mind: we follow it end to end.

Next: "Where does the request go first?"

2Every call goes through the API gateway before it reaches the agent.

~40 s · Point at: the gateway, between the app and the agent.

Say: One door in. Authentication, quotas and logs are enforced here, not in each service.

Ask the room: "Where are these controls applied today?"

Next: the agent needs to prove who it is.

3The agent signs in with its own identity, not a shared secret.

~30 s · Point at: Agent service, Identity provider.

Say: The agent is a first-class identity: it can be audited, limited and revoked.

Next: now it can do the work.

4It reasons with the model and reads the order from the system of record.

~40 s · Point at: the two arrows to the right.

Say: The model proposes; the Orders API is the source of truth. The database stays where it is.

Next: "What if the model is down?"

5If the model is unavailable, the gateway switches the agent to a degraded answer.

~40 s · Point at: the red model.

Say: Failure is designed in: the customer gets an honest, degraded answer, not an error page.

Ask the room: "What is an acceptable degraded answer for you?"

6Each call is traced, with the agent's identity, in one place.

~30 s · Point at: Monitoring.

Say: One trace per request: who called what, when, with which identity.

Next: step back to the whole picture.

7One governed path: one door, one identity, one trace.

~30 s · Recap on the whole diagram. Pause for questions before moving on.
